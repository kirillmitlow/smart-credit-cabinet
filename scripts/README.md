# Проверка стенда

Из корня репозитория: `bash scripts/smoke.sh`. Нужны Bash, curl и стандартные команды
`mktemp`, `rm`, `sleep`, `cat`. На Windows — Git Bash или WSL. Установка Python, Node,
jq и Docker CLI для самого скрипта не требуется.

**Полная проверка сбрасывает только тестовую Соколову**, удаляя её прошлые заявки и
кредиты, затем оформляет новый синтетический кредит 500 000 ₽ на 12 месяцев. Остальные
компании сохраняются. Проверка повторяема; не запускайте её одновременно с ручным
прохождением Соколовой. Во время сброса занятая операция (`409 DEMO_RESET_IN_PROGRESS`)
повторяется раз в секунду; остальные ошибки останавливают проверку.

Для проверки готовности без изменения данных: `bash scripts/smoke.sh --quick`.
Успех — строка `PASS` и код возврата 0; ошибка — `SMOKE FAIL`, имя сервиса или шаг,
HTTP-статус и код возврата 1. Полный вариант ждёт `APPROVED`, подписывает согласия и
договор кодами из демо-режима и ждёт `DISBURSED`. Неожиданные решения останавливают
прогон сразу. Коды входа, cookie и тела ответов не выводятся.

## Адреса и время ожидания

| Настройка | Значение по умолчанию |
|---|---|
| Последний аргумент — адрес интерфейса | `http://127.0.0.1:8080` |
| `--api-url URL` — прямой адрес API | Адрес интерфейса + `/api` |
| `--timeout N` — предел каждого ожидания, секунд | 90 |
| `SMOKE_REGISTRY_URL` | `http://127.0.0.1:8101` |
| `SMOKE_TAX_URL` | `http://127.0.0.1:8102` |
| `SMOKE_BKI_URL` | `http://127.0.0.1:8103` |
| `SMOKE_BANK_CORE_URL` | `http://127.0.0.1:8104` |
| `SMOKE_SCENARIOS_URL` | `http://127.0.0.1:8105` |

Локально проверяются `/healthz` у web, `/health/ready` у API и пяти моков, а также
свежесть сигнала воркера через `/health/deps`. Postgres, Redis и актуальность миграций
проверяет готовность API. У beat отдельного HTTP-адреса нет; сигнал воркера обновляется
через его расписание.

Для облачного адреса достаточно `bash scripts/smoke.sh https://адрес-стенда`.
Прямые проверки моков там отключены: их порты закрыты по архитектуре. Полный проход
проверяет работу интеграций через заявку. `--quick` в этом режиме проверяет только
доступные web, API и сигнал воркера; отдельной проверки каждого скрытого мока нет.
`--no-mock-ports` позволяет явно выбрать этот режим и на локальном прокси.
Будущая защита облачного сброса кодом стенда пока не реализована (T-374); её подключение
к smoke потребуется вместе с утверждённым контрактом этой задачи.

## Отдельный стенд разработчика

Всегда выбирайте своё имя compose-проекта и свои порты в отдельном override-файле.
Укажите основной compose и свой override через `-f`; стандартный локальный override
при этом не подключается. Переменные `SMOKE_*_URL` должны совпадать с вашими портами.
Например, для интерфейса на 22480 и моков на 22401–22405:

```bash
SMOKE_REGISTRY_URL=http://127.0.0.1:22401 \
SMOKE_TAX_URL=http://127.0.0.1:22402 \
SMOKE_BKI_URL=http://127.0.0.1:22403 \
SMOKE_BANK_CORE_URL=http://127.0.0.1:22404 \
SMOKE_SCENARIOS_URL=http://127.0.0.1:22405 \
bash scripts/smoke.sh http://127.0.0.1:22480
```

API по умолчанию проверяется через nginx, поэтому заодно проверяется проксирование.
Справка: `bash scripts/smoke.sh --help`. Автоматические проверки Bash-скрипта входят
в `make check` через [scripts/tests/test_smoke.py](tests/test_smoke.py). Проверка
настоящего стенда входит в CI отдельной задачей T-512.
