# Исследование извлечения ответов для кредитного мастера

Изолированный CPU-эксперимент: модель оценивает варианты **шести слотов**, парсер извлекает сумму. Банковский продукт здесь не выбирается. Кода интеграции, сервисов и изменений продукта нет. Результаты и рекомендация — в [REPORT.md](REPORT.md).

## Воспроизведение

Нужны установленный [uv](https://docs.astral.sh/uv/), curl, интернет для первого скачивания открытых весов и около 25 ГБ свободного места для полного набора кандидатов. Для одного кандидата места нужно заметно меньше. Python 3.13.7 зафиксирован в `.python-version`; uv при необходимости установит его. На macOS/Linux используется `.venv/bin/python`; для Windows удобнее WSL. Скрипты не являются готовой Windows-интеграцией.

Из корня репозитория достаточно двух команд:

```sh
cd research/wizard-nlu
UV_CACHE_DIR=.cache/uv uv run --frozen scripts/reproduce.py --repeat
```

`--repeat` явно разрешает перезаписать локальные копии опубликованных CSV. Уберите его в новой папке без результатов. Полный прогон сначала получает все веса, затем последовательно обрабатывает dev, фиксирует настройки и один раз обрабатывает test. Он не меняет датасет и не подбирает ничего на test. На другой машине численные результаты и особенно скорость могут отличаться. Ориентир по времени — до нескольких часов; каждый зависший запуск и скачивание ограничены. Два lock-файла нужны из-за поддержки Qwen3.5/GLiNER новой библиотекой; остальные модели запускаются в основной среде. Версии обеих сред зафиксированы.

Для быстрого воспроизведения одного кандидата добавьте `--ids rubert-knn` либо другой id из `candidates.json`. Модели скачиваются через curl с докачкой (`-C -`), повторными попытками и лимитом 20 минут на кандидата; названия ревизий зафиксированы в `model_manifest.json`. Веса, окружения и дообученный checkpoint исключены из git. Во время инференса включён offline-режим Hugging Face; внешних inference API нет. После скачивания весов отдельные прогоны можно выполнить без сети.

## Отдельные этапы

```sh
uv run --frozen scripts/run.py dev --ids rubert-knn --repeat
uv run --frozen scripts/seal.py --repeat
uv run --frozen scripts/run.py test --ids rubert-knn --repeat
uv run --frozen scripts/aggregate.py
```

По умолчанию повторный прогон уже обработанного split запрещён. Для намеренного воспроизведения предусмотрен `--repeat`. Не используйте повторный test для настройки модели. Исходные ручные фразы уже находятся в JSONL: `author_dataset.py` — запись происхождения, запускать его заново не нужно, существующие файлы он не перезаписывает.

## Фразы от людей

`dataset/human.jsonl` намеренно пуст. Добавьте 15–20 строк в том же формате, что `dev.jsonl`, с уникальными `id` и всеми метками. Разметку нужно получить отдельно от предсказаний модели. Затем, после скачивания кандидата и воспроизведения dev:

```sh
uv run --frozen scripts/run.py human --ids rubert-knn
uv run --frozen scripts/checks.py --split human
uv run --frozen scripts/aggregate.py
```

Пустой файл приводит к понятному сообщению без фиктивных метрик. Human не смешивается с dev/test; пороги для него уже зафиксированы. Для дообученной модели нужен локальный checkpoint, который создаёт этап dev.

## Что измеряется

* `*_predictions.csv`: текст, эталон, выбранная метка, все вероятности и исходные оценки, решение о подстановке. У дообученной модели dev-прогнозы получены вне обучавшей их части данных (три разбиения).
* `*_metrics.csv`, `slot_metrics.csv`: accuracy, macro-F1, ECE и selective accuracy/coverage по каждому слоту. Обычная точность включает UNKNOWN; подстановка UNKNOWN **никогда не считается автоматическим ответом**.
* `thresholds.csv`, `*_settings.json`: температуры и пороги, выбранные только на dev. Порог даёт на dev ≥95% точности при хотя бы пяти подстановках. Если такого порога нет, 1.01 отключает слот. Это эмпирическое правило на малой выборке, а не гарантия 95% в эксплуатации.
* `critical_confusion.csv`: DEFERRED_PAYMENT_ORDER против CASH_GAP, включая уходы в другие классы; `confusion_all_slots.csv` — все матрицы.
* `reliability.csv`: десять диапазонов уверенности с количеством ответов и долей верных. `diagnostic_risk_coverage.csv` — **только диагностические** кривые на test; ими запрещено настраивать пороги.
* `*_latency.csv`, `runtime.csv`: время одной фразы со всеми шестью слотами, без пакетирования разных клиентов, после трёх прогревочных dev-фраз; p50/p95, загрузка локальных весов с подготовкой опорных примеров, пиковая RAM процесса и занятое место на диске. Импорт Python-библиотек и скачивание весов во время загрузки не учитываются. Для дообученной модели отдельно сохранено время обучения.
* `amount_*.csv`, `parser_summary.csv`: точное совпадение целого числа/null, отдельно случаи с названной суммой и ложные извлечения.
* `status_*.csv`: успешные запуски и реальные причины пропусков/ошибок. Пустая ячейка точности при нулевом coverage означает отсутствие подстановок, а не 100% точности.

Средняя обычная точность/F1/ECE — арифметическое среднее шести слотов. Итоговая selective accuracy — число верных подстановок, делённое на число всех подстановок; coverage — подстановки / (число фраз × 6). Дополнительно сохраняется среднее selective accuracy по активным слотам. В таблицах указаны фактические результаты test при **dev-порогах**, даже если они оказались ниже 95%.

Подробные параметры обучения, калибровки и замеров — в [PROTOCOL.md](PROTOCOL.md), правила разметки — в [dataset/ANNOTATION.md](dataset/ANNOTATION.md), источники и лицензии — в [SOURCES.md](SOURCES.md). Это один синтетический набор одного автора; высокий результат не заменяет проверку на реальных независимых фразах.
