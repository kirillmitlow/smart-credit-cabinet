# Протокол дополнительной проверки на 20 фразах

Источник — 20 текстов, присланных пользователем и прямо названных им синтетическими. Сохранены дословно в dataset/followup_synthetic20.jsonl. Это не независимые человеческие фразы. Метки поставлены агентом до просмотра предсказаний и пока не проверены человеком. dataset/human.jsonl остаётся пустым.

Сравниваются три заранее выбранных варианта:

1. USER2-base + kNN с исходными порогами, k=3 и прежними 42 примерами.
2. Тот же USER2-base с более строгими порогами: только на прежних 60 dev-фразах выбирается максимальное число подстановок с 100% эмпирической точностью и хотя бы десятью подстановками в слоте. Если такого порога нет, слот отключается (1.01). Температуры остаются прежними. Это настройка порогов, без нового обучения весов.
3. Laya multilingual с исходными параметрами как контроль.

Новые 20 фраз не участвуют в выборе порогов. Старые test-метрики не переписываются. Параметры, исходные файлы, код и разметка фиксируются в results/followup_synthetic20/seal.json до инференса. USER2 оценивает фразы один раз; два набора порогов применяются к одним и тем же оценкам. Проверяется, что строгий вариант не добавляет ни одной подстановки относительно исходного. Повторный запуск на той же папке запрещён; для воспроизведения нужна новая папка результатов.

## Неоднозначные поля

До прогона для каждого текста записаны annotation_note и ambiguous_slots. Они фиксируются вместе с метками. Выводятся два среза: все 120 предварительных меток и 112 однозначных полей. Маска не меняется после просмотра ошибок.

* Фразы 3, 6, 16: график выплат по кредиту не определяет явно возврат выручки/длительность бизнес-дефицита. Предварительно payback_horizon=UNKNOWN, но поле исключено из однозначного среза: исходная схема нуждается в уточнении этого различия.
* Фраза 7: конец августа без даты-отсчёта/года не задаёт однозначную длительность.
* Фраза 19: три месяца финансирования и шесть до поступления денег расходятся. Предварительно отмечен фактический ожидаемый приход денег через полгода; поле спорное.
* Фразы 2 и 14: неясно, относится платёж к новому заказу или текущим обязательствам. Предварительная цель CASH_GAP, purpose исключён из однозначного среза.
* Фраза 10: «развитие» без конкретной цели допускает OTHER/GROWTH; purpose спорное.
* Для суммы отдельно отмечены спорными фразы 2, 16, 17: платёж поставщику, цена фургона и остаток старого долга не обязательно равны запрошенной сумме нового кредита. Парсер имеет 20 предварительных и 17 однозначных примеров.
* В фразах 6 и 14 запрошенная разница не названа числом; по исходному правилу извлечения явной суммы amount_rub=null. Автоматическое вычитание не добавляется.
* В фразе 12 два транша не складываются в одну явно названную сумму и сами по себе не доказывают регулярную потребность. В фразе 20 последняя исправленная сумма — 650 тыс.

Все детали и предварительные метки находятся рядом с каждым текстом в JSONL. Число спорных полей — решение до инференса, а не исключение неудобных ошибок после него.

## Ограничения

Во всех 20 текстах gov_contract=UNKNOWN, новый DEFERRED_PAYMENT_ORDER не задан однозначно. Для collateral явно указан только один NONE; другие виды залога не проверяются. Набор не покрывает всю схему и не подтверждает различение заказа/кассового разрыва. Много UNKNOWN может повышать обычную accuracy; основные показатели — точность и доля подстановок.

Сто процентов на десяти dev-ответах не доказывают 95% в эксплуатации. Новая политика выбрана после первого исследования; исходный dev уже использовался для настройки. Новый небольшой синтетический набор нужен для дополнительной диагностики, а не сертификации качества. Спорные поля требуют согласования онтологии с заказчиком. Для проверки нужны реальные независимые тексты и отдельные группы калибровки и оценки.

## Воспроизведение

После установки основной среды из README, из research/wizard-nlu:

```sh
uv run --frozen scripts/download.py --ids user2-base laya
uv run --frozen scripts/followup_synthetic20.py prepare --out .cache/followup-replay
uv run --frozen scripts/followup_synthetic20.py run --out .cache/followup-replay
```

Первый шаг не нужен, если веса уже скачаны. Имя папки replay должно быть новым: существующие результаты не перезаписываются. Воспроизведение не разрешает подбирать параметры по этим 20 фразам. Проверка протокола без загрузки моделей: `uv run --frozen scripts/test_followup_synthetic20.py`.

После исходного запуска выполнен отдельный численный аудит: `uv run --frozen scripts/audit_followup_synthetic20.py`. Он повторно кодирует тексты только для скалярной проверки сохранённых оценок, не заменяет прогнозы и не настраивает параметры. Результаты и замечание к разметке после запуска вынесены в [FOLLOWUP_SYNTHETIC20.md](FOLLOWUP_SYNTHETIC20.md); исходные метки, маска и запечатанный код не менялись.
