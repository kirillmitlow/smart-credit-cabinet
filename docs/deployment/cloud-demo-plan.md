# План облачного демонстрационного стенда

**25.10.2026: план, стенд не развёрнут.** Сервер не заказан, расходы не понесены. Локальный запуск остаётся способом сдачи; облако — дополнительный доступ для экспертов.

## Предлагаемый вариант

Одна Linux VM с Docker Compose, постоянным диском и публичным IPv4. Те же сервисы, перед web — Caddy с HTTPS. Браузер работает с одним доменом; API, базы и пять моков доступны только внутри Docker-сети. Postgres и Valkey сохраняются в томах. Стенд не зависит от включённого ноутбука команды.

Начальная инженерная оценка: **4 vCPU, 8 ГБ RAM, 40–60 ГБ SSD**, с запасом для сборки на сервере. Это не результат нагрузочного измерения. Оценка настройки после получения готового VPS и домена — **2–4 часа**, без гарантии сроков регистрации, DNS и исправления обнаруженных проблем.

Подойдёт доступный команде VPS. Например, Selectel документирует [Containers Ready](https://docs.selectel.ru/cloud-servers/applications/containers-ready/) с Docker и Compose. Минимальные требования провайдера относятся к его образу, а не нашему приложению. Тариф и оплату выбирает владелец; Portainer для проекта не нужен.

[Caddy автоматически выпускает и продлевает сертификаты](https://caddyserver.com/docs/automatic-https) для публичного домена при правильных DNS, доступных 80/443 и постоянном хранилище сертификатов.

## Что требуется завершить до публикации

| Область | Проверенный факт и действие |
|---|---|
| Compose | [Базовый стек](../../docker-compose.yml) проверен локально. [Облачный профиль](../../docker-compose.cloud.yml) пока только меняет секреты моков/БД: не добавляет HTTPS и не публикует web. Его нужно закончить отдельным небольшим PR |
| Режим и переменные | Для api/worker/beat: `APP_ENV=cloud`, `COOKIE_SECURE=true`, `DEMO_STAND_CODE`, `APP_TODAY=2026-10-21`. Последние две настройки безопасности (`COOKIE_SECURE`, `DEMO_STAND_CODE`) пока не передаются из Compose: записи в `.env` недостаточно |
| Секреты | [Settings](../../api/app/shared/settings.py) запрещает dev-секреты в cloud. Создать отдельные пароли БД, `SESSION_SECRET`, ключи четырёх моков и `MOCK_ADMIN_KEY`. Хранить вне Git. Для паролей в URL использовать hex либо корректное URL-кодирование |
| HTTPS и сессии | Добавить Caddy → web:8080. [nginx](../../web/nginx.conf) проксирует API и SSE. Проверить cookies, вход обеих ролей, подпись и HTTPS за двумя прокси |
| Демо-управление | [Проверка кода](../../api/app/modules/demo/control_guard.py) уже есть в cloud. Проверить отказ сброса/сбоев без `X-Demo-Code` и успех с кодом. Код демо-операций передаётся экспертам через README по D-086; это не пароль БД |
| Сеть | Явные `-f` не подхватывают локальный override. Публиковать только Caddy 80/443; SSH ограничить IP администратора. Не открывать 5432, 6379, 8000, 8100–8105 и панели управления |
| Данные | Сохранить тома, подготовить резервную копию и проверить восстановление. На стенде жюри не выполнять `down -v` |

## Порядок запуска

1. Владелец предоставляет VPS с SSH-доступом и домен/поддомен с A-записью на IP сервера. Секреты не помещать в публичные issues или README.
2. Завершить облачный профиль и Caddy, не меняя локальную конфигурацию и бизнес-логику. Проверить объединённый `docker compose ... config` с подставными секретами, без вывода настоящих в логи.
3. На сервере получить фиксированную версию и создать закрытый env-файл. После завершения профиля запустить с явными `-f docker-compose.yml -f docker-compose.cloud.yml`. Текущий файл ещё не является готовой инструкцией публичного запуска.
4. Снаружи проверить HTTPS и готовность API через web, закрытие внутренних портов, обе роли и код сброса.
5. Через HTTPS пройти те же четыре браузерных сценария до выдачи/графика или отказа. Локальная проверка не заменяет облачную.
6. Проверить работу после перезапуска контейнеров/VM. Сбросить только использованные персоны, убрать сбои моков.
7. После успеха добавить в README реальный URL, дату, SHA, код демо-операций и объяснение, что данные общие.

## Ограничения и условия

Не задерживать сдачу репозитория ради облака: до готовности действует [локальная инструкция](../../README.md). Без VPS/домена не обещать публичную ссылку. Посетители используют общие демо-компании; их сброс может прервать чужую проверку.

По D-083 публичные образы GHCR не публикуются до момента сдачи 26.10; локальная сборка на VPS из проверенных исходников публикации образов не требует. Заказ сервера, развёртывание и отправка материалов организаторам в этой подготовке не выполнялись.
