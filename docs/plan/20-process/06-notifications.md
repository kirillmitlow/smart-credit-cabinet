# Уведомления внутри продукта

| | |
|---|---|
| Статус | DRAFT |
| Владелец | Агент A (черновик субагента) |
| Зависит от | [20-02](02-application-states.md), [20-03](03-tasks-and-info-requests.md), [20-04](04-consents-and-signing.md), [20-05](05-disbursement-and-after.md), [50-11](../50-architecture/11-realtime.md), [50-06](../50-architecture/06-data-model.md) (`notifications`) |

Какие события клиент и сотрудник банка узнают, как и какими словами. Каналы только внутри продукта (D-020, RQ-54): сценарий жюри не выходит за браузер.

## Каналы

| Канал | Что это | Для чего |
|---|---|---|
| **Таймлайн** | Шаги заявки из журнала `application_events` ([20-02](02-application-states.md): 6 шагов) | Где заявка сейчас. Не требует прочтения |
| **Колокольчик** | Список уведомлений (`notifications`), счётчик непрочитанных, открывается по клику | Событие, на которое нужно среагировать или которое стоит заметить |
| **SSE** | Поток `GET /api/v1/events/stream` ([50-11](../50-architecture/11-realtime.md)) | Доставляет событие в открытую вкладку без перезагрузки |
| **Тост** (Q-134) | Всплывающая плашка на 6 секунд | Только то, где нужно действие клиента |

Почты, SMS, мессенджеров и push нет. Уведомление **создаётся один раз** (уникальность «получатель + событие»), даже если воркер повторил шаг.

## Как работает

- Событие записывается в `application_events` в той же транзакции, что и смена статуса. Правило создания уведомления смотрит на код события и решает, кому. После коммита в Redis уходит короткий сигнал, браузер перечитывает список обычным запросом с проверкой прав.
- В SSE нет персональных данных и нет текстов: только тип, номер заявки, номер уведомления.
- Тексты хранятся ключом (`text_key`) и параметрами. Шаблоны лежат в одном файле словаря интерфейса (60-06), на русском простыми словами.
- Прочитано: клик по уведомлению или открытие заявки. «Прочитать все» есть.
- Клиент получает уведомление **всем участникам компании**, если не сказано иначе. Исключения — личные: подпись руководителя, просьба поручителю.
- Поручитель, зашедший по личному ИНН, видит свои просьбы в колокольчике ([10-03](../10-product/03-users-and-roles.md)).
- Ссылка ведёт на конкретный экран («Что нужно от вас», карточка предложения), а не на главную.

## События клиента

Тексты — черновики для 60-06. Столбец «Кому»: **К** — все участники компании, **Р** — руководитель, **С** — сотрудник, создавший заявку, **П** — поручитель.

| Событие | Кому | Текст | Каналы |
|---|---|---|---|
| Заявка отправлена | К | «Заявка № {номер} у нас. Сейчас начнём проверку» | таймлайн, колокольчик |
| Проверки идут дольше обычного (источник недоступен) | К | «Проверка занимает больше времени. Передали заявку специалисту, ничего делать не нужно» | таймлайн, колокольчик |
| Создана задача «нужно от вас» | К | «Банку нужно от вас: {заголовок задачи}. Зачем: {причина}» | таймлайн, колокольчик, SSE, **тост** |
| Срок задачи подходит (только если таймер включён) | К | «Остался 1 день, чтобы ответить банку» | колокольчик |
| Ответ принят банком, идёт повторная проверка | К | «Спасибо, ответ получен. Проверяем ещё раз» | таймлайн |
| Заявку смотрит специалист | К | «Заявку смотрит специалист. Обычно до 1 рабочего дня» | таймлайн, колокольчик |
| Решение: одобрено | К | «Одобрено. Выберите условия и подпишите» | таймлайн, колокольчик, SSE, **тост** |
| Решение: другие условия | К | «Банк готов дать, но на других условиях. Посмотрите варианты» | то же |
| Решение: отказ | К | «К сожалению, мы не можем одобрить заявку. Причина: {причина}. Что можно сделать: {шаг}» | таймлайн, колокольчик, SSE |
| Предложение скоро истечёт (таймер включён) | К | «Предложение действует ещё 2 дня» | колокольчик |
| Просьба к поручителю | П | «{Компания} просит вас стать поручителем по кредиту {сумма}. Нужна ваша подпись» | колокольчик, **тост** при входе |
| Поручитель подписал | Р, С | «{ФИО} подписал(а) согласие поручителя» | таймлайн, колокольчик |
| Поручитель отказался | Р, С | «{ФИО} отказался(лась) от поручительства. Укажите другого поручителя или отзовите заявку» | колокольчик, **тост** |
| Сотрудник передал на подпись | Р | «{Сотрудник} подготовил(а) заявку. Нужна ваша подпись» | колокольчик, **тост** |
| Документы готовы к подписи | Р, П | «Договор готов. Проверьте и подпишите» | колокольчик, SSE, **тост** |
| Подписано одной стороной из двух | К | «Подписал(а) {ФИО}. Ждём ещё одну подпись» | таймлайн |
| Договор подписан | К | «Договор подписан. Готовим выдачу» | таймлайн, колокольчик |
| Выдача задерживается | К | «Выдача в обработке. Деньги придут, повторять ничего не нужно» | таймлайн, колокольчик |
| Деньги выданы | К, П | «{сумма} на счёте {номер}. Договор и график — в «Моих кредитах»» | таймлайн, колокольчик, SSE, **тост** |
| Заявка отозвана | К | «Заявка отозвана» | таймлайн |
| Срок истёк (таймер включён) | К | «Срок ответа вышел, заявка закрыта. Можно подать новую» | таймлайн, колокольчик |
| Согласие отозвано | К | «Согласие отозвано. Без него банк не может продолжить: заявку можно отозвать» | колокольчик, **тост** |

Правило слов: не говорим «стоп-фактор», «скоринг», «DSCR» клиенту; причина — из справочника причин (30-12).

## События банка

Андеррайтер и админ видят своё в колокольчике зоны банка (Q-135). Очередь заявок обновляется по SSE, как у клиента.

| Событие | Кому | Текст |
|---|---|---|
| Заявка пришла на ручное рассмотрение | Андеррайтер | «Новая заявка № {номер}: {причина}» |
| Клиент ответил на запрос | Андеррайтер | «Клиент ответил по заявке № {номер}: {что}» |
| Конвейер не смог завершиться (`PIPELINE_ERROR`) | Андеррайтер, админ | «Заявка № {номер} требует ручного разбора: ошибка обработки» |
| Источник недоступен | Андеррайтер | «Не ответил {источник}. Можно перезапросить» |
| Выдача застряла (`ACCOUNT_BLOCKED` и др.) | Андеррайтер, админ | «Выдача по заявке № {номер} не прошла: {причина}» |

## Что не делаем

Рассылки, дайджесты, настройки «о чём уведомлять», звуки, push в браузер, уведомления вне открытой вкладки, перевод на другие языки. Если вкладка закрыта, клиент увидит всё в колокольчике и таймлайне при следующем входе.

## Развилки для пользователя

**Q-134. Всплывающие плашки (тосты) для клиента.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Колокольчик + тост только там, где нужно действие клиента | Клиент не пропустит «нужно от вас» и «решение готово» | Чуть больше интерфейса |
| Б. Только колокольчик и таймлайн | Проще | На демо легко не заметить, что что-то случилось |

**Рекомендация: А.** Жюри не ждёт: событие должно быть видно само.

**Q-135. Уведомления для сотрудника банка.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Колокольчик со счётчиком + очередь по SSE | Видно, что клиент ответил, без обновления страницы | Небольшая работа на банковской стороне, которая «минимальная» |
| Б. Только очередь, без колокольчика, с пометкой «клиент ответил» в списке | Минимум кода | Нет единого места для сбоев и застрявших выдач |

**Рекомендация: А** в минимальном виде (список из 5 событий выше).

## Заметки для реализации

- Модуль `notifications` слушает журнал событий. Правила «событие → получатели → ключ текста» — таблица в конфиге, не `if` по коду.
- Поле `notifications`: `user_id` (или `person_inn` для поручителя, зашедшего позже), `company_id`, `application_id`, `kind`, `text_key`, `params`, `read_at`, `event_id` (для уникальности).
- Тесты: дубль события даёт одно уведомление; чужая компания не видит; поручитель получает только своё; SSE не содержит текстов; после обрыва SSE колокольчик догоняет по `Last-Event-ID`.
- Тосты показываются, только если вкладка активна; при возврате на вкладку не повторяются.
