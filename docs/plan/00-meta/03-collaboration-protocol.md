## Участники

| Кто | Роль |
|---|---|
| Пользователь (Кирилл) | Принимает решения, одобряет документы. Не из банковской сферы, новичок в git |
| **Агент A** — Claude Code | Планирует и реализует «под ключ» |
| **Агент B** — Codex (ChatGPT Plus) | **Полноценный сменщик агента A.** Когда у одного кончаются лимиты, другой продолжает ту же работу с того же места |
| GPT-6 Astra (через Codex) | Лимиты небольшие. Только для **сложных инженерных задач**, помеченных в бэклоге 🧠 |
| Команда (4 человека) | Заданий не имеют, всё делают агенты (Q-002) |

Зон «моё / твоё» нет: план один, работа одна. Важно одно — **чтобы смену можно было передать в любой момент без потерь.**

## Кто что решает (D-073)

| Тип вопроса | Кто решает | Как |
|---|---|---|
| Архитектура, код, технологии, инфраструктура | **Пользователь** | Документ вариантов + раунд вопросов |
| Продукт и интерфейс: границы MVP, экраны, роли, вход | **Пользователь** | Раунд вопросов |
| **Экономика и банковская методология**: скоринг, DSCR и лимиты, ставки, стресс-тесты, антифрод, экономические параметры | **Агент** | Выбирает проверенный банковский метод. У каждого параметра — источник (ЦБ, Базель, Росстат, закон) или явная пометка «допущение». Документ вариантов всё равно пишется, а пользователь получает короткую сводку, а не вопрос |

## Начало смены

1. `git switch main` и `git pull`. Если в [08-handoff.md](08-handoff.md) указана рабочая ветка, переключиться на неё.
2. Прочитать **[08-handoff.md](08-handoff.md) целиком**: там текущая задача, на каком шаге остановились, что уже проверено и что нельзя трогать.
3. Прочитать последние 3–5 записей [журнала](07-journal.md), открытые вопросы и решения.
4. Продолжить **ровно с указанного следующего шага**. Не переделывать сделанное «по-своему»: если не согласен, записать вопрос.

## Передача смены

Делается, когда лимиты подходят к концу, при паузе в работе и в конце каждой логической части. **Лучше передавать чаще, чем потерять контекст.**

1. Сохранить работу коммитом в рабочую ветку. Незаконченное — коммит с префиксом `wip:`.
2. **Перезаписать [08-handoff.md](08-handoff.md)**: текущая задача, сделанные шаги, следующий шаг (конкретно: файл, функция, команда), что проверено, что сломано, открытые сомнения.
3. Добавить запись в [журнал](07-journal.md).
4. Обновить статусы в бэклоге.
5. Если сменщик работает не на этой машине, ветку нужно запушить. Пушим только с разрешения пользователя (Q-028).

## Ветки и коммиты

| Что | Ветка |
|---|---|
| Документы плана | `plan/<тема>`, например `plan/30-scoring-options` |
| Код | `feat/<область>-<тема>`, `fix/…`, `test/…`, `chore/…` |

- Коммиты мелкие и осмысленные: в кейсе требуется «история коммитов». В сообщении коммита указываем, кто его сделал (A или B).
- `main` всегда рабочий: в него попадаем только через PR и с зелёными тестами (когда появится CI).
- Без просьбы пользователя ничего не пушим и не вливаем.

## Правила

1. **Не пересматривать принятые решения.** Не согласен — открой вопрос с аргументом и продолжай по решению.
2. **Контракты меняются только через решение.** Это OpenAPI, модель данных, `policy`-конфиг, статусы заявки и контракты моков.
3. **Нашёл противоречие или дыру — не выдумывай.** Запиши вопрос и делай то, что от него не зависит.
4. **Подсказки сменщику** оставляй в трёх местах:
   - в [08-handoff.md](08-handoff.md) — про текущую работу;
   - в журнале, в блоке «Подсказки следующему»;
   - в конце каждого документа, в разделе «Заметки для реализации».
5. **Тесты пишутся вместе с кодом**, а не в конце.
6. **Сложные инженерные задачи** (🧠 в бэклоге) можно отдать GPT-6 Astra. Например: оптимизатор встречных предложений, симулятор денежного потока, конкурентная обработка outbox. Задача для Astra должна быть самодостаточной: входные документы, критерии приёмки, тесты.
7. **С пользователем говорим по-русски и просто.** Термины объясняем, кода в объяснениях минимум, про git — пошагово.
