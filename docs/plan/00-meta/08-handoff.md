## T-127: устройство и проверки

- `split.py`: четыре списка админ-тел, люди отдельно для БКИ/АБС. Пустую АБС пропускает; ЗСК не-клиента сохраняет без создания клиента/счёта.
- `gateway.py`: httpx, URL из уже предусмотренных compose REGISTRY_URL/TAX_URL/BKI_URL/BANK_CORE_URL, X-Admin-Key и X-Scenario-Code. Таймаут по умолчанию 5 с.
- `locking.py`: один mutex Postgres на закреплённом соединении между коммитами. Claim идемпотентности раньше mutex; конкуренты того же ключа получают 409 IDEMPOTENCY_IN_PROGRESS. Фон использует try-lock.
- `apply.py`: PENDING и четыре намерения DELETE фиксируются атомарно до HTTP. Полная очистка перед PUT удаляет также RUNTIME и старых людей. PUT по порядку registry/tax/bki/bank-core; намерение до вызова, результат после. При сбое очищаются ВСЕ роли, включая не ответившую. FAILED/lastError и журнал сохраняются перед 502.
- `recovery.py`: раз в 2 с завершает незаконченный откат; PENDING без активного mutex считается прерванным. Источник — БД/журнал, не память запроса. FAILED+needs_reapply=false означает намерение удалить custom; после очистки удаляется сама строка. T-129 должен учитывать это, а T-128 создавать/применять под locked_session без промежуточного отдельного коммита PENDING.
- При сбросе common.forget_replies удаляет только сохранённые ответы о стёртых ресурсах: номера счетов для АБС, reportId/submissionId БКИ, code сценария. Данные и ключи другой компании сохраняются.
- GET показывает applications с id/system/action/httpStatus/error/at. В OpenAPI добавлен POST /scenarios/{code}/apply и 502 у изменений; снимок и Bruno обновлены. `make openapi` ещё заглушка T-543; полная выгрузка ролей — T-139, полная коллекция — T-140.
- Q-145: в старом примере SKIPPED у любого не-клиента, но T-125 создаёт ЗСК GREEN. Предложение PR: OK при реальных данных комплаенса, SKIPPED только без данных. **Ожидает согласия вместе с контрактом**, не выдавать за принятое решение.
- 694 passed, 95,06%, 390 быстрых/304 integration, mypy 105 файлов, make check зелёный. Реальный контейнерный тест строит локальный образ, запускает 5 моков + Postgres, останавливает/возвращает БКИ и проверяет фоновый откат. При рестарте Docker меняет внешний порт: тест обновляет base_url, внутренний DNS остаётся тем же.
