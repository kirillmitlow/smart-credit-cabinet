## Как устроен T-372 и что нельзя потерять

Новый `POST /demo/personas/{code}/reset`: моки → кэш → одна транзакция выборочной чистки и восстановления компании. Сохраняет UUID компании и вход. Незавершённый сброс оставляет demo_resetting; изменения компании блокируются до успешного повтора. 409 + Retry-After: 1 означает занятую операцию; 502 называет шаг MOCKS/CACHE/DATABASE. Чистка кэша до удаления строк сохраняет старые id для повтора при сбое Redis.

Миграция **0009_persona_reset_generation**, после 0008. Session advisory locks держатся между короткими транзакциями, включая сеть: общая разделяемая блокировка и разделяемая блокировка компании, исключительная для её сброса. Общий сброс берёт исключительную общую. У блокировок отдельный пул БД. Повторное чтение поколения закрывает задержку до замка. Outbox ограждён **до фиксации результата и аудита**, не только до ответа мока. Старые задачи стёртой заявки завершаются SKIPPED.

Журналы нельзя UPDATE; выборочный DELETE разрешён только транзакционным белым списком ресурсов. policy_versions защищена. Каждый модуль регистрирует свою чистку. Хешированные коды подписи имеют технический company_id в Redis; соседние коды и сессии не удаляются. Лимиты частоты по сессии сохраняются.

**Будущие обязательные подключения:** файлов T-333/T-336 ещё нет: весь их цикл, включая файлы/сеть, должен держать applications.hold_operation либо shared.operations.hold; зарегистрировать выборочную чистку.
