## Что мы строим

Прототип «Умный кредитный кабинет предпринимателя» для хакатона «Альфа-Будущее», дедлайн 26.10.2026. Сначала тонкий сквозной путь Соколовой: вход → заявка → решение → подпись → выдача → кредиты. Потом остальные исходы и дополнительные функции. Ресурсный ориентир: офисный ПК без GPU, 8–16 ГБ RAM, compose целится в 4 ГБ.

Жюри проверяет систему самостоятельно по README; интерфейс должен объяснять действия и состояния. С пользователем говори по-русски, простыми словами. Презентация не нужна, мобильный интерфейс не делаем. Дизайн MVP — стандартный Mantine с красным акцентом, декоративное оформление отложено.

Ядро кредитного решения детерминированное. ИИ помогает разбирать свободный текст, но его ответ — подсказка с подтверждением. Решать «дать кредит» модели нельзя.

## Как вести Git и проверки

- Одна карточка — одна ветка и PR. Коммиты маленькие, с `[B] T-NNN ...`. Main меняется через PR. Перед пушем — fetch, перед слиянием актуальная база и зелёный CI.
- Статусы: IN_PROGRESS → REVIEW перед PR → DONE после слияния. Не отмечай реализованным документ целиком, если готова только одна его часть.
- Созданный PR прикрепи к чату через `attach_artifact`. Перед слиянием проверь `ci-ok` именно последнего SHA, а не старого запуска.
- `make check` запускает линтеры, ссылки, типы, границы и быстрые тесты. Полный набор: в соответствующем Python-проекте `HYPOTHESIS_PROFILE=ci uv run pytest --cov` (для интеграции нужен Docker).
- Hypothesis: 200 примеров в CI, 2000 для глубокого прогона. Не ослабляй тесты ради зелёного результата; исправляй ошибку либо некорректный вход, если добавлено новое требование.
- `APP_TODAY`/часы приложения — единственное «сегодня». `datetime.now()` вне часов запрещён. Не используй несидированный random в синтетике. Денежные формулы — Decimal и HALF_UP.
- Контрольные числа персон — [30-17](../30-decisioning/17-persona-walkthrough.md); формулы графика — [30-16](../30-decisioning/16-loan-math.md). Общие пресеты не равны персонам: например IP_HEALTHY — 800 тыс., а Соколова — 905 тыс. явно.

## Модели, лимиты и завершение смены

Основная модель — Sol. Независимые задачи можно раздавать Sol-агентам в отдельных worktree, контролируя пересечения файлов. Astra — только при конкретной необходимости; по последнему указанию пользователя первый вызов сразу **очень высокий/xhigh**. Не запускай её только из-за значка 🧠. Назови причину перед вызовом, ограничь задачу, проверь результат. Прежний порядок «сначала high» отменён.

Проверяй пятичасовой лимит через get_usage_limits после логических этапов и перед большой новой задачей. Остаток = 100 − usedPercent для окна 300 мин. **При остатке 5% или меньше заверши смену:** сохрани/запушь результат, уточни состояние PR/CI, перезапиши 08-handoff, добавь запись в 07-journal и дай пользователю отчёт. Не расходуй бесплатный reset без отдельной явной просьбы. Пользователь готов передать работу другому Codex, который не знает прежней истории.

Защита Mac от сна включена временным caffeinate; время окончания и PID указаны в handoff. Не обещай, что она действует бесконечно; крышка должна оставаться открытой.
