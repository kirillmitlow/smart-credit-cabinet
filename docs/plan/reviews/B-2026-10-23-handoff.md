## Детали своей реализации

Банк: чужие данные читаются только в backoffice/queries.py статическими Core-проекциями Base.metadata (исключение R5), без чужих ORM/DML. Очередь по умолчанию MANUAL_REVIEW, прочие статусы только с историей ручного разбора; автоматические STOP-отказы исключены. Рекомендация — последний ENGINE. Причины trace11.routing.detail.manual представлены строкой с запятыми; факторы в explain.numbers.factors. Карточка READ ONLY/REPEATABLE READ; пороги из policy_versions снимка. Документы null означают неизвестность. До SSE fallback-опрос раз в5секунд, общий EventStreamProvider один.

Outbox: Idempotency-Key обязателен. Shared idempotency хранит2xx24ч, конфликт тела409, конкурентный повтор409. При повторе доставки сохраняются оригинальные receiver key/created_at/payload и исходное24ч окно; просроченное/без адресата не переотправляется. Аудит/HTTP-кэш/изменение в одной транзакции, enqueue после commit. Company fence ограждает от сброса.

Демо: GET персон читает только публичные разрешённые поля сервиса сценариев. Нет users/spec/expanded/секретов. GET chaos независим по четырём источникам; PUT только разрешённые системы/режимы. В облаке общий Redis-лимит, код стенда нужен только для сбросов/сбоев. Public-config не содержит код, только demoCodeRequired/docsLinks. Кнопки банка открывают отдельную вкладку того же браузера и не удаляют клиентский кэш/сессию. Ссылки только http(s)/относительные безопасные адреса. Тексты централизованы.

Создание сценария: Idempotency-Key, стабильный code из ключа при его отсутствии. Сервис сценариев сохраняет FAILED даже после502; нестабильный автокод на повторе создал бы вторую компанию. Поэтому тот же ключ всегда даёт тот же код. Частичный исход не выдаётся за успех; SCENARIO_EXISTS не вызывает скрытый apply чужого сценария. Пользователи ограничены клиентскими ролями/длинами до внешних эффектов, остальной ScenarioSpec валидирует владелец. Public companies.apply_scenario, аудит и HTTP-кэш атомарны, общий и company lock ограждают от reset.

Служебный login: только интеграционный хелпер, обязательный явный login. Нет кнопки UI и вызова из Playwright. Только активный CLIENT/членство своего scenario_code; нет sync, отозванные права не оживают. SID клиента ротируется, банк не затрагивается. При провале DB commit новая Redis-сессия удаляется, старая сохраняется. Audit LOGIN/LOGIN_FAILED с demoHelper. Технический сценарий без учёток не получает вход.

Совпадают companyId/продукт/сумма/срок, отдельно поясняется влияние других данных. При сбросе старое зелёное подтверждение очищается в onMutate; повтор ждёт реального ответа, закрытие/кнопки блокируются.
