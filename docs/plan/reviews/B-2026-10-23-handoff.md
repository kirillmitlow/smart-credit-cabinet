### Банк: важные детали

- Модуль `api/app/modules/backoffice/`, UI `web/src/features/bank/`. Чужие таблицы читаются только в queries.py через статические Core-проекции Base.metadata.tables, исключение R5. Никаких чужих ORM/DML.
- Очередь по умолчанию MANUAL_REVIEW. Другие статусы — только с историей ручного рассмотрения; автоматические STOP-отказы не попадают. Исходная рекомендация — последний ENGINE, не последняя запись вообще. Причины `trace[11.routing].detail.manual` — строка с запятыми. Баллы в `explain.numbers.factors` (не reason.points).
- Карточка GET /backoffice/applications/{id}?expectedVersion=N: единый READ ONLY/REPEATABLE READ снимок. Пороговые значения из policy_versions конкретного решения, не текущая policy. Исходный ENGINE и решения UNDERWRITER раздельно. Документы null означает «неизвестно», не пустую папку. Снимки выводятся безопасными таблицами, HTML не исполняется. Клиентский DTO внутренних полей не получил.
- SSE банка пока отсутствует. Один существующий EventStreamProvider, fallback-опрос очереди 5 секунд. Не сообщать, что серверные события сделаны. Перепроверка в UI отключена с объяснением, пока нет A-интерфейса.
- Outbox GET /backoffice/outbox и POST /backoffice/outbox/{id}/retry. Idempotency-Key обязателен. Public shared.outbox.retry_dead сохраняет исходный ключ приёмника и окно24ч от оригинального created_at. PENDING означает постановку в очередь, не завершённую доставку. Same HTTP key повторяет сохранённый ответ, не второй эффект; одновременный ключ даёт 409. Аудит/повтор/HTTP-кэш в одной транзакции, отправка задачи после commit.
- Новый shared.idempotency.run_once — общий публичный помощник, не глобальный middleware старых клиентских API. OperationFence охватывает банковский повтор, в том числе весь HTTP до enqueue. Новые банковские мутации заявки тоже нужно включить в fence по компании.
- У компании is_bank_customer берётся из известного поля; если NULL — из features последнего ENGINE. false сохраняется.
