## Как повторить дополнительный путь

[README](../../../README.md) сохраняет четыре основных сценария и добавляет необязательный проход Гарипова. Готовый синтетический [файл](../../test-data/garipov-statement-12-months.txt) и [его происхождение](../../test-data/README.md) включены в docs. Он получен функцией statement() из существующих независимых интеграционных fixtures, с исходными параметрами700000/600000 на12месяцев по оракулу. Клиент должен выбрать файл, дождаться PARSED, проверить суммы и отдельно подтвердить поступления. Одно пояснение текстом не заменяет файл.

В основной Postman-коллекции четыре самодостаточные папки, без локального пути к файлу. Гарипов проверялся отдельной временной коллекцией, поэтому его автоматический прогон не выдаётся за часть импортируемой основной коллекции. Новый полный браузерный прогон и Postman GUI не выполнялись.

## Оставшиеся границы

- Кнопка автогенерации выписки не работает до T-130; это явно указано в README и API-навигации. Мок и код приложения C не исправлял.
- В модели/форме есть заявленное имущество, но его оценка и принятие банком не считаются доказанными анкетой. Поручитель и весь путь бухгалтер → директор не перепроверялись.
- После трёх раундов повторный REVENUE_UNKNOWN всё ещё может оставить NEEDS_INFO без новой задачи: pipeline/hooks.py лишь логирует отказ открыть раунд. Обязательный ручной разбор по D-091 остаётся работой владельца кода; не объявлять это закрытым.
- Полный новый прогон ошибочных файлов, замены, дублей/потерянных ответов и сброса файлов не выполнялся; в коде есть адресные интеграционные тесты, здесь они не подменяются положительным API-проходом.
- Автоматическая актуализация диаграмм/лицензий в CI, полный каталог технических персон, чистая Windows, репетиция человеком, релиз и облако остаются отдельными задачами. Новые генераторы/CI/настройки этим PR не добавляются.
