Как модель попадает в образ `nlu`, чтобы стенд запускался без интернета и воспроизводился, и какие лицензии записываем в `THIRD_PARTY_NOTICES`. Какая именно модель, решит T-001: таблица ниже — **кандидаты** из [40-00](00-problem-map.md).

## Принципы

1. Во время запуска сеть не нужна: ничего не скачивается (RQ-53).
2. Версия модели закреплена: источник, номер ревизии, SHA-256 файлов лежат в репозитории.
3. Образ собирается воспроизводимо: те же входы дают тот же состав.
4. В итоговом образе только то, что нужно для ответа: рантайм ONNX, токенайзер, файлы модели. Тяжёлых библиотек обучения там нет.
5. Загрузчик Hugging Face на машине автора зависал (40-00): сборка не должна зависеть от него без запасного пути (Q-139).

## Как модель попадает в образ

| Этап сборки | Что делает | Результат |
|---|---|---|
| 1. Загрузка | Берёт файлы модели строго по закреплённой ревизии из `nlu/models.lock` | Файлы во временном слое |
| 2. Проверка | Считает SHA-256 каждого файла и сверяет с `models.lock`. **Не совпало — сборка падает** | Гарантия, что внутри именно то, что проверено |
| 3. ONNX | Использует готовый ONNX-файл модели; если его нет, разовая конвертация вне сборки и результат кладётся как артефакт (Q-139) | Один файл `.onnx` + токенайзер |
| 4. Квантование | Для int8: пересмотр точности на тестовом наборе T-001; принимаем, если падение точности не более 1 п.п. (допущение) | Меньший файл, быстрее на CPU |
| 5. Финальный слой | Копирует файлы в итоговый образ, где только `onnxruntime`, `tokenizers`, `numpy`, веб-сервер | Образ без `torch` и `transformers` |

`models.lock` — таблица (файл в репозитории): имя модели, источник, ревизия, имя файла, SHA-256, размер, лицензия, версия квантования. Меняется только вместе с повторным замером T-001.

## Запуск без интернета

- Переменные окружения запрещают обращения к хабу (`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`); в итоговом образе библиотеки загрузки вообще не установлены.
- При старте `nlu` проверяет хеши файлов ещё раз и сообщает имя и SHA-256 в `/health`. Расхождение — не готов, `api` скрывает поле «своими словами».
- Контейнер входит во внутреннюю сеть compose, наружу в интернет не выходит.
- Проверка перед сдачей: запустить `nlu` с отключённой сетью (`--network none`), послать запрос — ответ получен. В CI тест «`nlu` стартует и отвечает без сети».
- Образы публикуются в GHCR только в день сдачи (D-083). Образ содержит модель, значит, жюри, скачавшие образ, интернет для модели не используют вовсе; тем, кто собирает сами, нужен интернет только на этапе сборки (допустимо по RQ-53).

## Кандидаты: размер и лицензия

Размер файла в float32 — число параметров × 4 байта; в int8 — примерно четверть (расчёт, замерить при сборке). Параметры взяты с карточек на Hugging Face.

| Модель | Параметры | float32 | int8 | Лицензия | Заметка |
|---|---|---|---|---|---|
| `cointegrated/rubert-tiny2` | 29,4 млн ([карточка](https://huggingface.co/cointegrated/rubert-tiny2)) | ≈ 118 МБ | ≈ 30 МБ | MIT | Только русский, самая лёгкая |
| `deepvk/USER-base` | 124 млн ([карточка](https://huggingface.co/deepvk/USER-base)) | ≈ 496 МБ | ≈ 125 МБ | Apache-2.0 | Только русский; нужны префиксы `query:`/`passage:` |
| `intfloat/multilingual-e5-small` | порядка 118 млн (из памяти, сверить) | ≈ 470 МБ | ≈ 120 МБ | MIT ([тег на Hugging Face](https://huggingface.co/intfloat/multilingual-e5-small)) | Многоязычная; нужны префиксы; готовый ONNX у автора есть, сверить |
| `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7` | 0,3 млрд ([карточка](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7)) | ≈ 1,1 ГБ | ≈ 300 МБ | MIT | Тяжёлая, нулевой выстрел (NLI); лицензии обучающих наборов на карточке не оговорены |

Если победит тяжёлая модель, во float32 она в лимит 1 ГБ не лезет: нужен int8.

## Лицензии для `THIRD_PARTY_NOTICES`

Критерий: только свободные лицензии без ограничения коммерции и без запроса доступа (RQ-51, RQ-57). Список ниже предварительный, из памяти и карточек; финальная версия **генерируется из lock-файлов** (`pip-licenses`, `npm`) и дополняется вручную блоком про модели ([50-09](../50-architecture/09-security.md): сборка из lock-файлов).

| Компонент | Тип | Лицензия | Где используется | Что делаем |
|---|---|---|---|---|
| Выбранная модель (из таблицы выше) | Модель | MIT или Apache-2.0 | `nlu` | Имя, ревизия, лицензия, ссылка; текст лицензии в `licenses/` |
| Обучающие данные модели | Датасеты | Указаны на карточке модели, у части не оговорены | Косвенно | Пометка «см. карточку модели»; не заявляем больше, чем знаем |
| `onnxruntime` | Библиотека | MIT | `nlu` | Строка + файл лицензии |
| `tokenizers` | Библиотека | Apache-2.0 | `nlu` | То же, плюс NOTICE при наличии |
| `numpy` | Библиотека | BSD-3 | `nlu` | Строка |
| `fastapi`, `uvicorn`, `pydantic` | Библиотеки | MIT / BSD-3 / MIT | `nlu` | Те же, что в `api` |
| `huggingface_hub`, `optimum`, `transformers`, `torch` | Библиотеки сборки | Apache-2.0 (первые три), BSD-подобная (`torch`) | **Только этап конвертации**, в образ не попадают | Указываем в разделе «инструменты сборки» |
| Тестовый набор фраз для мастера | Данные | Лицензия репозитория | Тесты, замер T-001 | Пометка: написаны агентами, синтетические |
| Qwen 3–4B (возможная LLM, Q-007) | Модель | Apache-2.0 (из памяти) | Не используется (отложено) | Проверить при включении |

Модели с лицензиями «только для исследований», «некоммерческие» (CC BY-NC и подобные), с обязательной заявкой на доступ или с особыми «условиями использования» не берём, даже если вес открыт.

## Развилки для пользователя

**Q-139. Откуда берутся файлы модели при сборке.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Скачивание с Hugging Face по закреплённой ревизии и хешу | Репозиторий лёгкий; хеш защищает от подмены | Зависит от доступности Hugging Face на сборке (на машине автора зависало) |
| Б. Файл ONNX хранится в репозитории (Git LFS) | Сборка без внешних сервисов | Репозиторий тяжелеет; лимиты LFS; файл > 100 МБ без LFS не принимается GitHub |
| В. Файл лежит как вложение релиза GitHub (одно в нашем репозитории), сборка качает оттуда с проверкой хеша; Hugging Face — запасной источник | Один адрес, который мы контролируем; репозиторий лёгкий | Релиз нужно создать до сборки; вес отдельно от кода |

**Рекомендация: В.** Платим одним шагом выпуска релиза и держим А запасным путём.

## Заметки для реализации

- Файлы: `nlu/Dockerfile`, `nlu/models.lock`, `nlu/app/` ([50-03](../50-architecture/03-repo-and-conventions.md)). Образ `nlu` отдельный от `api` (профиль `ai`).
- Проверить для победителя T-001: ONNX доступен готовым или конвертируется без `torch` в итоговом слое; параметры квантования записаны в `models.lock`.
- Тесты: сборка падает при испорченном хеше; `nlu` отвечает без сети; `/health` содержит имя и хеш; размер образа записан в README.
- Размеры и память замерить `docker stats` и записать в README (память — плановые цифры 50-01).
- Лицензии зависимостей `nlu` включаются в общий `THIRD_PARTY_NOTICES`; лицензию выбранной модели переписать с карточки в день сдачи, а не по этому списку.
