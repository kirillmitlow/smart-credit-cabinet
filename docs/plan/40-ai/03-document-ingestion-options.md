## Задача

Гарипов загружает выписку другого банка, получает понятный результат проверки и продолжает ту же заявку. СтанкоПром загружает договор поставщика для просмотра сотрудником. Загрузка файла и автоматическое извлечение чисел — разные возможности: просмотр PDF не означает, что система умеет надёжно извлекать отчётность.

## Критерии и варианты

Без внешнего inference API, на CPU, общий бюджет памяти из 50-14. Выписка 1С идёт в первом сквозном сценарии (D-065). Лимиты размеров и страниц задаёт 50-12, здесь не дублируются. Оценки ниже — часы реализации с тестами, ориентиры агента.

| Вариант | Что поддерживаем | Плюсы | Цена и ограничения |
|---|---|---|---|
| А. 1С + ручной просмотр PDF | Строгий парсер 1С; PDF хранится и доступен уполномоченному сотруднику, без извлечения цифр | Закрывает обязательный цикл Гарипова и запрос документа СтанкоПрому; мало зависимостей | 5–7 ч; из PDF отчётности выручку автоматически не берём |
| Б. А + текстовые PDF | Из PDF с текстовым слоем извлекаются кандидаты строк 2110/2330/2400 и год; требуется подтверждение сотрудником | Дополнительная польза на типовой отчётности | Ещё 4–6 ч; таблицы/единицы могут читаться неверно; сканы не поддерживаются |
| В. Б + OCR сканов | Локальный OCR, затем те же проверки и подтверждение | Читает изображения | Ещё 8–12 ч плюс вес/CPU и отдельный корпус проверки; без замера качество неизвестно |

**Решено 21.10 (Q-018, D-095): вариант А.** Парсер выписки 1С идёт со сквозным сценарием; PDF хранится и открывается андеррайтером для просмотра. Вариант Б (извлечение цифр из текстового PDF) — Could, отдельная задача после сквозного сценария; В (OCR) — вне MVP. Генеративную LLM не добавляем: Q-007 отложен.

## Контракт парсера 1С

Детерминированный разбор записей, без модели и сетевых запросов. [Официальная спецификация 1С](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/standart-obmena-s-sistemami-klient-banka/formaty-obmena/) описывает сигнатуру, версии, кодировку, секции счёта и документы. Целевой профиль — 1.03, Windows-1251 и запасной UTF-8 из 50-12; DOS и иные версии до отдельного решения отклоняются понятным сообщением.

| Шаг | Правило и результат |
|---|---|
| Распознавание | Сигнатура 1CClientBankExchange по содержимому; строки ключ=значение, разбиение по первому =; порядок секций проверяется; известные необязательные поля не обязательны |
| Кодировка | Строгое декодирование, без молчаливой замены символов; согласовать с объявленной Кодировка. Неразбираемое → BAD_ENCODING |
| Денежные значения | Decimal с точностью до копейки; сумма документа неотрицательная. Агрегаты округляются до целого рубля один раз на выходе по ROUND_HALF_UP; проверка баланса до округления с точностью копейки |
| Владелец | Счёт из секции совпадает со стороной платежа; ИНН владельца собирается из его стороны документов и сверяется с заявкой. Конфликт ИНН или недостаточно сведений для проверки → INN_MISMATCH/OWNER_UNCONFIRMED, не принимаем на веру |
| Период | Даты валидны, начало ≤ конец, документы внутри заявленного периода; минимум три полных месяца по 50-12. Неполный текущий месяц хранится отдельно и не повышает среднее |
| Проведённость | В приход включаем по ДатаПоступило, расход — по ДатаСписано; дата создания платёжки сама по себе не доказывает движение денег |
| Направление | Собственный счёт у получателя → приход, у плательщика → расход; чужие счета не добавляются. Собственный перевод между двумя загруженными счетами учитывается один раз и исключается из прокси-выручки |
| Сверка | Суммы документов сходятся с итогами секции и остатками. Дубликат документа с тем же счётом/номером/датой/суммой не удваивает оборот; конфликт одинакового ключа → ошибка проверки |
| Выход | Счета, ИНН, период, обороты по полным месяцам, суммы исключений, неоднозначные операции, предупреждения, provenance и SHA-256 исходного файла |

Не называем все поступления выручкой. Собственные переводы, выдача кредита, взнос владельца и возвраты требуют исключения при надёжном признаке. Для неопределённой операции сохраняем предупреждение и передаём на проверку; парсер не выдумывает экономический смысл по одному назначению. Порог/метод расчёта выручки остаётся в 30-03, а не копируется в парсер.

Несколько файлов одного счёта с пересечением периодов не суммируются вслепую: объединение по ключу операции, контроль дубликатов и согласованности остатков. В MVP неоднозначное пересечение требует одного непротиворечивого файла. Внутренние переводы определяются только по подтверждённым собственным счетам, не по совпадению названия.

## Фоновый процесс

1. Сохранить исходные байты и хеш через FileStore, показать «Проверяем выписку».
2. Celery выполняет разбор, пишет parse_status и структурированный результат, не меняя исходный файл.
3. Ошибка → понятный код/текст, клиент может заменить файл; заявка остаётся NEEDS_INFO.
4. Успех → показать период и обороты, запросить подтверждение. Выполнение всех задач текущего раунда разрешает повторный CHECKING.
5. Сгенерированная демо-выписка проходит тот же путь, проверку и подтверждение; обхода по origin нет.

Сброс персоны отменяет результаты старого поколения задач: запоздавший парсер не возвращает удалённой заявке документ. Повтор одной задачи не создаёт второй результат/уведомление.

## PDF и источник цифры

Если выбран Б, автоматическое извлечение сначала даёт только кандидаты: значение, единица измерения (рубли/тысячи), год, номер страницы, строка отчёта, фрагмент-основание. Человек подтверждает до использования. Нельзя брать выручку предыдущего года за текущую, терять множитель 1000 или считать отсутствие текста нулевой выручкой. При конфликте с ГИР БО действует приоритет 30-03 и флаг сверки.

| Ситуация | Поведение |
|---|---|
| PDF-договор поставщика | Файл для ручного просмотра; сам по себе не подтверждает оплату или госконтракт |
| PDF с текстом | При выбранном Б — кандидаты и подтверждение; иначе только хранение/просмотр |
| Скан, повёрнутые страницы, таблица не извлечена | «Не удалось извлечь данные», ручная проверка/другой файл; не нули |
| Зашифрованный, слишком большой/длинный файл | Ошибки и лимиты из 50-12 |
| Встроенные инструкции в документе | Содержимое документа — данные, не команды агенту или ядру |

**Q-140 сейчас не нужен** (выбран А); если когда-нибудь возьмём Б, инструмент — pypdf для текста (рекомендация: проще), либо pdfplumber для координат таблиц (больше контроля и зависимостей). [pypdf: ограничения извлечения](https://pypdf.readthedocs.io/en/stable/user/extract-text.html), [pdfplumber: официальный репозиторий](https://github.com/jsvine/pdfplumber). Выбор требует короткой пробы на нашем корпусе после разрешения кода; ни одна библиотека сама не подтверждает достоверность цифр.

## Проверка и приёмка

| Группа | Примеры и ожидаемый результат |
|---|---|
| Корректный 1С | Файл мока + независимый от генератора ручной fixture: точные приходы/расходы/остатки, месяц, ИНН |
| Поля и кодировки | CRLF/LF, UTF-8/Windows-1251, знак = в назначении; битая кодировка, неверные секции и DOS → понятная ошибка |
| Деньги | Копейки, запятая/точка, отрицательное/нечисло, огромная сумма, расход/приход одного счёта |
| Подмена | PDF с .txt, чужой ИНН/счёт, конфликтующие владельцы, операция вне периода |
| Агрегация | Граница месяца/года, неполный месяц, внутренний перевод, дубликаты/пересечения и конфликт остатков |
| Процесс | Повтор Celery, ошибка/замена файла, отмена заявки/сброс во время разбора, чужая компания → 404 |
| PDF при выбранном Б | Независимые документы с проверенными строками и единицами; отсутствие текстового слоя, неверный год; без подтверждения данные не идут в решение |

100% совпадение ожидаемых сумм на фиксированном корпусе — критерий парсера. Прочитанный PDF без корпуса и ручной проверки не объявляется успешным распознаванием. Скорость и память измеряются на целевом ПК; «меньше секунды» в 50-12 — цель, пока не замер.
