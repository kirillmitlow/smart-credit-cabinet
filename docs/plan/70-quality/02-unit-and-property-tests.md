## Зачем

Ядро (`decide()`, кредитная математика, стейт-машина) определяет деньги клиента и баллы жюри. Примеры проверяют один случай, **свойство проверяет закон для тысяч случаев**. Здесь список этих законов (инвариантов): по нему агент пишет тесты, а ревьюер проверяет полноту.

## Как это устроено

| Тема | Правило |
|---|---|
| Инструменты | pytest, Hypothesis (стратегии генерации входов), respx, свои «часы» `APP_TODAY` |
| Где лежит | `api/tests/unit/` — примеры и границы; `api/tests/property/` — инварианты. Один инвариант = один тест с ID `INV-NN` в названии |
| Входы | Генераторы строят **валидные и реалистичные** компании: выручка по логнормали, возраст 0–30 лет, 0–5 кредитов, пропуски (`None`) в необязательных полях. Невалидные входы — отдельные unit-тесты |
| Сравнение исходов | Вводим порядок строгости: `APPROVED` < `COUNTER_OFFER` < `MANUAL_REVIEW` < `REJECTED`. `NEEDS_INFO` в сравнения не входит: проверки идут на полных данных |
| Профили Hypothesis | `dev` — 50 примеров; `ci` — 200, без случайности (`derandomize`); `deep` — 2000 со случайным seed (ночью и перед сдачей), Q-101 |
| Найденная ошибка | Hypothesis сжимает пример до минимального. Он копируется как обычный unit-тест, чтобы ошибка не вернулась |
| Чистота | Тесты ядра не ходят в сеть и в БД: сокеты запрещены на уровне фикстуры |
| Типы | Строгий mypy на модулях ядра (Q-051 B): половина классов ошибок ловится до запуска |

## Инварианты ядра

Формулировки простыми словами. «Прочее равно» — все остальные входы те же.

### Монотонность: ухудшение не улучшает

| ID | Свойство | Оговорки |
|---|---|---|
| INV-01 | Больше дней просрочки (прочее равно) → исход не мягче | Порядок строгости выше |
| INV-02 | Больше ежемесячных платежей по действующим кредитам → исход не мягче, грейд не лучше | Платёж по линии считается по правилу 30-08 |
| INV-03 | Больше просрочка / запросов в БКИ за 30 дней / налоговый долг → баллы скоркарты не растут | Каждый фактор отдельно |
| INV-04 | Больше выручка и старше бизнес → баллы не падают, максимальная сумма не уменьшается | |
| INV-05 | Залог не повышает ставку: ставка с залогом ≤ ставки без залога | Скидка за залог и меньшая доля потерь (30-09) |
| INV-06 | Хуже грейд → ставка не ниже; ставка всегда внутри коридора продукта | |
| INV-07 | Больше срок → **не меньшая** максимальная сумма по DSCR | Для аннуитетных продуктов |
| INV-08 | Если запрос проходит, то запрос на меньшую сумму (тот же срок, продукт) тоже проходит | |
| INV-09 | Больше сумма при том же сроке → платёж не меньше, DSCR не лучше | |

### Кредитная математика (30-16)

| ID | Свойство | Оговорки |
|---|---|---|
| INV-20 | **Сумма платежей по графику = основной долг + проценты** | Допуск: рубль на округление, остаток уходит в последний платёж |
| INV-21 | Остаток долга убывает и в конце равен нулю; число платежей = сроку; проценты ≥ 0 | |
| INV-22 | Ставка 0% → платёж = сумма / срок; платёж растёт со ставкой и падает со сроком | |

### Обратная задача лимита и проверки

| ID | Свойство | Оговорки |
|---|---|---|

| INV-31 | Максимальная сумма не отрицательна; при нуле встречных вариантов по сумме нет | Поток не покрывает текущие платежи |

## Обязательные unit-тесты «по примерам»

- **Границы**: DSCR ровно 1,25; налоговый долг ровно 10% месячной выручки; 6 месяцев возраста; расхождение ровно 30%; сумма ровно на пороге автоматического решения.
- **Таблица «ответы → продукт»** из [10-07](../10-product/07-need-wizard.md) — по тесту на строку, один в один.
- **Контрольный пример СнабКонтракта** ([30-08](../30-decisioning/08-affordability-options.md)): 8 млн на 12 мес не проходит, на 36 мес проходит; один грейд, разные продукты — разный итог. Точные числа берутся из 30-17, когда он появится.
- **Персоны**: ожидаемый исход и коды причин каждой из 9 персон и 10 технических сценариев — на уровне `decide()`, без сети.
