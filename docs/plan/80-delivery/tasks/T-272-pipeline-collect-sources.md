## Цель

Шаг 2 конвейера: реестр, ЕФРСБ по каждому участнику, ФНС, ЕИС (для `CONTRACT`), комплаенс и АБС запрашиваются свежо и параллельно; ответы как есть сохраняются снимками, а в ядро идёт единый снимок данных с статусами источников.

## Входит / не входит

- **Входит:** `pipeline/facts.py`: перевод моделей адаптеров во вход `decide()` ([T-280](T-280-decide-types-and-purity.md)): у источника `OK/NOT_FOUND/UNAVAILABLE/NOT_REQUESTED`, дата данных, `snapshot_id`; пул из 4 потоков, субъекты ЕФРСБ: компания, директор и все учредители-люди; таблица `source_snapshots` (`payload`, `payload_hash`, `data_actual_at`, `retrieved_at`, `request_id`), неизменяемая; недоступность обязательного источника → `SOURCE_UNAVAILABLE` без падения; необязательные (отчётность, обороты, блокировки) — по правилам [30-04](../../30-decisioning/04-stop-factors-and-flags.md).
- **Не входит:** БКИ ([T-273](T-273-pipeline-bureau-step.md)); разобранная выписка клиента ([T-334](T-334-statement-to-facts.md)).

## Критерии приёмки

- [ ] Второй запрос заменяет снимок, а не дублирует его (ключ «версия + шаг»)
- [ ] В худшем режиме `SLOW` суммарное время шага укладывается в бюджет (параллельность, а не ~54 с)
- [ ] Снимки не содержат расхождений с ответом мока (проверка `payload_hash`)
- [ ] Решение использует свежие данные без кэша (после [T-237](T-237-cached-vs-fresh-gateway.md) — через `FreshGateway`): правка данных через админ-API видна в следующей заявке
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
