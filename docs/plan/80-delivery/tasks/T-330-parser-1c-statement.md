## Цель

Загруженный файл `1CClientBankExchange` превращается в обороты по полным месяцам с проверками владельца, периода и сумм. Без ИИ и без сети: Гарипов продолжает ту же заявку (D-065, D-095).

## Входит / не входит

- **Входит:** сигнатура и разбор `ключ=значение` по первому `=`, порядок секций, профиль 1.03, Windows-1251 и запасной UTF-8 (строгое декодирование, `BAD_ENCODING`); деньги `Decimal` с копейками, агрегаты в целые рубли один раз на выходе `ROUND_HALF_UP`, проверка баланса до округления; владелец: счёт из секции, ИНН из его стороны платежей сверяется с заявкой (`INN_MISMATCH`, `OWNER_UNCONFIRMED`); период ≥ 3 полных месяцев, неполный месяц отдельно; направление по собственному счёту: приход по `ДатаПоступило`, расход по `ДатаСписано`; собственные переводы между своими счетами исключаются; дубликаты документов не удваивают оборот; конфликт ключа — ошибка; сверка итогов секции и остатков; выход: счета, ИНН, период, обороты по месяцам, исключения, предупреждения, provenance и SHA-256 файла.
- **Не входит:** хранение и загрузка ([T-332](T-332-filestore-upload-download.md)); фоновая задача ([T-333](T-333-statement-parse-task.md)); PDF.

## Критерии приёмки

- [ ] Ошибки: `INN_MISMATCH`, `PERIOD_TOO_SHORT`, `BALANCE_MISMATCH`, `BAD_ENCODING`, DOS и иные версии — понятный отказ
- [ ] Все поступления не называются выручкой: выдача кредита, взнос владельца, возвраты исключаются при надёжном признаке, неопределённое → предупреждение
- [ ] Файлы с пересечением периодов не суммируются вслепую
- [ ] В логи только ID/хеш/код ошибки, без назначений платежей
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
