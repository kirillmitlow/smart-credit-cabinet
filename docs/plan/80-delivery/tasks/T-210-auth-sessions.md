## Цель

Появляется механизм сессий и прав, на который опираются все ручки: две независимые сессии (`sid_client` для клиента, `sid_bank` для банка, D-085) и единая функция проверки права.

## Входит / не входит

- **Входит:** сессия = случайный идентификатор в `HttpOnly` cookie `SameSite=Lax`, данные в Redis (AOF), простой 30 мин, абсолют 8 ч, смена идентификатора при входе, немедленный выход; `Principal` (пользователь, роль, компании, активная компания, личный ИНН, уровень L1/L2) и зависимости `current_client()`, `current_bank()`; `require(permission)` и фильтр по компании через `Principal`; чужая компания → `404`; таблица `users` (миграция) с ролями `CLIENT`, `UNDERWRITER`, `ADMIN`.
- **Не входит:** вход по ИНН и коду ([T-212](T-212-client-login-api.md)); демо-вход банка ([T-213](T-213-bank-demo-login.md)); лимит частоты и CSRF ([T-207](T-207-rate-limit-csrf-headers.md)).

## Критерии приёмки

- [ ] Клиентские ручки читают только `sid_client`, банковские — только `sid_bank`; вход и выход одной зоны не затрагивают другую (тест)
- [ ] Выход удаляет сессию на сервере сразу; смена роли действует со следующего запроса
- [ ] Срок простоя и абсолютный максимум настраиваются; истёкшая сессия → 401 `UNAUTHENTICATED`
- [ ] Падение Redis → понятный `503`, а не 500
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

integration (Redis): две сессии, выход, истечение; unit: сборка `Principal`, `require`.

## Заметки для реализации

- Сравнение токенов — `hmac.compare_digest`.
- Для SSE зона выбирается параметром `zone`, но права проверяются на сервере ([50-09](../../50-architecture/09-security.md), «Разделение сессий»).
