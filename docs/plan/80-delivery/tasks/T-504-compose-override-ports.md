## Цель

Жюри открывает Swagger любого мока в браузере, ничего не настраивая. Порты публикуются только на `127.0.0.1`, ключи берутся из значений по умолчанию.

## Входит / не входит

- **Входит:**
  - `docker-compose.override.yml` (compose читает его сам): `127.0.0.1:8080` — интерфейс, `8000` — Swagger `api`, `8101…8105` — моки
  - Локальные ключи по умолчанию из таблицы 3.4 спецификации (`dev-registry-key`, `dev-tax-key`, `dev-bki-key`, `dev-bank-core-key`, `dev-admin-key`); `.env` не нужен
  - В базовом `docker-compose.yml` в сервисах есть и `image:` (GHCR), и `build:` ([T-541](T-541-image-build-policy.md) проверяет поведение)
  - Комментарий в файле: чем локальный запуск отличается от облачного ([T-507](T-507-compose-cloud.md))
- **Не входит:**
  - Облачный файл ([T-507](T-507-compose-cloud.md))
  - Политика `pull_policy` ([T-541](T-541-image-build-policy.md))

## Критерии приёмки

- [ ] На хосте доступны `8080`, `8000`, `8101–8105`, но только с `127.0.0.1` (проверка `ss`/`netstat` или попытка с другого адреса)
- [ ] `docker compose up` без `.env` стартует с ключами по умолчанию
- [ ] Админ-ключ по умолчанию и порты моков не попадают в облачный профиль (проверит [T-507](T-507-compose-cloud.md))
- [ ] `docker compose config` объединяет файлы без ошибок
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Проверка вручную и в задании `e2e`: Swagger каждого мока открывается по ссылке из README.

## Заметки для реализации

- Override при явных `-f …` не читается, поэтому облачный файл на него не опирается (50-13).
- Порты — пункт README «Порты и компоненты» ([T-531](T-531-readme-generated.md)).
