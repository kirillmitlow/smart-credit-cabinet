## Цель

Петля замыкается: банк сообщает о заявке и выданном кредите, и следующий отчёт по клиенту уже содержит наш кредит. Это видно на демо и проверяется тестами.

## Входит / не входит

- **Входит:**
  - `POST /api/v1/submissions` (`Idempotency-Key` обязателен): события `APPLICATION_REGISTERED`, `APPLICATION_DECIDED` (`APPROVED`/`REJECTED`/`WITHDRAWN`), `OBLIGATION_OPENED`, `OBLIGATION_CLOSED` (Could)
  - Ответ `202 {"submissionId", "status": "ACCEPTED"}`; ошибки `422`, `404 APPLICATION_NOT_FOUND`, `409 IDEMPOTENCY_KEY_REUSED`, `409 IDEMPOTENCY_IN_PROGRESS`
  - Дедупликация по `eventId`: повтор события с другим ключом возвращает исходный `202` с тем же `submissionId`; другое тело — `409`
  - Заявки получают `isOwn: true`; тот же `uid` второй раз обязательство не создаёт; `RUNTIME`-записи
  - После `OBLIGATION_OPENED` следующий отчёт по субъекту содержит новое обязательство; допускается `WITHDRAWN` после `APPROVED` отдельным событием
- **Не входит:**
  - Отправка из `api` (outbox) — задачи `api`
  - Решение по встречному предложению (Q-022 уже принят: `APPROVED` после принятия клиентом)

## Критерии приёмки

- [ ] Три события из примера 6.3 для СнабКонтракта обрабатываются и меняют следующий отчёт
- [ ] Повтор с тем же `eventId` и другим ключом возвращает исходный `202`; тело другое — `409`
- [ ] Решение по незарегистрированной заявке — `404 APPLICATION_NOT_FOUND`
- [ ] Если субъекта в БКИ не было, `APPLICATION_REGISTERED` его создаёт
- [ ] OpenAPI описывает все типы событий
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

Тесты роли: последовательность трёх событий, дубль по `eventId`, `WITHDRAWN` после `APPROVED`, отчёт до и после. Хаос-вариант (`LOST_RESPONSE`) проверяет [T-138](T-138-mocks-tests-chaos-sync.md).
