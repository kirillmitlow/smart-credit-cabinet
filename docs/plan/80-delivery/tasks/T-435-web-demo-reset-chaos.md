## Цель

Повторяемость и отказоустойчивость на глазах у жюри: «Сбросить эту компанию», «Сбросить стенд», «Уронить кредитное бюро» и красная полоса, пока сбой включён.

## Входит / не входит

- **Входит:** кнопки с подтверждением и прогрессом по ответу сервера, остановка на шаге с «Повторить»; в облаке — ввод кода стенда; переключатели четырёх систем с режимами `OK/SLOW/ERROR/DOWN/LOST_RESPONSE`, подписи на языке жюри («Кредитное бюро»); «Полоса активного сбоя» в шапке всех зон (слот из [T-404](T-404-web-shell-demo-badge.md)).
- **Не входит:** —.

- [ ] Сценарий: уронить БКИ → заявка уходит к специалисту → починить → «Перепроверить» → решение
- [ ] Полоса видна в клиентской и банковской зонах, пока сбой включён
- [ ] Подпись «Сброс затронет всех, кто сейчас пользуется стендом»
- [ ] Двойное нажатие сброса невозможно

## Реализация B, 23.10.2026

Подтверждение общего/персонального сброса, облачный код, ожидание реального ответа, шаги результата/ошибки. Общий сброс очищает кэш и переводит на вход; персональный сохраняет сессию. Четыре источника, пять режимов, общая красная полоса, обновление раз в 5 секунд. Реальный браузер: DOWN → банк видит полосу → OK → сброс одной персоны → общий сброс. Сценарий сбой БКИ → MANUAL_REVIEW → перепроверка пока не закрыт: нужен public pipeline.request_recheck от A.
