## Цель

Клиент и банк видят изменения без перезагрузки: таймлайн сам идёт вперёд. Postgres — источник правды, Redis pub/sub — «звонок в дверь», потерянное докачивается по `Last-Event-ID`.

## Входит / не входит

- **Входит:** после коммита публикация короткого сообщения в Redis (id события, область `company:{ИНН}` или `bank`); подписка на процесс `api`, раздача открытым потокам; `GET /api/v1/events/stream` на `sse-starlette`: `id` = номер события журнала, типы `status_changed`, `step_done`, `task_created`, `resync`, `auth_expired`; без ПДн и текстов; `zone=client|bank` выбирает cookie, права проверяются на сервере; повторная проверка сессии раз в минуту; до 5 потоков на сессию; `Last-Event-ID` → до 100 событий из `application_events`, иначе `resync`; `: ping` каждые 15 с; очередь на соединение 100 событий.
- **Не входит:** список уведомлений ([T-354](T-354-notifications-client.md)); хук фронта ([T-407](T-407-web-use-event-stream.md)).

## Критерии приёмки

- [ ] Событие воркера доходит до клиента на каждом из двух экземпляров `api`
- [ ] Обрыв и докачка по `Last-Event-ID`; пропущено > 100 → `resync`
- [ ] Чужая компания не получает даже номера события
- [ ] Redis недоступен: поток молчит, фронт переходит на опрос; сессия истекла → `auth_expired`
- [ ] Публикация только после коммита (клиент не получает событие раньше данных)
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

integration: два `api`, обрыв/докачка, права; unit: фильтр области.

## Заметки для реализации

- Для nginx `proxy_buffering off`, увеличенный `proxy_read_timeout`, HTTP/1.1 к `api` ([T-401](T-401-web-dockerfile-nginx.md), [T-502](T-502-compose-main.md)).
- Не использовать Redis Streams на старте ([50-11](../../50-architecture/11-realtime.md)).
