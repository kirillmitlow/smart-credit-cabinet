## Цель

После загрузки Celery разбирает файл, пишет `parse_status` и месячные обороты; ошибка видна клиенту до отправки раунда, заменить файл можно без потерь.

## Входит / не входит

- **Входит:** `documents.parse_statement` (таймаут 60 с), идемпотентность повтора, одно уведомление на результат; результат в `documents.parsed`; ошибки с понятными кодами (`INN_MISMATCH`, `PERIOD_TOO_SHORT`, `BALANCE_MISMATCH`…); ограждение «поколения» компании: запоздавший парсер не возвращает удалённой после сброса заявке документ (связь с [T-372](T-372-demo-reset-persona.md)).
- **Не входит:** использование в решении ([T-334](T-334-statement-to-facts.md)).

## Критерии приёмки

- [ ] Повтор Celery не создаёт второго результата и второго уведомления
- [ ] Отмена заявки/сброс во время разбора не оставляет «живых» результатов
- [ ] Чужой ИНН → ошибка в задаче, файл не потерян, задача остаётся открытой
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
