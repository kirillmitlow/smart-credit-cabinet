## Цель

Руководитель подписывает сохранённый файл договора кодом, поручитель — своё поручительство; `SIGNED` наступает после всех обязательных подписей в любом порядке (D-092).

## Входит / не входит

- **Входит:** `POST /contracts/{id}/request-signature` (сотрудник → задача `SIGNATURE` руководителю), `POST /contracts/{id}/sign`; проверки: пользователь `ACTIVE`, `DIRECTOR` и `can_sign`, ИНН совпал с реестром, оферта не истекла, `content_hash` файла совпал; таблица `signatures`, `proof` (HMAC), прогресс «подписали 1 из 2», переход `OFFER_ACCEPTED → SIGNED` ровно один раз и запуск выдачи.
- **Не входит:** генерация файла ([T-336](T-336-pdf-generation-weasyprint.md)); выдача ([T-342](T-342-disbursement-workflow.md)).

## Критерии приёмки

- [ ] Бухгалтер получает `ROLE_CANNOT_SIGN` (INV-74); изменённый файл не подписывается
- [ ] Два параллельных «Подписать» дают одну подпись и один переход
- [ ] С поручителем `SIGNED` только после обеих подписей, при любом порядке
- [ ] После `SIGNED` отозвать заявку нельзя
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
