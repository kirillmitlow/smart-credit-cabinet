## Цель

Клиент проверяет документы и подписывает: просмотр договора с водяным знаком «ДЕМО», график, «Что вы подписываете», код; после подписи видно, как идёт выдача.

## Входит / не входит

- **Входит:** `/applications/:id/offer` и `/sign`: просмотр PDF и графика, «Подписать» (руководитель) или «Передать руководителю на подпись» (бухгалтер); плашка кода, ввод, ошибки; прогресс «подписали 1 из 2» при поручителе; шаги выдачи: «Открываем счёт» (не клиент) → «Зачисляем» → «500 000 ₽ на счёте…», «Выдача в обработке» при задержке АБС.
- **Не входит:** «Мои кредиты» ([T-427](T-427-web-my-loans.md)).

## Реализованный объём 22.10

- `OfferActions`: принятие выбранного варианта с ключом действия, защитой повторных нажатий и обновлением статуса заявки из ответа API.
- `ContractSigning`: после перезагрузки получает договор через предложение, показывает согласованные условия, документ, подписи, правила ПЭП и код. Открывать документ для подписи необязательно (D-092).
- Полномочия — из `canSign` / `canPassToDirector`. При смене прав перечитывает договор, сотрудник передаёт запрос руководителю.
- Три попытки и срок кода; в демо код виден только когда API вернул `demoCode`.
- Статусы `SIGNED`, `DISBURSING`, `DISBURSED` показываются из API. Для линии и овердрафта — лимит без фиксированного платежа.
- Ограничения существующего API: подписывает руководитель; документ — сохранённый демонстрационный текст вместо PDF; точный счёт и шаг открытия из `ContractOut` недоступны. Эти пункты не объявлены завершёнными.
