## Цель

Клиент видит один основной продукт и одну альтернативу с «почему подходит», платежом, сроком решения и документами. Один компонент карточки используется на подборе, в каталоге и во встречных (платёж не расходится).

## Входит / не входит

- **Входит:** экран результата: две карточки, «Изменить ответы», «Посмотреть весь каталог»; состояние «подходящего нет → что станет доступно и когда»; компонент `VariantCard` (сумма, срок, платёж, переплата, ставка «ориентировочно», что нужно, «почему», метка «Рекомендуем»); переход «Оформить» → заявка по шагам.
- **Не входит:** каталог ([T-415](T-415-web-catalog-calculator.md)); экран трёх карточек исхода ([T-423](T-423-web-outcome-counter-offer.md)).

## Что сделано и отступления (22.10.2026)

- `web/src/components/VariantCard.tsx` — общий компонент (сумма, срок, платёж, переплата, ставка «от», решение, документы, «Почему подходит вам», «Рекомендуем», другие сроки, слот для кнопок). Все поля необязательные, чтобы тот же компонент взяли каталог (T-415) и встречные (T-423). Термины «платёж», «переплата», «ставка» — с подсказкой (`TermHint`).
- Экран `/wizard/result`: ответы и результат приходят в состоянии адреса (`navigate(…, { state })`) и переживают перезагрузку; прямой заход без них предлагает начать подбор. «Изменить ответы» возвращает в мастер с прежними ответами. «Посмотреть весь каталог» ведёт на `/products`, там пока заглушка до T-415.
- «Оформить заявку»: мастер уже положил в черновик основной продукт, сумму и срок, поэтому основной вариант просто открывает `/applications/:id/edit/1`. Для запасного фронт делает `PATCH …/draft` (продукт, сумма, срок). Если черновика нет, создаётся заявка.
- Переплата на карточке берётся из варианта платежа с тем же сроком, что выбрал клиент; если срок не выбран, переплаты в карточке нет (бэкенд отдаёт её только внутри `comfortableOptions`).
- Срок решения в API только `AUTO`/`MANUAL`: подписи «за минуты» и «1–2 дня» заданы словарём.
