## Цель

Клиент выбирает госконтракт из списка при заявке под контракт. Мок отдаёт контракты поставщика, чтобы продукт `CONTRACT` для СнабКонтракта имел реальную основу.

## Входит / не входит

- **Входит:**
  - `GET /api/v1/contracts?supplierInn=`: реестровый номер, заказчик (название, ИНН), предмет, цена, даты заключения, исполнения и оплаты, статус, оплачено; блок `meta` с `source: EIS`
  - Нет контрактов — `200` с пустым списком
  - Таблица `public_contracts` и поле `contracts[]` в админ-теле `PUT`; `supplierInn` берётся из пути
- **Не входит:**
  - Выбор контракта в интерфейсе и расчёт суммы под контракт (задачи `api`/фронта)

## Критерии приёмки

- [ ] Пример 5.6 воспроизводится; у компании без контрактов список пуст
- [ ] Сроки исполнения и оплаты не раньше даты заключения, `paidRub` не больше цены (иначе `422`)
- [ ] ИНН заказчика проходит проверку контрольной суммы
- [ ] OpenAPI описывает эндпоинт и фильтр `supplierInn`
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Тесты роли: список, пустой список, нарушение дат при записи, чужой ключ.
