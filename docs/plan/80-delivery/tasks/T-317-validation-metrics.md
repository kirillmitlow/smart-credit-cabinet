## Цель

Чистые функции метрик, которыми строится отчёт валидации: различающая способность, калибровка по грейдам, стабильность, концентрация и одобрения.

## Входит / не входит

- **Входит:** AUC (ничьи — средний ранг), Gini = 2·AUC − 1, KS, бутстреп-доверительный интервал Gini (детерминированный); калибровка: таблица A–E, биномиальный тест с поправкой на корреляцию (`ρ = 0,12`, `statistics.NormalDist`), Brier и BSS, Хосмер–Лемешоу (справочно), монотонность; PSI по баллу и CSI по факторам (10 корзин, пустые → 0,0001), сдвиг по времени; концентрация (доли грейдов, HHI), доля одобрений, доля A ≤ 33%; светофоры по конфигу отчёта.
- **Не входит:** сборка отчёта ([T-318](T-318-validation-report-build.md)).

## Критерии приёмки

- [ ] Gini = 1 для идеального и 0 для случайного баллов; AUC и KS совпадают с малым ручным примером
- [ ] PSI одинаковых выборок = 0; Brier и BSS на известном примере
- [ ] Gini > 0,80 помечается как подозрение на утечку, а не успех
- [ ] Пороги светофоров в конфиге отчёта, а не в коде
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

unit на ручных примерах; property: границы метрик.

## Заметки для реализации

- Метрики на синтетике показывают механику и процесс проверки, не реальную силу модели — оговорка идёт в начало каждого отчёта ([30-14](../../30-decisioning/14-model-validation-monitoring.md), раздел 1).
