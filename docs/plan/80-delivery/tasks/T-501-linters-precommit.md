## Цель

Единые проверки качества для обоих агентов: одно и то же локально, в хуке и в CI.

## Входит / не входит

- **Входит:**
  - `ruff` (проверка и формат, строка 100, правила `E,F,I,B,UP,S,C4,PT` и `DTZ` — запрет `datetime.now()`/`date.today()`) в `api/` и `mocks/`
  - `mypy`: строгий режим для модулей ядра (`decisioning`, `simulator`, `pipeline`, `applications`), обычный для остального (вариант Б из 50-03, Q-051); список строгих модулей в `pyproject.toml`
  - `import-linter`: заготовка контрактов границ модулей (наполняют задачи `api`)
  - ESLint (+ `jsx-a11y` как ошибки), Prettier, `tsc --noEmit` для `web/` (заготовка)
  - `.pre-commit-config.yaml`: ruff, prettier/eslint для изменённых файлов фронта, размер файлов (> 1 МБ запрещён), концы строк, YAML/JSON, `gitleaks`; тяжёлое (mypy, тесты) в хук не входит
  - `make check` вызывает эти проверки и быстрые тесты
- **Не входит:**
  - Конфигурация CI ([T-509](T-509-ci-skeleton.md))
  - Настройка контрактов `import-linter` по модулям (задачи `api`)

## Критерии приёмки

- [ ] `pre-commit run --all-files` проходит на каркасе; `gitleaks` ловит тестовый секрет в проверочном коммите
- [ ] `ruff` отклоняет прямой `datetime.now()` и `date.today()`
- [ ] `make check` зелёный на пустом каркасе и красный при нарушении (проверено вручную)
- [ ] Строгие модули mypy перечислены в одном месте
- [ ] Установка pre-commit описана в `AGENTS.md` в одной строке
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Проверка запуском: специально испорченный файл делает `make check` красным.

## Заметки для реализации

- Версии инструментов фиксируются точно (в lock-файлах и в `.pre-commit-config.yaml`).
- Тяжёлое не в хуке, чтобы коммиты не тормозили (50-03).
