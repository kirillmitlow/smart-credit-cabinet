## Цель

Коллекция запросов — артефакт сдачи (RQ-19) и проверка в CI. Здесь та её часть, что относится к мокам; коллекция для `api` — [T-544](T-544-bruno-collection-api.md).

## Входит / не входит

- **Входит:**
  - `docs/api/collection/mocks/`: по запросу на каждую персону и на каждую ошибку, ЕФРСБ и ЕИС, выписка (по сценарию и по ИНН), сценарий «уронить БКИ» и вернуть обратно
  - Папка «Своя компания»: примеры `POST /scenarios` на каждый пресет
  - В каждой папке персоны первым идёт `POST /scenarios/{code}/apply`
  - Окружения `local` и `ci` (ключи по умолчанию из `.env.example`), проверки (статус, ключевые поля) лежат в самих запросах; секретов нет
  - Запуск `bru run` проходит против поднятого стенда
- **Не входит:**
  - Коллекция запросов `api` ([T-544](T-544-bruno-collection-api.md))
  - Подключение `bru run` в CI ([T-512](T-512-ci-e2e.md))

## Критерии приёмки

- [ ] Для каждой персоны есть запрос по каждому нужному эндпоинту с проверкой ключевых полей
- [ ] `bru run` по папке `mocks/` зелёный на свежем `docker compose up`
- [ ] Запрос «Сделать компанию» с каждым пресетом возвращает `201`
- [ ] Коллекция открывается в Bruno без правки путей и не содержит настоящих секретов
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

`bru run --env ci` в CI-задании e2e ([T-512](T-512-ci-e2e.md)).

## Заметки для реализации

- Порядок запросов в папках важен: сначала `apply`, потом чтение; не используйте состояние предыдущих папок.
