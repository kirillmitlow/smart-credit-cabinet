## Цель

Андеррайтер и админ входят одной кнопкой (D-010), единственный демо-вход даёт уровень L2, а ограничения L1 проверяются API-тестами (D-090, Q-110).

## Входит / не входит

- **Входит:** `POST /auth/bank-demo-login` (только при `DEMO_MODE`), роль `UNDERWRITER`/`ADMIN`, уровень L2; поле уровня у пользователя банка; тестовый пользователь L1 создаётся фикстурой; `audit.record` для входов и выходов банка.
- **Не входит:** матрица решений по уровням ([T-362](T-362-backoffice-decision.md)).

## Реализация 23.10, Агент B

Демо-вход создаёт отдельную sid_bank: по умолчанию UNDERWRITER L2, ADMIN разрешён явным enum API, интерфейс предлагает только андеррайтера. Передать произвольный уровень/роль нельзя. GET /auth/bank-me и POST /auth/bank-logout работают только в своём контексте. Клиентская сессия и её кэш сохраняются. Отозванные права не восстанавливаются демо-входом; роль, статус и уровень банка сверяются с User на каждом запросе. Вне DEMO_MODE вход отвечает403 до проверки тела. Аудит LOGIN/LOGOUT связывается явно через wiring и публичный обработчик auth.

Миграция0010 добавляет User.level и ограничение CLIENT→NULL, bank→L1/L2; прежние сотрудники получают L2. Миграция вверх/вниз/вверх проверена с существующими клиентом и сотрудником. Банк входит независимо от незавершённого сброса компании клиента. UI сохраняет банковский ответ в кэш до перехода, чтобы прежний bank=null не возвращал на вход; next ограничен банковской зоной. Контекст CSRF/ошибок на /login?zone=bank банковский.

Проверки: 1359 API без внешних contract/persona, 55 целевых проверок банка/входа/миграций/границ после последних изменений; 46 целевых web-проверок, включая полный renderApp вход→банк при bank=null. OpenAPI/orval обновлены, кнопка очереди пока ведёт на прежнюю заглушку T-429. Саму очередь и действия T-360…T-365 эта карточка не заменяет.
