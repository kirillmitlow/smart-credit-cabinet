## Цель

Все данные для решения в одном ответе: запрос и компания, рекомендация ядра, источники со снимками, баллы по факторам, платёж и устойчивость, ставка с разбивкой, флаги, встречные, история и документы.

## Входит / не входит

- **Входит:** `GET /backoffice/applications/{id}`: отдельная модель ответа (баллы, DSCR, стресс, снимки с `data_actual_at` и `retrieved_at`, коды причин с названиями и `CODE` мелко, версия правил и ядра); «Источник не получен» с кнопкой перезапроса, `required_level`, версия заявки для оптимистичной блокировки; история событий, документы, прошлые решения и переопределения.
- **Не входит:** действия ([T-362](T-362-backoffice-decision.md), [T-363](T-363-backoffice-request-info-recheck.md)).

## Реализация B, 23.10

GET /backoffice/applications/{id} — отдельная банковская схема: текущая заявка, кто подал и роль в компании; последний снимок решения, оригинальная рекомендация ENGINE, баллы девяти факторов с исходными значениями и порядком по недобору, платежи, DSCR/стресс/долг, ставка по компонентам и коридору, флаги с числами признаков, варианты ядра, журнал, прошлые решения и переопределения. Снимки источников содержат payload/hash, dataActualAt/retrievedAt/requestId и отметку использования в текущем решении.

Все данные карточки читаются через backoffice/queries.py в одной REPEATABLE READ / READ ONLY транзакции. Параллельное решение не смешивает старую заявку с новым журналом. expectedVersion — необязательный параметр: отличающаяся версия даёт stale=true; текущая version всегда в ответе. Это признак для интерфейса, будущие действия обязаны снова проверять версию при записи.

Порог каждого сравнения читается из policy_versions именно выбранного решения; регистрация новой политики не меняет старое объяснение. Полные числа из explain не округляются до чисел оракула на экране. Ставки/доли превращены в проценты только на границе отображения, корректировка округления/коридора показана отдельно. Кредитное решение заново не считается. Нулевые баллы и рекомендации не придумываются, если конвейер не сохранил решение.

Документы пока documents=null: T-332 отсутствует. Это явно показывается на экране T-430; не выдавать отсутствие сервиса за пустой список документов и не считать цикл V4 завершённым. Прямой записи в таблицы A нет; тестовые UNDERWRITER-снимки — только для проверки чтения истории, не реализация T-362. Клиентская схема проверена на отсутствие банковских полей.
