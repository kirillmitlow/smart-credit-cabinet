## Цель

Последняя «гигиена» перед тегом: доступ для жюри, отсутствие лишнего и секретов, понятная история и зафиксированная версия (RQ-10, D-001).

## Входит / не входит

- **Входит:**
  - Доступ аккаунта `alfa-hack-2026` к репозиторию (действие пользователя; агент готовит пошаговую инструкцию и проверяет результат)
  - Проверка: PDF кейса и `docs/` не попали в образы; `.env` и секреты не закоммичены (`gitleaks` по всей истории); `.dockerignore` актуален; лишние файлы (временные, личные) удалены
  - История коммитов осмысленная (формат `[A]`/`[B]`), нет «wip» в последних коммитах `main`, нет force-push следов
  - Текст release notes: версия, что внутри, как запустить, ссылка на README; commit hash записан в README
  - Решение о PDF кейса: убрать из репозитория перед любой публикацией (D-001), но не ломать ссылки README
- **Не входит:**
  - Публикация образов и тег ([T-539](T-539-release-and-tag.md))

## Критерии приёмки

- [ ] Аккаунт `alfa-hack-2026` получил доступ (подтверждено пользователем/скриншотом настройки)
- [ ] `gitleaks` по истории чист; PDF кейса не в публичных артефактах
- [ ] Release notes написаны и согласованы с пользователем
- [ ] Commit hash готовой версии записан в README и в журнале
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Проверка скриптами и вручную; результат — чек-лист в PR.

## Заметки для реализации

- Доступ выдаёт владелец репозитория — действие пользователя; агент не выдаёт доступ сам.
