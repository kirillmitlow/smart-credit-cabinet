## Цель

Клиент входит без регистрации: ИНН компании → выбор пользователя из членов компании; личный ИНН → компании, где он руководитель, и его ИП; самозанятый получает объяснение (D-062, D-015).

## Входит / не входит

- **Входит:** `GET /auth/roles/{inn}` (не создаёт сессию), `POST /auth/request-code`, `POST /auth/verify-code`, `POST /auth/logout`, `GET /me`, `GET /public-config`; ветки ИНН: 10 цифр, 12 цифр личный ИНН, ИП, самозанятый (`NOT_ELIGIBLE` до кода), не найден, компания не действует (вход есть, подача нет); аудит входов и неудачных попыток, лимит частоты через [T-207](T-207-rate-limit-csrf-headers.md) (если уже готов); выбор активной компании в сессии.
- **Не входит:** экраны входа ([T-408](T-408-web-login-inn.md), [T-409](T-409-web-login-code-company.md)); демо-вход андеррайтера ([T-213](T-213-bank-demo-login.md)).

## Критерии приёмки

- [ ] Все персоны с учётками входят: `sokolova`, `snabkontrakt`, `stankoprom` (два пользователя), `garipov`, `romashka`, `zarya`, `quick-start`; `orlov` получает объяснение, `vektor` входит
- [ ] Код, запрошенный для одного человека, не открывает сессию другого (тест)
- [ ] Личный ИНН директора `stankoprom` возвращает «вы директор СтанкоПрома» и ведёт к выбору компании
- [ ] `GET /public-config` отдаёт `demoMode`, название стенда, версию и признак доступности NLU без секретов
- [ ] Права подписи у сотрудника не появляются от выбора им пользователя-директора
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
