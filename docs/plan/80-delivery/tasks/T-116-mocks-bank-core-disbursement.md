## Цель

Выдача кредита — единственная операция с деньгами в стенде. Она обязана быть идемпотентной: повтор после потерянного ответа не создаёт второй кредит и не двоит остаток.

## Входит / не входит

- **Входит:**
  - `POST /api/v1/disbursements` (`Idempotency-Key` обязателен): создание кредита, ссудного счёта, проводок и зачисление на расчётный счёт заёмщика
  - Ошибки: `409 ALREADY_DISBURSED` (другой ключ на ту же заявку), `409 ACCOUNT_NOT_OWNED` (чужой счёт), `422` на невалидные условия, `404` на неизвестного клиента
  - Кредит отдаёт `outstandingRub = amountRub`, `contractUid` совпадает с `uid` в БКИ у кредитов с `ourBank: true`
  - Поддержка видов: кредит (`LOAN`), линия и овердрафт (только лимит, транши не моделируем, D-093)
  - Запись `RUNTIME`; повторное чтение через `GET /loans/{id}` и `GET /customers/{inn}/loans`
- **Не входит:**
  - Открытие счёта для не-клиента ([T-117](T-117-mocks-bank-core-open-account.md))
  - Сообщение в БКИ (его шлёт `api` через outbox)

## Критерии приёмки

- [ ] Повтор с тем же ключом возвращает сохранённый ответ с `Idempotent-Replayed: true` и не меняет остаток счёта
- [ ] Другой ключ на ту же заявку — `409 ALREADY_DISBURSED`; чужой счёт — `409 ACCOUNT_NOT_OWNED`
- [ ] Два параллельных запроса с одним ключом: один выполняется, второй `409 IDEMPOTENCY_IN_PROGRESS`, затем тот же результат
- [ ] Режим `LOST_RESPONSE` (после [T-106](T-106-mocks-chaos.md)): данные записаны, повтор не задваивает кредит
- [ ] Сумма проводок сходится: списание ссудного счёта = зачисление на расчётный
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

pytest с БД и параллелизмом: повторы, гонка, чужой счёт, второй ключ; property: для любой последовательности повторов остаток равен сумме одной выдачи.

## Заметки для реализации

- Это мок, на который смотрят хаос-сценарии `H-06` и `H-08` ([70-06](../../70-quality/06-resilience-and-load.md)); сначала довести идемпотентность, потом красоту проводок.
- Номер договора и УИд генерируются детерминированно от `applicationRef`, иначе повтор после «брошенного» ключа даст другой номер.
