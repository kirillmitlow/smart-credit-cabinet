## Цель

Каталог тестовых сценариев — обязательный артефакт (RQ-22). Документ плана становится файлом сдачи: актуальные суммы, статусы и ссылки на реальные автотесты.

## Входит / не входит

- **Входит:**
  - `docs/test-scenarios.md` из [70-09](../../70-quality/09-test-scenarios-catalog.md): те же `TS-NNN`, но с реальными цифрами (после 30-17 и реализации), реальными именами автотестов и актуальными кодами причин
  - Раздел «Как читать» и «Как запустить» (команды, как сбросить персону)
  - Таблица сводки: сколько сценариев, какой слой (E2E/API/IT/UNIT/PROP/FE/CHAOS/SYN/CTR/BRU/LOAD/РУЧНОЙ)
  - Прогон проверки меток [T-523](T-523-check-docs-ts-labels.md): нет сценариев без теста и тестов без сценария
  - Ссылка из README и из [80-05](../05-submission-checklist.md)
- **Не входит:**
  - Написание самих тестов
  - Правка 70-09 как плана (хранится в `docs/plan`, эта копия — артефакт сдачи)

- [ ] Все `TS-NNN` присутствуют, у каждого — результат, который соответствует фактическому поведению стенда
- [ ] Колонка «Автотест» ссылается на реальные файлы или тесты
- [ ] Проверка меток `check-docs` зелёная
- [ ] Каталог читается без знаний банка: термины объяснены или заменены
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)
