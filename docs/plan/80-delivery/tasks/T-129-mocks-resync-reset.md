## Цель

Стенд остаётся рабочим при пересоздании базы одного мока, смене версии персон и смене месяца. Также единый сброс моков, который возвращает chaos в `OK`.

## Входит / не входит

- **Входит:**
  - Сверка (шаги 3–4 из 10.6): данные сценария в пересозданный мок идут из сохранённого `expanded` (те же ИНН, счета, даты); `builtinVersion` выше сохранённого → переприменить; месяц `applied_month` раньше текущего → переприменить в окне 03:00–04:00 по Москве первого числа (при старте — сразу)
  - Фоновые повторы упавших сценариев каждые 30 секунд с ростом паузы до 5 минут (`FAILED`/`PARTIAL`)
  - `POST /api/v1/scenarios/sync`: проверено, досоздано и в каком моке, что не удалось
  - `POST /api/v1/scenarios/reset` (`KEEP_CUSTOM`/`BUILTIN_ONLY`): очистка четырёх моков, применение заново, встроенные возвращаются к исходнику из кода, **`PUT /admin/chaos {"mode":"OK"}` у всех четырёх**
  - Поле `modified` у изменённых встроенных сценариев
- **Не входит:**
  - Единый сброс демо `POST /demo/reset` в `api` (модуль `demo`) и сброс одной персоны (Q-105) — задачи `api`

## Критерии приёмки

- [ ] Таблица ситуаций из 10.6 проходит целиком (пересборка с цельным томом, `down -v`, удалена база одного мока, смена месяца, упавший мок при старте)
- [ ] После `reset` режим chaos у всех четырёх моков `OK` — проверяется запросом `GET /admin/chaos`
- [ ] В пересозданный мок идут сохранённые `expanded`: ИНН и номера счетов прежние
- [ ] Данные `RUNTIME` (выдачи) не стираются при сверке, где данные сценария есть
- [ ] Фоновый повтор срабатывает без перезапуска сервиса
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

Интеграционные тесты с compose и ручным управлением часами (`APP_TODAY`): смена месяца, удаление базы одного мока, остановка мока, `sync`, оба режима `reset`. Параллельный `reset` и `apply` не дают гонок.

## Заметки для реализации

- Эту часть легко сломать неочевидной гонкой (`sync` во время `apply`): ставьте блокировку на сценарий в базе.
- Время 03:00–04:00 берите из часов стенда, чтобы тест мог его «проиграть».
