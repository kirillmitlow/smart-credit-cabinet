## Цель

Тесты с самого начала: структура папок, маркеры, профили Hypothesis и общие генераторы «реалистичной компании», на которых потом строятся property-тесты ядра и синтетика.

## Входит / не входит

- **Входит:** папки `unit/`, `property/`, `integration/`, `contract/`, `personas/`, `synthetic/`, `resilience/`; маркеры `unit`, `property`, `integration`, `contract`, `persona`, `synthetic`, `chaos`, `slow`; `make check` гоняет только быстрые; фикстура запрета сокетов, времени и файлов для тестов ядра (INV-51); профили Hypothesis: `dev` 50, `ci` 200 с `derandomize`, `deep` 2000 со случайным seed (D-088, Q-101); `tests/strategies`: генератор входов для `decide()` — выручка по логнормали, возраст 0–30 лет, 0–5 кредитов, пропуски; пока по типам из [T-280](T-280-decide-types-and-purity.md); пороги покрытия 90% строк / 85% ветвей для ядра и 70% остального (D-087), падение блокирует слияние.
- **Не входит:** сами инварианты ([T-303](T-303-core-property-tests.md)).

## Критерии приёмки

- [ ] `pytest -m unit` и `pytest -m property` запускаются раздельно
- [ ] Попытка открыть сокет в тесте ядра падает с понятным сообщением
- [ ] Профиль выбирается переменной окружения, `ci` детерминирован
- [ ] Покрытие считается без `__init__.py`, миграций и `TYPE_CHECKING`
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

meta-тесты фикстур: запрет сокета срабатывает, профиль применяется.
