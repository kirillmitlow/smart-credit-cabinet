## Цель

Ответы мастера превращаются в основной продукт и одну альтернативу по таблице правил из конфига; ответы сохраняются в черновик заявки; продукт не выбирает модель (D-060).

## Входит / не входит

- **Входит:** раздел `wizard` политики: слоты, ветвление, таблица «ответ → продукт», порог суммы для вопроса о залоге; ручка возвращает основной и альтернативный продукт, «почему подходит вам», примерный платёж, срок решения, нужные документы, путь «На запуск» для бизнеса моложе 6 мес; варианты «комфортного платежа» (2–3 пары срок → платёж → переплата), тот, что по силам при известной выручке, помечен; создание заявки `DRAFT` в начале мастера и перенос ответов в `draft`.
- **Не входит:** свободный текст ([T-244](T-244-amount-parser.md), [T-245](T-245-wizard-parse-text.md)); предварительный расчёт PREVIEW ([T-243](T-243-preview-and-preapproval.md)).

## Критерии приёмки

- [ ] Таблица «ответы → продукт» из [10-07](../../10-product/07-need-wizard.md) проверяется набором unit-тестов один в один
- [ ] Для каждой персоны мастер даёт продукт из [10-02](../../10-product/02-personas.md) (`snabkontrakt` → `WORKING_CAPITAL`, `stankoprom` → `INVESTMENT`, `quick-start` → путь «На запуск»)
- [ ] Кандидат, не проходящий требования продукта, не показывается основным; причина доступна
- [ ] «Не знаю» не блокирует, подбор идёт без этого ответа
- [ ] Один и тот же набор ответов даёт один продукт независимо от источника (кнопки или текст)
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

unit: таблица подбора (все строки); integration: персоны; property: ответы всегда дают продукт или «каталог с подсказкой».

## Заметки для реализации

- Таблица лежит в конфиге, а не в коде фронта ([10-07](../../10-product/07-need-wizard.md), заметки).
