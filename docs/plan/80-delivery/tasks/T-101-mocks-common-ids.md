## Цель

Все роли и генератор сценариев используют один модуль для проверки, генерации и маскирования идентификаторов. Значит, любой ИНН в стенде синтетический (регион `00`) и проходит контрольную сумму.

## Входит / не входит

- **Входит:**
  - `common/inn.py`: проверка ИНН 10 и 12 цифр с контрольной суммой; генерация валидных ИНН региона `00`; маскирование для логов (`0017****22`)
  - ОГРН (13 цифр), ОГРНИП (15 цифр) и КПП: генерация и проверка; год в ОГРН совпадает с годом регистрации; первые 4 цифры КПП равны первым четырём цифрам ИНН
  - `common/accounts.py`: номера счетов 20 цифр с верным ключом по БИК `040000999` (расчётный `40702…`/`40802…`, ссудный `45206…`/`45406…`); отдельный БИК «другого банка» `040000111` для выписки
  - Генерация детерминирована: принимает `seed`
- **Не входит:**
  - Использование модуля в ролях (подключают задачи ролей)
  - Генерация УИд обязательств БКИ (в [T-123](T-123-mocks-expand-bki-basic.md))

## Критерии приёмки

- [ ] Все ИНН из примеров спецификации и гида проходят проверку контрольной суммы (в том числе `001234567887`, `0017654322`, `0015557771`)
- [ ] Сгенерированные ИНН всегда имеют регион `00`; повтор с тем же `seed` даёт тот же результат
- [ ] Неверная длина или контрольная сумма даёт ошибку, которую роли превратят в `400 INN_INVALID`
- [ ] Номера счетов из примеров спецификации проходят проверку ключа; сгенерированный номер проходит ту же проверку
- [ ] Маска ИНН не раскрывает середину; ФИО и номера счетов в лог не попадают
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Unit-тесты на примерах из спецификации и гида; property-тест (Hypothesis): любой сгенерированный идентификатор проходит собственную проверку, любая замена одной цифры её не проходит.

## Заметки для реализации

- Алгоритм ключа счёта — по правилам ЦБ (ключ считается по БИК и номеру счёта); сверить пример счёта из раздела 7.5 спецификации.
- Регион `00` в ИНН/ОГРН — требование кейса RQ-52: данные не должны совпасть с реальными.
