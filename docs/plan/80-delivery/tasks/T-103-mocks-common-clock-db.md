## Цель

У стенда одно «сегодня» (`APP_TODAY`), и каждая роль умеет подключаться к своей базе, применять миграции при старте и помечать записи происхождением. Без этого сценарии «стареют», а сброс не отличает данные сценария от данных, появившихся в работе.

## Входит / не входит

- **Входит:**
  - `common/clock.py`: единственный источник «сейчас» (`APP_TODAY` задаёт дату, время суток реальное; пусто = реальные дата и время); границы суток и месяца по Europe/Moscow; допуск ±5 минут вынесен в функцию; прямой вызов `datetime.now()` и `date.today()` запрещён правилом ruff `DTZ`
  - `common/reldate.py`: разбор `-3M`, `-9y`, `-14d`, `-2y3M`, `+3M` в абсолютную дату; правило «последний год отчётности» (до 1 апреля — позапрошлый год)
  - `common/db.py`: engine, сессия, применение Alembic-миграций роли при старте (под блокировкой), `GET /health/ready` проверяет БД и миграции
  - Миксин таблиц: `origin` (`SCENARIO`/`RUNTIME`) и `scenario_code`
  - Фоновая очистка устаревших ключей идемпотентности — заготовка планировщика (наполнит [T-104](T-104-mocks-common-idempotency.md))
- **Не входит:**
  - Таблицы конкретных ролей (задачи ролей)
  - Часы `api` (их делает задача ядра, но по тому же правилу)

## Критерии приёмки

- [ ] Смена `APP_TODAY` на 30 дней вперёд сдвигает «сегодня» во всех модулях; без неё работает реальное время
- [ ] Граница месяца и суток считается по Москве: тест на 23:30 UTC 31-го числа
- [ ] Все относительные форматы из спецификации разбираются; ошибка формата — понятное сообщение
- [ ] `GET /health/ready` возвращает `503`, пока БД недоступна или миграции не применены, и `200` после
- [ ] ruff падает, если в `mocks/app` использован `datetime.now()` или `date.today()`
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Unit-тесты часов и относительных дат (граничные случаи: конец месяца, високосный год, переход через 1 апреля для отчётности); интеграционный тест с Postgres из [T-516](T-516-testcontainers-harness.md) или временной базой: миграции вверх и `ready`.

## Заметки для реализации

- Часы — общий модуль, чтобы никто не вызывал системное время напрямую (раздел 3.3 спецификации).
- Alembic: свой набор миграций на роль (`roles/<роль>/migrations`), общий каталог версий не нужен.
