## Цель

Человек ставит отдельные галочки и подтверждает весь свой пакет одним кодом; в базу пишется доказательство подписи, а не хеш шестизначного кода.

## Входит / не входит

- **Входит:** принятие «Правил использования простой подписи» `pep-rules-v1` один раз на человека (событие в аудит); `POST` на подпись пакета: код из [T-211](T-211-one-time-codes.md) цели `SIGN_CONSENT`, запись `proof = HMAC(секрет, код + хеш текста + ИНН + идентификатор попытки)`; достаточно галочки «ознакомлен», открытие документа не обязательно (D-092); события в журнал, подписанные согласия видны участникам.
- **Не входит:** подпись договора ([T-263](T-263-contract-signing.md)).

## Критерии приёмки

- [ ] Подпись не под своим пользователем отклоняется; повтор «Подписать» не создаёт второй подписи
- [ ] В `proof` не восстанавливается код, секрет не попадает в БД и логи
- [ ] Три неверных кода блокируют пакет
- [ ] Время подписи берётся из `clock`
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

integration: цепочка выпуск кода → подпись; негативные; unit: HMAC и независимость от порядка.
