## Цель

Единственный «ревьюер» для обоих агентов: что не зелёное, то не влито. Каркас с итоговой задачей `ci-ok` появляется первым, а остальные задания подключаются по мере появления кода.

## Входит / не входит

- **Входит:**
  - Workflow(ы): триггеры PR / push в `main` / ночью / тег `submission` по таблице 70-08; отмена предыдущего запуска того же PR; версии действий точные
  - Итоговое задание `ci-ok` (обязательная проверка PR): зелёное, когда зелены все нужные
  - Задания `lint-py`, `lint-web`, `arch`, `docs` (только `docs/plan/**` запускают одну лёгкую задачу), `build` (`docker buildx` образов `api`, `mocks`, `web` без публикации; кэш слоёв)
  - Кэши: `uv` (по хешу `uv.lock`), `pnpm`, слои Docker; браузеры Playwright (по версии)
  - Сводка запуска в `$GITHUB_STEP_SUMMARY`
- **Не входит:**
  - Тестовые задания ([T-510](T-510-ci-tests-coverage.md)), контракты и безопасность ([T-511](T-511-ci-contracts-security-notices.md)), e2e ([T-512](T-512-ci-e2e.md)), ночные ([T-513](T-513-ci-nightly-full.md)), релиз ([T-514](T-514-ci-release-ghcr.md))

## Критерии приёмки

- [ ] На PR с одним тривиальным тестом `ci-ok` зелёный; при красном `lint-py` красный
- [ ] Изменение только в `docs/plan/**` запускает лёгкое задание `docs`, остальное пропускается и `ci-ok` всё равно зелёный
- [ ] Быстрый набор укладывается в ориентир ≈ 15 минут (замер записан)
- [ ] Версии всех действий зафиксированы точно, секретов в обычных запусках нет
- [ ] Если защита веток недоступна на закрытом репозитории, это записано в [80-09](../09-risks.md), а правило «не просить merge при красном CI» вынесено в протокол
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Проверка запуском в тестовых PR: зелёный, красный линтер, изменение только документов.

## Заметки для реализации

- Первый коммит кода — каркас с зелёным `ci-ok` на одном тесте (50-03).
- CI запускает те же команды, что `make check` и `make test`; в Makefile нет флагов, которых нет в CI, и наоборот.
