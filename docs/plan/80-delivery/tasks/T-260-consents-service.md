## Цель

Согласия на БКИ, обороты и персональные данные хранятся с версией и хешем текста; список обязательных согласий определяется заявкой; БКИ нельзя вызвать без действующего согласия.

## Входит / не входит

- **Входит:** тексты в `policy/consents/*` (версия в имени, SHA-256 после нормализации пробелов), показ перед подписью; таблица `consents` (`bundle_id`, `subject_inn`, `kind`, `purpose`, `text_version/hash`, `signed_at`, `valid_until`, `signer_user_id`, `proof`, `revoked_at`); набор обязательных согласий заявки: БКИ компании/ИП, БКИ директора, БКИ поручителя, обороты (клиенту банка), ПДн каждого человека — по одному согласию на человека, если директор = владелец; правила кто может подписать: компания — DIRECTOR или сотрудник с действующим `SIGN_COMPANY_CONSENTS`, личные — только сам субъект; срок 6 месяцев; `get_valid_consent(application, subject, kind)` для адаптера БКИ.
- **Не входит:** подпись пакета кодом ([T-261](T-261-consent-bundle-signing.md)); отзыв ([T-262](T-262-consent-revocation.md)).

## Критерии приёмки

- [ ] Изменение текста = новая версия, прошлые подписи не меняются; хеш нормализованного текста воспроизводим (тест)
- [ ] Просроченное согласие → `CONSENT_EXPIRED`; нет согласия → БКИ не вызывается (тест на счётчик вызовов мока = 0)
- [ ] Предзаполненных галочек нет; согласие ПДн отдельное от БКИ
- [ ] Для `sokolova` (ИП) и `stankoprom` (ООО, директор = владелец) набор согласий верный
- [ ] Согласие привязано к одной заявке и не переносится на новую (D-077)
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

unit: набор согласий по случаям; integration: полномочия, срок, привязка.

## Заметки для реализации

- Согласие компании сотрудник подписывает только при действующей доверенности и полномочии ([T-223](T-223-poa-permissions.md)); личные не делегируются (D-091).
