## Цель

Клиент видит, что берём и зачем, ставит отдельные галочки (БКИ, обороты, персональные данные) и подтверждает пакет одним кодом; предзаполненных галочек нет (D-092).

## Входит / не входит

- **Входит:** список согласий заявки по субъектам (компания, директор/ИП, поручитель), текст и версия перед подписью; принятие «Правил использования простой подписи» один раз, код с плашкой «Демо: в реальной системе код пришёл бы по SMS»; статус «подписали 1 из 2», кто что ещё должен подписать; достаточно галочки «ознакомлен», открытие файла не обязательно.
- **Не входит:** передача руководителю и отзыв ([T-420](T-420-web-handover-and-consent-revoke.md)).

- [x] Нельзя подписать чужое личное согласие; сотрудник без полномочия не подписывает согласия компании

- [x] Подписанные согласия отображаются неизменяемо
- [x] Тесты написаны и зелёные (`make check`)

## Заметки для реализации

- Честная оговорка о демо-коде — в README и в плашке ([20-04](../../20-process/04-consents-and-signing.md)).
- Реализовано в `web/src/features/application/ConsentsStep.tsx`; код пакета — `ConsentCodeForm.tsx`. `canSign`, набор и версии текстов берутся из API, состав пакета после получения кода неизменяем.
- `ReviewStep` проверяет `allSigned` до отправки; опрос раз в 5 секунд подхватывает подпись другого участника. Передача руководителю и отзыв остаются T-420.
- Проверено: `make check` и полный `make -C web test`, 298 тестов фронтенда, 94,97% строк; axe без критических и серьёзных нарушений. API и сгенерированный клиент не менялись.
