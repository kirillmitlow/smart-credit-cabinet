## Цель

Для компаний без оборотов в нашем банке (Гарипов и любой пользовательский сценарий с `bank.isCustomer: false`) сервис генерирует файл `1CClientBankExchange`, согласованный с финансами сценария. Кабинет разбирает его тем же парсером, что и настоящую выписку.

## Входит / не входит

- **Входит:**
  - `GET /api/v1/scenarios/{code}/documents/bank-statement?months=1..24` и `POST /api/v1/documents/bank-statement` (произвольный ИНН, `avgMonthlyRevenueRub` обязателен, необязательные `holderName`, `okved`, `vatRatePercent`, тренд, сезонность, `seed`)
  - Файл `text/plain; charset=windows-1251`, CRLF, `Content-Disposition` с именем `statement_<ИНН>_<ГГГГ-ММ>_<ГГГГ-ММ>.txt`, без блока `meta`; признак симуляции в заголовке файла
  - Структура: заголовок, секция остатков, платёжные поручения (`СекцияДокумент`…`КонецДокумента`), `КонецФайла`; «другой банк» вымышленный (БИК `040000111`)
  - Согласованность: период — последние полные месяцы; поступления ≈ `incomingRub` оборотов сценария (разброс 5–8%); списания = поступления − остаток; начальный остаток + поступило − списано = конечный, «всего» равны сумме документов; до ~60 документов в месяц
  - Детерминизм по сценарию: один запрос дважды — один файл; `POST` без `seed` — разные файлы; ИНН владельца в файле равен ИНН сценария
- **Не входит:**
  - Разбор выписки и загрузка в `api` (парсер 1С — задача `api`)
  - Кнопка «сгенерировать» в интерфейсе

## Критерии приёмки

- [x] Эталонный парсер формата 1С (в тесте) читает файл без ошибок; суммы сходятся
- [x] Ошибки: `400 INN_INVALID`, `422 VALIDATION_ERROR`, `404 SCENARIO_NOT_FOUND`, `422` для сценария без расчётного счёта бизнеса
- [x] Поступления по месяцам ≈ `incomingRub` оборотов сценария (для Гарипова ровно 700 тыс./мес при noisePercent: 0; списания 600 тыс.)
- [x] Файл разбирается настоящим неизменённым parse_statement кабинета (3/12/24 месяца); кнопку и полный путь после слияния проверяет Codex №1 по указанию пользователя 25.10
- [x] Эндпоинты требуют `X-Admin-Key`, описаны в OpenAPI
- [x] Тесты написаны и зелёные
- [x] Документация и OpenAPI обновлены, если менялся контракт
- [x] Запись в журнале
- [x] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Unit-тесты генератора (суммы, период, детерминизм, кодировка, CRLF); контрольный эталонный парсер в тестах; тест соответствия оборотам сценария.

## Заметки для реализации

- Приоритет S: резется вместе с парсером выписки в `api` (Should по [10-05](../../10-product/05-mvp-scope.md)). Если на 24.10 парсер подтверждён, задача считается Must (решает [80-02](../02-schedule.md)).
- Если парсера нет, `NEEDS_INFO` у Гарипова закрывается вручную; это решение по продукту, а не по мокам.

### Фактическая проверка C, 25.10

Реализация: `81137f808d173d66c704272c5a45f8a672454951`. Только scenarios, его тесты и экспорт mock-scenarios.openapi.yaml; без новых зависимостей. GET читает сохранённый snapshot, POST не читает и не пишет сценарии. Файл формируется динамически, расчёт ведётся в целых копейках. POST без seed создаёт новый файл даже при нулевых оборотах; seed и GET воспроизводимы.

`make -C mocks check`: mypy — 111 файлов, 569 тестов прошли. Полный `make -C mocks test`: 900 тестов прошли, покрытие 94,89%. Все шесть схем совпадают с кодом, изменён только экспорт scenarios. Настоящий parse_statement отдельно прочитал свежую генерацию за 3/12/24 месяца. При APP_TODAY=2026-10-21 файл за 12 месяцев: 01.10.2025–30.09.2026, 437 документов, по 700000 ₽ поступлений и 600000 ₽ списаний ежемесячно, начальный остаток 0 ₽, конечный — 1200000 ₽. SHA-256: `4f44b423281c86ef61dc429eb252a0b48065cf3467a248a3d5ccbfb5175ee8fc`.

Единственное предупреждение UNCLASSIFIED_RECEIPTS ожидаемо: пользователь должен отдельно подтвердить поступления от бизнеса. Мок выдаёт от 1 до 24 месяцев, а парсер кабинета для источника дохода требует минимум три полных месяца. Кнопку и весь путь Гарипова после слияния проверяет Codex №1.

Общий make check на Mac: 1357 быстрых тестов API прошли, два теста PDF не нашли системную libgobject; API не менялся. В раннем полном прогоне mocks два контейнерных теста не запустились из-за PATH без Docker credential helper. После исправления команды итоговые 900 прошли. Общий CI — обязательный барьер слияния PR.
