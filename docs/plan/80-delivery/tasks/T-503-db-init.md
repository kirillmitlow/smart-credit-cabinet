## Цель

На любом томе Postgres, пустом или уже заполненном, появляются базы `app` и пять баз моков со своими пользователями, и контейнер завершается.

## Входит / не входит

- **Входит:**
  - Идемпотентный SQL: создать пользователя и базу, если их нет, выдать права (database-per-service: `app`, `mock_registry`, `mock_tax`, `mock_bki`, `mock_bank_core`, `mock_scenarios`)
  - One-shot контейнер, код возврата 0 (`service_completed_successfully`); пароли из `POSTGRES_PASSWORD` и `MOCK_DB_PASSWORD`
  - Повторный запуск ничего не ломает; добавление нового мока на существующем томе создаёт только недостающее
- **Не входит:**
  - Миграции схем (делает каждый сервис сам)

## Критерии приёмки

- [ ] Два запуска подряд на одной базе проходят успешно
- [ ] Каждый пользователь видит только свою базу (проверка попыткой подключиться к чужой)
- [ ] Скрипт лежит в `deploy/db-init/` и не содержит секретов в коде
- [ ] Время работы контейнера меньше 10 секунд
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Интеграционная проверка в CI-задании `integration` или `e2e`: запуск дважды, подключение под каждым пользователем.

## Заметки для реализации

- Postgres не умеет `CREATE DATABASE IF NOT EXISTS`: используйте проверку по `pg_database` и `\gexec`.
