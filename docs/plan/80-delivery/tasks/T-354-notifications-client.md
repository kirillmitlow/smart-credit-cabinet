## Цель

Уведомление создаётся один раз на событие и получателя и ведёт на конкретный экран; текст хранится ключом и параметрами, показывается из словаря интерфейса.

## Входит / не входит

- **Входит:** таблица `notifications` (`user_id` или `person_inn`, `company_id`, `application_id`, `kind`, `text_key`, `params`, `read_at`, `event_id`), уникальность «получатель + событие»; таблица правил «событие → получатели → ключ текста → каналы» в конфиге (не `if` по коду), события клиента из [20-06](../../20-process/06-notifications.md) (К/Р/С/П); `GET /notifications`, `POST /notifications/{id}/read`, «прочитать все»; тост только там, где нужно действие (Q-134); поручитель получает только свои просьбы.
- **Не входит:** уведомления банка ([T-355](T-355-notifications-bank.md)); UI ([T-428](T-428-web-notifications-ui.md)).

## Критерии приёмки

- [ ] Дубль события даёт одно уведомление; чужая компания не видит чужих
- [ ] SSE-событие не содержит текстов; после обрыва колокольчик догоняет по `Last-Event-ID`
- [ ] Каждому событию из [20-06](../../20-process/06-notifications.md) соответствует ключ текста, иначе тест падает
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
