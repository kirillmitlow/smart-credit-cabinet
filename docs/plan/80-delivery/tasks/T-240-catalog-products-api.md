## Цель

Клиент видит шесть продуктов с границами суммы и срока и понимает, какой из них доступен его компании и когда станет доступен остальной (не тупик).

## Входит / не входит

- **Входит:** `GET /products`, `GET /products/{code}` из раздела `catalog` политики; доступность для компании через единую функцию требований продукта ([T-294](T-294-rules-product-requirements.md)): серая карточка с причиной и подсказкой «станет доступен после 6 месяцев обслуживания»; список документов для продукта (из [10-06](../../10-product/06-product-catalog.md)).
- **Не входит:** калькулятор ([T-241](T-241-payment-calculator.md)); мастер ([T-242](T-242-wizard-recommendations.md)).

## Критерии приёмки

- [ ] Те же функции требований вызывает ядро и каталог; расхождения «показали, а потом отказали» невозможны (тест: для каждой персоны допустимость в каталоге = допустимость в `decide()`)
- [ ] `OVERDRAFT` недоступен не-клиенту и клиенту с оборотами < 6 мес с понятным пояснением
- [ ] Новый продукт добавляется записью в `policy/v1.yaml`, без правок кода
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
