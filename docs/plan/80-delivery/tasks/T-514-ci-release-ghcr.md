## Цель

Публичные образы появляются только в момент сдачи (D-083) и только по тегу `submission` с ручным подтверждением. До этого `build` лишь собирает.

## Входит / не входит

- **Входит:**
  - Задание `release`: запуск только по тегу и вручную; перед публикацией — проверка, что в образы не попали `docs/` и PDF кейса, `trivy image` зелёный; образы помечены хешем коммита, базовые — по точной версии
  - Права записи пакетов выдаются только этому заданию; секретов, кроме встроенного токена, нет
  - Сухой прогон (`workflow_dispatch` с `dry-run`): собирает и проверяет, но не публикует
  - Инструкция по смене видимости пакетов на публичную (действие пользователя) и по проверке `docker pull` без логина
- **Не входит:**
  - Сам выпуск и тег ([T-539](T-539-release-and-tag.md))
  - Политика `image`/`build` в compose ([T-541](T-541-image-build-policy.md))

## Критерии приёмки

- [ ] В обычных запусках публикации нет (проверено)
- [ ] Сухой прогон проходит и показывает, какие образы и теги были бы выпущены
- [ ] Проверка «в образах нет `docs/` и PDF» реально падает на искусственном нарушении
- [ ] Список образов и их имена записаны в README-план ([80-06](../06-readme-plan.md))
- [ ] Дата и время публикации не раньше 26.10 (правило записано в чек-листе [80-05](../05-submission-checklist.md))
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Сухие прогоны; проверка `docker run` образа после сборки.

## Заметки для реализации

- Образы публичны, значит код в них виден всем (D-081). Убедитесь, что в образы не попадают `.env`, `docs/`, тестовые фикстуры с секретами.
- Образ `nlu` уже содержит модель (Q-142), его размер учитывайте при публикации.
