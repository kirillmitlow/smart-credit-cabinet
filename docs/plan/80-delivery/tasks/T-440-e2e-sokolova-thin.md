## Цель

Браузер доказывает тонкий сквозной сценарий (10-05): вход по ИНН и коду → мастер → заявка → согласия → таймлайн идёт сам → «Одобрено» с условиями → принятие и подпись договора → «Деньги зачислены» → «Мои кредиты» с графиком.

**Сценарий шире первоначальной карточки.** Экраны принятия, подписи ([T-426](T-426-web-accept-and-sign.md)) и «Мои кредиты» ([T-427](T-427-web-my-loans.md)) уже готовы, поэтому тест идёт до конца и это TS-001 целиком, а не только путь до решения.

## Входит / не входит

- **Входит:** сценарий на помощниках [T-518](T-518-playwright-harness.md): сброс персоны, вход по ИНН с кодом с экрана, мастер, заявка, ожидание решения до 90 с без перезагрузки страницы (`waitForStatus` читает таймлайн); проверки: ставка 21,5%, платёж 46 677 ₽, нет баллов и внутренних слов, axe на ключевых экранах; метка `TS-001`, элементы ищутся по роли и подписи.
- **Входит дополнительно (расширение):** «Принять и перейти к подписанию», подпись договора кодом с экрана, ожидание «Деньги зачислены: 500 000 ₽», «Открыть в «Мои кредиты»», кредит с графиком из 12 платежей и «Итого» 560 126 ₽ (долг 500 000 + проценты 60 126), ставка 21,5%, платёж 46 677 ₽, переплата 60 126 ₽.
- **Не входит:** остальные персоны ([T-441](T-441-e2e-counter-reject-notelig.md)…[T-443](T-443-e2e-garipov.md)); проверка PDF договора и «в АБС один кредит» (это слой API, `api/tests/personas`).

## Заметки для реализации

- Файл теста: `web/e2e/sokolova.spec.ts`, метка `TS-001` в названии. Шаги 2–3 заявки пока заглушки (T-417, T-418), тест проходит их кнопкой «Продолжить»; когда экраны оживут, добавить шаги.
- Тест идёт только на чистом стенде: повторная заявка Соколовой честно получает «встречное предложение» из-за платежа по первому кредиту. Пока нет сброса персоны ([T-372](T-372-demo-reset-persona.md)), на «грязной» персоне тест пропускается (в CI падает) с подсказкой пересоздать стенд.
- Решение проверяется по таймлайну и блоку исхода; цифры (21,5%, 46 677 ₽, 60 126 ₽) взяты из оракула [30-17](../../30-decisioning/17-persona-walkthrough.md).
