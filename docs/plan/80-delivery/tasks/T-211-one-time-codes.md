## Цель

Один механизм кодов для трёх целей (`LOGIN`, `SIGN_CONSENT`, `SIGN_CONTRACT`): 6 цифр, хеш в Redis на 5 минут, 3 попытки; в демо-режиме код возвращается ответом вместо SMS (D-020).

## Входит / не входит

- **Входит:** `issue(person, purpose, subject)`, `verify(request_id, code)` с хешем и TTL, счётчик попыток, привязка к человеку и цели; показ кода только при `DEMO_MODE=true`; вне демо код не возвращается и не пишется в лог; ошибки `CODE_INVALID`, `CODE_EXPIRED`, `CODE_ATTEMPTS_EXCEEDED`.
- **Не входит:** HMAC-доказательство подписи ([T-261](T-261-consent-bundle-signing.md), [T-263](T-263-contract-signing.md)); ручки входа ([T-212](T-212-client-login-api.md)).

## Критерии приёмки

- [ ] Код, выпущенный для одного человека или цели, не подходит другому (тест на разных целях и ИНН)
- [ ] Три неверные попытки блокируют код; повтор верного после блокировки отклоняется
- [ ] В базу код не пишется, в логах его нет (тест маскирования)
- [ ] Сравнение — `hmac.compare_digest`
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

unit + integration (Redis): выпуск, проверка, истечение по часам, блокировка.
