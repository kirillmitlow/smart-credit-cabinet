## Цель

Из `avgMonthlyRevenueRub` и режима налогообложения строятся согласованные обороты по счёту, строки бухотчётности, налоговый профиль и категория МСП. Этого достаточно для первой персоны (Соколова) и для тонкого сквозного сценария.

## Входит / не входит

- **Входит:**
  - Обороты у клиента банка: 12 месяцев (24, если есть отчётность, но не больше срока обслуживания); поступления = выручка месяца × (1 + НДС/100), `incomingNetRub` на 0,5–1% меньше; списания = поступления минус денежный остаток; шум ±5%
  - НДС: `finance.vatRatePercent`, иначе по дате месяца из `VAT_RATE_SCHEDULE` (20% до 2025, 22% с 2026) для ОСНО, 0 для остальных
  - Отчётность ГИР БО: выручка за год = сумма месячной выручки без НДС, прибыль = выручка × `netMarginPercent`, баланс сходится (1600 = 1100 + 1200 = 1300 + 1400 + 1500); годы от последнего отчётного назад, не раньше года после регистрации
  - Налоговый профиль: режимы, долги, доход равен строке 2110; категория МСП по выручке и численности (микро/малое/среднее; выше среднего — не в реестре)
  - Часть bank-core: клиент, расчётный счёт, остаток (`bank.isCustomer`, `customerSinceMonths`, `balanceRub`)
  - Параметр `noisePercent` (0 = плоские ряды без шума, как требуют персоны по 30-17); `minMonthlySurplusRub` задаёт нижнюю границу остатка; вместе с маржой воспроизводит точные числа персон (Соколова 110 000, СнабКонтракт 1 100 000, Гарипов 100 000, `quick-start` 105 000; у Зари 10% поступлений, у T-BASE 15%)
- **Не входит:**
  - Тренд, сезонность, расхождение отчётности и оборотов, пороги спецрежимов ([T-122](T-122-mocks-expand-finance-advanced.md))
  - Правила проверки (общий валидатор [T-126](T-126-mocks-consistency-rules.md))

## Реализация B, 21.10.2026

- `finance.py` возвращает готовые тела `tax` и `bankCore`. В `finance_series.py` один месячный источник выручки для оборотов и годовой строки 2110; отдельная случайность по коду/месяцу, без изменения общих месяцев при сдвиге окна. Все деньги через `Decimal`, HALF_UP до рубля; валовые поступления без шума до 100 ₽.
- НДС берётся из `ScenarioSettings.vat_rate_schedule` (`VAT_RATE_SCHEDULE`, JSON-объект дата → ставка). Числовой график меняется без правки формул; учитывается дата каждого месяца, явная ставка имеет приоритет. БИК берётся из настроек приложения; номер счёта проверяется с этим БИК.
- **D-102:** название пресета не означает Соколову. Её 905 000 / 795 000 получаются из явных параметров. Общий `IP_HEALTHY` остаётся 800 000 / 704 000 без шума. Минимум не заменяет положительную маржу, если та больше; отрицательная маржа без минимума создаёт списания выше поступлений.
- Техническое допущение по глубине: два последних допустимых года отчётности, каждый строго после года регистрации. Последний отчётный год — общий helper с границей 1 апреля. Отчётности у ИП/самозанятого нет; юрлицо без полного года не получает выдуманный год.
- МСП до 10-го числа следующего после регистрации месяца отсутствует. `isNewlyCreated` трактуется как период до первой годовщины (явное техническое допущение). Категория определяется обоими порогами; параметры — `SME_THRESHOLDS`. Отраслевые исключения и многолетний механизм изменения категории в MVP не моделируются.
- Синтетические доли баланса: активы — половина годовой выручки, не менее 10 тыс.; основные средства 40%, капитал 60%, краткосрочные обязательства — остаток. Это допущения генератора, не банковские пороги. Долгосрочные обязательства и проценты пока нулевые; согласование с БКИ относится к T-123/T-126. Уплаченные налоги здесь не рассчитываются, стоят нули; налоговый долг берётся из параметра.
- Отсутствие обслуживания вместе с явно заданным остатком (в том числе нулём), сроком обслуживания или `ourBank` — `422`. Для удаления параметров пресета сохраняются явно переданные `null`; отсутствующие поля и явный `null` различаются. JSON Merge Patch по-прежнему удаляет поле, восстанавливая при разворачивании пресет, если его больше ничто не перекрывает.
- Тренды, сезонность, намеренное расхождение, лимиты спецрежимов — T-122; кредитная история, комплаенс и применение — последующие карточки. OpenAPI не меняется: имеющийся `previewScenario` уже возвращает объект развёрнутых данных; тест снимка остаётся зелёным.
