## Цель

OpenAPI пяти ролей лежит в `docs/api/` и всегда совпадает с кодом. Это артефакт сдачи (RQ-18) и основа контрактных тестов адаптеров.

## Входит / не входит

- **Входит:**
  - `mocks/scripts/export_openapi.py` выгружает `docs/api/mock-registry.openapi.yaml`, `mock-tax…`, `mock-credit-bureau…`, `mock-bank-core…`, `mock-scenarios…`
  - Схемы безопасности `ApiKeyAuth` и `AdminKeyAuth`; описаны все коды ошибок через `Problem`; у каждого эндпоинта своя схема; примеры значений для «Try it out»
  - Контрактный тест: выгрузка из кода равна закоммиченному файлу (CI красный, если контракт поменяли, а документ нет)
  - Строка в `make openapi`
- **Не входит:**
  - Выгрузка OpenAPI `api` и клиент TypeScript ([T-543](T-543-make-openapi-all.md))
  - Spectral/oasdiff в CI ([T-511](T-511-ci-contracts-security-notices.md))

## Критерии приёмки

- [ ] Пять файлов в `docs/api/` совпадают с выгрузкой из кода
- [ ] В каждом файле есть обе схемы безопасности и привязка к эндпоинтам
- [ ] `operationId` читаемые (`<ресурс><Действие>`), чтобы Spectral не ругался
- [ ] Контрактный тест падает при изменении ручки без обновления файла
- [ ] Swagger каждой роли позволяет пройти «Authorize» один раз и выполнять запросы
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Контрактный тест (выгрузка = файл), проверка наличия схем безопасности, прогон Spectral локально.

## Заметки для реализации

- Выгрузка не должна зависеть от БД и «сегодня» (иначе файл будет меняться без причины).
