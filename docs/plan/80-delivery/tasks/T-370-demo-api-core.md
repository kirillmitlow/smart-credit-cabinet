**Реализация (22.10.2026, часть).** Модуль `api/app/modules/demo/` и зависимость `require_demo_mode` на весь роутер `/demo`: вне `DEMO_MODE` любая демо-ручка отвечает `403 DEMO_MODE_DISABLED`. Первая ручка роутера — `POST /demo/reset` ([T-371](T-371-demo-reset-all.md)). GET персон и GET/PUT chaos в main (#84). POST /demo/scenarios и служебный POST /demo/personas/{code}/login реализованы последующими PR. Новые ручки повесить на тот же роутер, гейт подействует сам. Локально демо-ручки открыты без входа (D-086); код стенда для облака — [T-374](T-374-demo-stand-code.md).

## Цель

Модуль `demo` (только при `DEMO_MODE`) отдаёт шпаргалку по персонам и переключает сбои моков; это единственное исключение из «api не вызывает админ-API моков» (D-081).

## Входит / не входит

- **Входит:** гейт `DEMO_MODE`, иначе `403 DEMO_MODE_DISABLED` на все `/demo/*`; `GET /demo/personas` (данные из `mock-scenarios`: что просит, ожидаемый исход и коды, что дальше) без кнопки входа; `GET /demo/chaos`, `PUT /demo/chaos/{system}` (прокси на `PUT /admin/chaos`); `POST /demo/personas/{code}/login` — только хелпер интеграционных тестов при `DEMO_MODE`; `POST /demo/scenarios` — создание тестовой компании.
- **Не входит:** сброс ([T-371](T-371-demo-reset-all.md), [T-372](T-372-demo-reset-persona.md)); выписка ([T-373](T-373-demo-bank-statement.md)).

## Реализация B, 23.10.2026

GET /demo/personas читает сценарии и отдаёт разрешённые поля, без users/spec/секретов. GET /demo/chaos возвращает доступность четырёх источников независимо; PUT меняет только разрешённый источник и режим. Общий замок ограждает переключение от сброса. Тестовый вход персоны и создание сценария не реализованы; клиент входит по ИНН, банк — через T-213.


**Создание сценария, B 23.10.** POST /demo/scenarios требует Idempotency-Key, принимает ScenarioSpec (учётки/длины проверяются api, остальные разделы проверяет сервис сценариев). Если code не указан, генерируется стабильный код по ключу. При потере ответа тот же ключ не создаёт другую компанию; локальный каталог и аудит синхронизируются атомарно через public companies.apply_scenario. Ответ содержит только персону и итог четырёх моков, без users/spec/expanded. Частичный внешний сбой не выдаётся за успех; при сохранённом FAILED повтор может дать SCENARIO_EXISTS — восстановление через apply сервиса сценариев, без автоматической перезаписи чужого кода. Локально и в облаке создание открыто при DEMO_MODE; в облаке действует общий лимит, код стенда по D-086 нужен только сбросам и сбоям.


**Служебный вход, B 23.10.** POST /demo/personas/{code}/login требует явный login существующего активного участника сценария. Возвращает userId/companyId/роль членства и HttpOnly sid_client, не меняя sid_bank. Клиентские экраны и e2e по-прежнему используют ИНН+код. Нет пересинхронизации учёток при входе: отозванные права не восстанавливаются. Сессия ротируется; при провале аудита/commit новая удаляется, старая сохраняется. Есть audit LOGIN/LOGIN_FAILED с пометкой demoHelper, защита от сброса компании и облачный лимит. У технического сценария без учёток входа нет. Публичные порты компаний и auth, без чтения их частных таблиц.
