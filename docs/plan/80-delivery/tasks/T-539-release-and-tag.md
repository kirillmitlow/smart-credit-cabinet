## Цель

Момент сдачи (26.10): тег `submission`, публикация публичных образов в GHCR (D-083) и проверка, что `docker compose up` работает и с готовыми образами. Только по явному «да» пользователя.

## Входит / не входит

- **Входит:**
  - Запрос подтверждения у пользователя (перечень: версия, список образов, что станет публичным)
  - Тег `submission` на проверенном коммите, запуск задания `release`, смена видимости пакетов на публичную (действие пользователя)
  - Проверка с чистой машины: `docker compose up` скачивает образы и доходит до `healthy`; сценарий проходится; `docker pull` без логина работает
  - Запись в README: тег, commit hash, дата; в журнал и handoff: что опубликовано
- **Не входит:**
  - Любые новые функции (после заморозки запрещены)

## Критерии приёмки

- [ ] Тег `submission` указывает на коммит с зелёным полным набором CI (включая `resilience` и `load`)
- [ ] Публичные образы скачиваются без авторизации, версия совпадает с тегом
- [ ] Первый запуск с готовыми образами укладывается в 1–2 минуты (цифра записана)
- [ ] Время публикации записано; последние коммиты после дедлайна отсутствуют
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Проверка с чистой машины ([T-535](T-535-clean-machine-linux.md)) после публикации.

## Заметки для реализации

- Выпуск возможен только после согласия пользователя; агент не публикует и не тегирует сам по себе (протокол).
- Фиксация точного времени дедлайна — [80-02](../02-schedule.md) и Q-009a.
