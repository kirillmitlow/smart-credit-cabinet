## Цель

Фоновые задачи ставятся по имени после коммита транзакции (R10) и выполняются воркером с `acks_late`; `beat` умеет запускать периодические задачи; воркер публикует признак жизни.

## Входит / не входит

- **Входит:** `app/worker.py`: Celery 5 + Redis, JSON-сериализация, `acks_late`, `reject_on_worker_lost`, `prefetch=1`, `visibility_timeout` 15 мин, без result backend, `max_tasks_per_child=200`; `shared.enqueue(name, **kwargs)` с хуком `after_commit`; `requestId` в заголовок задачи и восстановление контекста логов в воркере; очереди `pipeline`, `outbox`, `default`; расписание beat-заглушками (сторож 30 с, relay 30 с, истечение 60 с); хелсчек воркера по файлу в `/tmp` (сигнал `heartbeat_sent`).
- **Не входит:** сами задачи конвейера ([T-270](T-270-pipeline-skeleton.md)); outbox ([T-278](T-278-outbox-relay.md)); compose-сервисы `worker` и `beat` ([T-502](T-502-compose-main.md)).

## Критерии приёмки

- [ ] Задача, поставленная до коммита, не запускается; после отката транзакции задачи нет (интеграционный тест)
- [ ] Повтор доставки той же задачи (имитация) не ломает идемпотентную задачу-пример
- [ ] Воркер без падения читает задачу с `requestId` и пишет его в лог
- [ ] Постановка по имени работает без импорта модуля-исполнителя
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
