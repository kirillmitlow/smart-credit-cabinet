## Цель

Схема OpenAPI строится из кода (code-first, Q-059) с читаемыми именами операций, чтобы orval сгенерировал нормальный клиент для фронта ([T-402](T-402-web-api-layer-orval.md)); схема выгружается в репозиторий и проверяется.

## Входит / не входит

- **Входит:** единое правило `operationId` = `<ресурс><Действие>` (например `applicationsSubmit`), теги по модулям, `camelCase`-алиасы Pydantic; скрипт выгрузки схемы `api` в `docs/api/api.openapi.yaml` (без секретов), который вызывает общая команда `make openapi` из [T-543](T-543-make-openapi-all.md); тест перечня: каждая ручка из таблиц [50-07](../../50-architecture/07-api-design.md) есть в схеме (по мере появления ручек — список с пометками «ожидается»); правила Spectral: у каждой операции есть `operationId`, описаны ошибки, имена полей `camelCase`.
- **Не входит:** сводная команда на шесть схем и генерация TS-клиента ([T-543](T-543-make-openapi-all.md), [T-402](T-402-web-api-layer-orval.md)); сводная команда `make openapi` на шесть схем ([T-543](T-543-make-openapi-all.md)), oasdiff и Spectral в CI ([T-511](T-511-ci-contracts-security-notices.md)), Schemathesis ([T-519](T-519-schemathesis-harness.md), [T-393](T-393-api-contract-tests-critical.md)).

## Критерии приёмки

- [ ] `make openapi` даёт воспроизводимый файл; повторный запуск без изменений кода не меняет файл
- [ ] Spectral без ошибок на текущей схеме
- [ ] Все ошибочные ответы описаны как `problem+json`
- [ ] Swagger UI открывается без входа ([50-07](../../50-architecture/07-api-design.md), служебные)
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
