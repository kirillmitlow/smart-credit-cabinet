## Цель

Ядро возвращает коды с параметрами, а тексты собираются по справочнику `texts/ru`: клиенту — что случилось и что можно сделать, без банковских слов; андеррайтеру — с числами и источником.

## Входит / не входит

- **Входит:** каталог `texts/ru`: для каждого кода три текста (клиенту / андеррайтеру / что можно сделать) — допуск и данные, семь стоп-факторов, флаги и ограничение, правила продукта и деньги, маршрут и итог; общий форматтер (пробелы в числах, `₽`, даты `21.10.2026`, доли с запятой), подстановка параметров; правила: `AML_LIST` не раскрывает причину; флаги — «заявку смотрит специалист» с «Обычно до 1 рабочего дня»; тексты собираются в момент решения и сохраняются в снимке (Q-113).
- **Не входит:** вклад факторов и «что изменить» ([T-299](T-299-explanations-factors-whatif.md)); UI-словарь ([T-405](T-405-web-texts-dictionary-infra.md), [T-437](T-437-web-texts-full-60-06.md)).

## Критерии приёмки

- [ ] Тест полноты: у каждого кода политики есть все три текста
- [ ] Тест подстановки: все параметры заполнены, в выводе нет незаполненных скобок
- [ ] Тест языка: в клиентских текстах нет слов «грейд», «балл», «скоринг», «PD», «DSCR», «стоп-фактор», «флаг»
- [ ] Для `AML_LIST` клиентский текст не содержит причины
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

unit: полнота, подстановки, язык, AML.
