## Цель

Через админ-API сервис сценариев, тесты и человек в Swagger создают и меняют тестовые данные в каждом моке. Общая часть пишется один раз, роли только подставляют свои обработчики.

## Входит / не входит

- **Входит:**
  - Каркас `common/admin.py`: `PUT /admin/subjects/{inn}` (создать или заменить, заголовок `X-Scenario-Code` ставит `scenario_code` и `origin = SCENARIO`), `PATCH` (JSON Merge Patch, RFC 7396; массивы заменяются целиком), `GET /admin/subjects/{inn}` (включая `RUNTIME`-записи), `GET /admin/subjects?scenario=&origin=&limit=&offset=`, `DELETE /admin/subjects/{inn}`
  - `GET /admin/scenarios` (какие `scenario_code` есть и сколько субъектов у каждого), `DELETE /admin/scenarios/{code}` (со всеми `RUNTIME`-записями), `POST /admin/wipe` (всю базу мока, справочники не трогает)
  - Интерфейс `AdminHandler` для роли: проверить тело, записать, прочитать, удалить; ошибки `422` с понятной причиной и `404 SUBJECT_NOT_FOUND`
  - Все `/admin/*` требуют `X-Admin-Key`; chaos и латентность на них не действуют
- **Не входит:**
  - Конкретные тела `PUT` по ролям (их пишут задачи ролей: [T-107](T-107-mocks-registry-companies.md), [T-109](T-109-mocks-tax-core.md), [T-112](T-112-mocks-bki-reports-consent.md), [T-115](T-115-mocks-bank-core-reads.md))

## Критерии приёмки

- [ ] Все восемь запросов набора работают на тестовой роли-заглушке и описаны в OpenAPI со схемой `AdminKeyAuth`
- [ ] `PATCH` склеивает объекты и заменяет массивы целиком (тест на `activeLoans`-подобном массиве)
- [ ] `DELETE /admin/scenarios/{code}` удаляет и `RUNTIME`-записи этого сценария, чужие не трогает
- [ ] Без `X-Admin-Key` — `401`, ключ потребителя на `/admin/*` — `403`
- [ ] Пример ручной правки из 8.3 («Соколову признали банкротом») воспроизводится в Swagger после готовности [T-107](T-107-mocks-registry-companies.md)
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Интеграционные тесты на заглушке с реальной БД: PUT→GET, PATCH, DELETE, список с фильтрами, удаление по сценарию, wipe.

## Заметки для реализации

- `api` админ-API не вызывает никогда. Исключение — модуль `demo` при `DEMO_MODE=true` (D-081); на облачном стенде порты моков закрыты.
- Тело `PUT` описано в терминах ответа бизнес-API без `meta`: переиспользовать те же Pydantic-схемы, а не писать вторую.
