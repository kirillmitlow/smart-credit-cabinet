## Цель

Двойное нажатие и повтор после обрыва сети не создают второго эффекта: отправка, отзыв, принятие оферты, подпись, загрузка и ответ на задачу защищены одним механизмом ([50-07](../../50-architecture/07-api-design.md), «Идемпотентность»).

## Входит / не входит

- **Входит:** зависимость FastAPI для `POST`: область ключа = пользователь + метод + путь, хеш тела, хранение `2xx` ответа сутки в `idempotency_keys`; повтор → тот же ответ с `Idempotent-Replayed: true`; другое тело → `409 IDEMPOTENCY_KEY_REUSED`; запрос ещё идёт → `409 IDEMPOTENCY_IN_PROGRESS` + `Retry-After`; «брошенный» ключ через 60 с; очистка просроченных ключей (суточная).
- **Не входит:** идемпотентность вызовов во внешние системы ([T-230](T-230-resilience-layer.md), [T-278](T-278-outbox-relay.md)); защита автосохранения черновика (это `version`, [T-253](T-253-application-draft.md)).

## Критерии приёмки

- [ ] INV-80 и INV-81 из [70-02](../../70-quality/02-unit-and-property-tests.md): повтор — один эффект (одно событие, одна запись outbox); другое тело — `IDEMPOTENCY_KEY_REUSED`
- [ ] Параллельный повтор: второй запрос получает `IDEMPOTENCY_IN_PROGRESS`, а после завершения первого — сохранённый ответ (интеграционный тест на двух потоках)
- [ ] Не-`2xx` ответы не сохраняются, ключ можно использовать заново
