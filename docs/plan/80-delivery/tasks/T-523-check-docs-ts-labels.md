## Цель

Каталог тестовых сценариев (артефакт сдачи) и реальные автотесты не расходятся: каждый `TS-NNN` либо имеет тест с меткой, либо явно помечен «вручную» (Q-109, D-090).

## Входит / не входит

- **Входит:**
  - Разбор таблиц [70-09](../../70-quality/09-test-scenarios-catalog.md) (колонка «Автотест») и поиск меток `TS-NNN` в pytest-маркерах, тегах Playwright и именах Vitest
  - Отчёт: сценарии без теста, тесты с несуществующим `TS`, сценарии «РУЧНОЙ» без причины
  - Подключение к заданию `docs` ([T-509](T-509-ci-skeleton.md)); красное — если метка есть, а сценария нет
- **Не входит:**
  - Написание самих тестов и каталога

## Критерии приёмки

- [ ] Искусственная метка `TS-999` в тесте делает проверку красной
- [ ] Сценарий каталога с пометкой «E2E», но без теста, попадает в отчёт
- [ ] Сводка «N сценариев, M с автотестом, K вручную» выводится в сводку CI
- [ ] Проверка не падает на сценариях со статусом «РУЧНОЙ» с указанной причиной
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Unit-тесты разбора таблицы и меток на фиктивных файлах.

## Заметки для реализации

- Метки на тестах появляются по мере написания тестов; до V6 проверка работает в режиме предупреждений.
