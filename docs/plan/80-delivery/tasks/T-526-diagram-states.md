## Цель

Диаграмма состояний — обязательный артефакт (RQ-20). Она генерируется из таблицы переходов в коде (D-055) и проверяется тестом, поэтому не может разойтись с поведением.

## Входит / не входит

- **Входит:**
  - Генератор: таблица переходов стейт-машины → mermaid `stateDiagram-v2` (все 14 статусов, подписи переходов, терминальные состояния)
  - Тест «диаграмма = таблица»: закоммиченный `.mmd` равен выгрузке из кода; любой недопустимый переход даёт `409 INVALID_TRANSITION` (проверка на матрице всех пар статусов)
  - Выгрузка в `docs/architecture/application-states.svg` и `.png` + страница `application-states.md` с таблицей переходов (кто, при каком условии)
  - Команда `make diagrams`
- **Не входит:**
  - Сама стейт-машина (задачи `api`)

## Критерии приёмки

- [ ] Диаграмма содержит все 14 статусов и все переходы из таблицы 20-02
- [ ] Изменение таблицы переходов в коде без обновления диаграммы ломает тест
- [ ] Матрица всех пар статусов подтверждает: допустим ровно тот переход, который есть в таблице
- [ ] Страница описывает, кто делает каждый переход и при каком условии
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)
