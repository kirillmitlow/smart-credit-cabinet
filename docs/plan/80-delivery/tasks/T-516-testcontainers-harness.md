## Цель

Агент на любом ПК запускает интеграционные тесты одной командой `pytest`, не поднимая базу вручную (D-088, Q-104). Один контейнер на прогон, чистая схема на тест.

## Входит / не входит

- **Входит:**
  - `conftest.py`-фикстуры: контейнеры Postgres 17 и Redis (один раз на прогон), строка подключения, применение миграций, изоляция теста (чистая схема или откат; `FLUSHDB` для Redis)
  - Маркеры pytest (`unit`, `property`, `integration`, `contract`, `persona`, `synthetic`, `chaos`, `slow`) и профили Hypothesis (`ci`, `deep`)
  - Часы теста из `APP_TODAY`, а не системные; фабрика настроек `APP_ENV=test`
  - Работает и в `mocks/tests` (общий приём, отдельный `conftest`)
  - Понятное сообщение, если Docker недоступен
- **Не входит:**
  - Сами интеграционные тесты `api` и моков (по месту)

## Критерии приёмки

- [ ] Тест-пример с обращением к Postgres и Redis проходит на чистом ПК одной командой
- [ ] Два теста подряд не видят данных друг друга
- [ ] Старт контейнеров не дольше ~10 секунд, один раз на прогон
- [ ] Без Docker тест пропускается с пояснением, а не падает странной ошибкой
- [ ] Документация в `AGENTS.md`/комментариях `conftest`: как запускать подмножества по маркерам
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Тесты самой обвязки: изоляция, миграции, Redis, пропуск без Docker.

## Заметки для реализации

- Nonparallel по умолчанию; для параллельного запуска используйте схему на worker (если решите, зафиксируйте в PR).
- Версии образов Postgres и Redis в тестах равны версиям compose (одна константа).
