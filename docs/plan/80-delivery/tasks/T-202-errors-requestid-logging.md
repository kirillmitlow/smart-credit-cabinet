## Цель

Любая ошибка `api` — `application/problem+json` с машинным `code` и `requestId`; любая строка лога — JSON с `requestId`, а ИНН и запрещённые поля не попадают в логи никогда.

## Входит / не входит

- **Входит:** исключение приложения с `code`, `status`, `detail`, `errors[]`; обработчики для валидации FastAPI, `404/405`, необработанных ошибок (без стека наружу); middleware `X-Request-Id` (принять или создать `req_`+ULID), `X-Instance-Id`, контекст для логов и Celery-заголовков; structlog в JSON, обработчик маскирования ИНН (`0017****22`) и отбрасывания полей `ФИО`, счёт, пароль, код, токен, текст клиента; справочник кодов ошибок из [50-07](../../50-architecture/07-api-design.md) (`INVALID_TRANSITION`, `VERSION_CONFLICT`, `CONSENT_REQUIRED`, `RATE_LIMITED`…) одним файлом.
- **Не входит:** логи Celery-воркера (подключаются в [T-205](T-205-celery-skeleton.md)); метрики ([T-390](T-390-metrics-prometheus.md)).

## Критерии приёмки

- [ ] Единый тест: любая ошибка (валидация, 404, 409, 500) отдаёт `problem+json` с `code` и `requestId`
- [ ] Тест маскирования ([50-10](../../50-architecture/10-audit-and-observability.md)): набор логов с правдоподобными ИНН, ФИО и номерами счетов не содержит исходных значений
- [ ] `X-Request-Id` клиента возвращается в ответе; без заголовка создаётся новый
- [ ] `detail` не содержит текстов для людей: клиентский текст берётся фронтом из словаря по `code`
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

unit: формат ошибок, маскирование; интеграционный: сквозной requestId «запрос → лог».
