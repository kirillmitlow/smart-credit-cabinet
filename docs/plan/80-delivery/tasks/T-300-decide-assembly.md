## Цель

Шаги 1–13 из [30-01](../../30-decisioning/01-pipeline-overview.md) работают как одна чистая функция: выполняет все независимые проверки, собирает все нарушения, выбирает исход по приоритету и оставляет след шагов для таймлайна и карточки андеррайтера.

## Входит / не входит

- **Входит:** оркестрация в порядке: допуск → стопы → признаки → скоринг → ставка → лимиты и стресс → правила продукта → маршрут → встречные → объяснения; приоритет исхода: стоп-фактор → `NEEDS_INFO` → условное встречное для молодого бизнеса → ручные триггеры → автоматическое решение; режимы `PREVIEW` и `DECISION` (в PREVIEW — осторожные БКИ-факторы, те же функции правил продукта); `inputs_hash` (канонический JSON), `trace` шагов (выполнен или нет, какие значения сравнивались); для `COUNTER_OFFER`, `REJECTED` по деньгам и `NEEDS_INFO` — блок «что изменить» (если [T-299](T-299-explanations-factors-whatif.md) готов).
- **Не входит:** сохранение ([T-275](T-275-decision-persistence.md)).
