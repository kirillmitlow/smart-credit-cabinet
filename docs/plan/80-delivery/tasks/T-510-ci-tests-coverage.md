## Цель

Тестовые слои работают в CI с порогами из D-087: ядро 90% строк и 85% ветвей, остальное 70%. Падение ниже порога блокирует слияние.

## Входит / не входит

- **Входит:**
  - Задания `unit` (pytest + покрытие по зонам: ядро / остальной `api` / `mocks` / фронт), `property` (Hypothesis, профиль `ci` — 200 примеров; ночью `deep` — 2000), `web-unit` (Vitest + axe + покрытие), `integration` (Postgres и Redis через Testcontainers, миграции вверх-вниз-вверх)
  - Конфигурация исключений покрытия: сгенерированный клиент, миграции Alembic, `__init__.py`, `if TYPE_CHECKING`
  - Кэш каталога примеров Hypothesis; отчёты JUnit и покрытия как артефакты на 14 дней
  - Критические/серьёзные находки axe блокируют слияние, остальные — в отчёт (Q-107, D-089)
  - Сводка с ключевыми числами в `$GITHUB_STEP_SUMMARY`
- **Не входит:**
  - Синтетика и нагрузка ([T-513](T-513-ci-nightly-full.md), [T-521](T-521-synthetic-report-ci.md))
  - Сами тесты (пишутся вместе с кодом)

## Критерии приёмки

- [ ] Снижение покрытия ядра ниже 90%/85% делает `ci-ok` красным (проверено искусственным удалением теста)
- [ ] Профиль Hypothesis в PR — 200 примеров, ночью — 2000
- [ ] Задание `integration` не зависит от Docker-in-Docker экзотики и стабильно на 5 запусках подряд
- [ ] Нарушение axe уровня critical/serious в экранном тесте блокирует слияние
- [ ] Время набора записано, превышение предела 20 минут оформлено задачей оптимизации
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Проверка запуском на специально испорченных ветках; стабильность — пятикратный перезапуск.

## Заметки для реализации

- Маркеры pytest из 70-01: `unit`, `property`, `integration`, `contract`, `persona`, `synthetic`, `chaos`, `slow`; `make check` гоняет только быстрые.
- Нестабильные тесты не лечатся повтором (исключение: один повтор Playwright в CI).

## Итог выполнения

Сделано для того, что существует сегодня (`mocks/`): задание `tests-py` (матрица `api`, `mocks`, `nlu`; отсутствующий проект пропускается чисто), unit + property + integration одним `make test`, порог 70% в `mocks/pyproject.toml`, профили Hypothesis `dev`/`ci`/`deep` (`HYPOTHESIS_PROFILE`), сводка покрытия в `$GITHUB_STEP_SUMMARY`, артефакты JUnit и покрытия на 14 дней, `ci-ok` зависит от задания.

Подключается вместе с кодом, которого ещё нет: пороги ядра 90%/85% (появятся в `api/pyproject.toml` по тому же образцу), `web-unit` с Vitest и axe, ночной профиль `deep` (T-513), проверка искусственным удалением теста и пятикратный прогон `integration` на реальном CI.
