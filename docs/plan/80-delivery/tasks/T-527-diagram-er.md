## Цель

Модель данных — обязательный артефакт (RQ-21). ER-диаграмма строится из реальных таблиц, а не рисуется руками.

## Входит / не входит

- **Входит:**
  - Генератор ER (mermaid `erDiagram`) из метаданных SQLAlchemy или из схемы базы после миграций: таблицы, ключи, связи; группировка по модулям
  - Выгрузка `docs/data-model/er.svg`/`er.png` и страница `er.md` с описанием основных таблиц и назначением (кратко, ссылка на 50-06)
  - Тест: набор таблиц на диаграмме равен набору таблиц после `alembic upgrade head`
  - Отдельные базы моков кратко (одна схема на мок) или явная пометка «в 5 отдельных базах»
- **Не входит:**
  - Сама модель данных (задачи `api`)

## Критерии приёмки

- [ ] ER-диаграмма совпадает с базой после миграций (проверяет тест)
- [ ] Читается на GitHub и открывается как картинка; крупная схема разбита по модулям, а не одним полотном
- [ ] Страница объясняет простыми словами ключевые таблицы (заявка, версия заявки, решение, снимок источников, outbox)
- [ ] Команда `make diagrams` обновляет и ER
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)
