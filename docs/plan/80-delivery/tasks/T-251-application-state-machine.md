## Цель

Единственное место, где меняется статус: таблица переходов из [20-02](../../20-process/02-application-states.md) в коде, проверка «кто вызывает и при каких условиях», безопасная смена «сравнить и поменять».

## Входит / не входит

- **Входит:** 14 статусов, таблица разрешённых переходов, правила «кто» и «условия» ([20-02](../../20-process/02-application-states.md), «Кто вызывает переходы»); `UPDATE … SET status=… WHERE id=… AND status=… AND version=…`: ноль строк = `409`, не ошибка для задач; недопустимый переход → `409 INVALID_TRANSITION` с `currentStatus`; статус, версия и журнал не меняются; генерация диаграммы mermaid из таблицы и тест «диаграмма в документации = таблица в коде»; расчёт `allowedActions` из статуса и ролей.
- **Не входит:** вызов переходов из конвейера и бэк-офиса (в задачах-вызывающих).

## Критерии приёмки

- [ ] INV-70…INV-73 из [70-02](../../70-quality/02-unit-and-property-tests.md): из любого статуса достижим конечный; около 160 запрещённых пар дают `409`; случайные последовательности действий поддерживают инварианты (одно событие на переход, после `SIGNED` отозвать нельзя)
- [ ] Тест гонки: два потока одновременно переводят заявку, один успех, второй `409`; версия выросла один раз
- [ ] Недопустимых путей в обход таблицы нет: прямой `UPDATE status` вне модуля запрещён тестом/линтером
- [ ] Каждый переход пишет событие в той же транзакции ([T-252](T-252-events-and-audit.md))
- [ ] Тесты написаны и зелёные (`make check`)
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале

## Тесты

unit: каждый разрешённый переход; параметрические: все запрещённые пары; property: INV-70…73 (Hypothesis state machine); integration: гонка.
