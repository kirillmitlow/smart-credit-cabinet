## Цель

Любой мок можно «уронить» для демо и тестов: медленно, с ошибками, совсем, с потерянным ответом. Это то, что жюри увидит кнопкой «уронить БКИ» и что проверяют хаос-тесты.

## Входит / не входит

- **Входит:**
  - `GET /admin/chaos` и `PUT /admin/chaos` (`mode`, `errorRate`, `latencyMs`, `paths`, `rateLimitPerMinute`, `until`); режимы только прописными: `OK`, `SLOW`, `ERROR`, `DOWN`, `TIMEOUT`, `LOST_RESPONSE`
  - Состояние режима в памяти процесса; рестарт возвращает `OK`; `until` сам возвращает `OK`
  - Заголовок `X-Mock-Scenario` (`ERROR`, `SLOW`, `SLOW:3000`, `TIMEOUT`, `LOST_RESPONSE`) ломает один запрос, режим не меняет; работает только на бизнес-эндпоинтах
  - Порядок: chaos → ключ API → идемпотентность → обработчик → (для `LOST_RESPONSE`) обрыв соединения после коммита
  - `rateLimitPerMinute` включает `429` с `Retry-After`; `paths` ломает только часть путей
- **Не входит:**
  - Вызов chaos из демо-панели `api` (задача модуля `demo`)
  - Сброс chaos при `scenarios/reset` (в [T-129](T-129-mocks-resync-reset.md))

## Критерии приёмки

- [ ] Каждый режим ведёт себя как в таблице 8.2; `ERROR`, `DOWN`, `TIMEOUT`, `SLOW`, `429` срабатывают до обработчика и не оставляют ни данных, ни ключа идемпотентности
- [ ] `LOST_RESPONSE` выполняет запрос до конца (данные записаны), но клиент ответа не получает; повтор с тем же ключом возвращает результат без дубля
- [ ] `/health/*` и `/admin/*` под chaos не попадают
- [ ] Строчные значения режима отклоняются (`422`)
- [ ] Включённый режим виден в `GET /admin/chaos` и в поле `chaos` журнала запросов
- [ ] Тесты написаны и зелёные
- [ ] Документация и OpenAPI обновлены, если менялся контракт
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

pytest: по тесту на режим; `paths`, `until` (через сдвиг `APP_TODAY`); `X-Mock-Scenario` ломает только один запрос; `LOST_RESPONSE` + идемпотентный повтор на заглушке-выдаче.

## Заметки для реализации

- Обрыв соединения без ответа в uvicorn делается через закрытие транспорта в ASGI-обработчике; проверить на Windows-Docker и Linux одинаково.
- Один воркер uvicorn обязателен, иначе режим «расходится» между процессами.
