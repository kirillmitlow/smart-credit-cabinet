## Цель

Одна команда отвечает на вопрос «стенд живой и проходит счастливый путь». Её используют CI, разработчики и облачный стенд.

## Входит / не входит

- **Входит:**
  - `scripts/smoke.sh`: ожидание `/health/ready` каждого сервиса, вход под демо-персоной `sokolova` (ИНН + код с демо-экрана), подача заявки, ожидание `APPROVED`, подпись и `DISBURSED`
  - Таймауты и понятные сообщения; код возврата 0/1; работает на локальном стенде и на облачном (адрес параметром)
  - Вариант `--quick`: только готовность сервисов (для проверки Windows-участниками)
  - LF-окончания (`.gitattributes`), совместимость с `bash` в Git Bash/WSL
- **Не входит:**
  - Playwright-сценарии ([T-518](T-518-playwright-harness.md))

## Критерии приёмки

- [x] На работающем стенде скрипт доходит до `DISBURSED` для `sokolova` и возвращает 0
- [x] При остановленном моке скрипт возвращает 1 и называет причину
- [x] Параметр адреса стенда позволяет запускать на облаке
- [x] Скрипт использует только `curl`/`bash` и не требует установки пакетов
- [x] Тесты написаны и зелёные
- [x] Документация и OpenAPI обновлены, если менялся контракт (контракт не меняется)
- [ ] Запись в журнале
- [ ] Выполнено [определение готовности](../04-definition-of-done.md) (линтеры, PR по шаблону, статус задачи обновлён)

## Тесты

Запуск в CI-задании `e2e` и вручную; негативный запуск при остановленном сервисе.

## Заметки для реализации

- Скрипт появляется, когда есть вход и заявка (V3). До этого проверяется только `--quick`.
- Тот же скрипт запускает пользователь и команда на Windows ([T-536](T-536-windows-check-pack.md)).
- Реализовано C 23.10: [smoke.sh](../../../../scripts/smoke.sh),
  [справка и параметры](../../../../scripts/README.md),
  [18 автоматических проверок](../../../../scripts/tests/test_smoke.py). JSON читается
  на Bash 3.2+ без jq/Python; нужны только стандартные `mktemp`, `rm`, `sleep`, `cat`.
- Полный запуск сбрасывает **только Соколову** (повторяется лишь 409 занятого сброса)
  и доходит до выдачи; `--quick` не меняет данные. Не запускать одновременно с ручной
  проверкой Соколовой. Изменяющие запросы автоматически не повторяются.
- Через публичный адрес облака прямые пробы моков выключены: их порты закрыты по
  50-14. Полный сценарий проверяет интеграции через заявку, `--quick` — только web,
  API и сигнал воркера. Контракт кода облачного стенда добавится вместе с T-374.
- Проверено на Mac, Bash 3.2, отдельный compose-проект `scc-c-smoke`, web 22480,
  моки 22401–22405, `APP_TODAY=2026-10-23`: `APPROVED → DISBURSED` (0);
  остановленный `mock-tax` → имя сервиса и код 1 за 2 секунды. Нативная Windows
  пока не проверялась; это T-536, текущие проверки не заменяют её.
