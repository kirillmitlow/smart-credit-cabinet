## Зачем

Жюри клонирует репозиторий и проверяет прототип само, без нас (D-064). README — первое и главное, что оно открывает. Документ отвечает на вопрос «какие разделы нужны, в каком порядке и откуда берётся каждый». Текст пишется по задачам [T-530](tasks/T-530-readme-static.md) (ручные разделы), [T-531](tasks/T-531-readme-generated.md) (генерируемые), [T-532](tasks/T-532-jury-self-check-readme.md) (самопроверка).

## Принципы

- **Верх читается за минуту:** что это, три команды запуска, куда идти дальше. Остальное ниже.
- **Простые слова.** Термины с пояснением в скобках; без внутренних номеров `D-NNN` в основном тексте, их место в `docs/adr/`.
- **Не врём.** Чего нет, названо прямо. Числа (память, время) измерены ([T-534](tasks/T-534-resource-measurement.md)), а не взяты из плана.
- **Не копируем документы плана.** Короткая версия плюс ссылка. Таблицы, которые устаревают (переменные, порты, ИНН, качество), генерируются скриптом ([T-531](tasks/T-531-readme-generated.md)).
- **Относительные ссылки**, работающие на GitHub; все пути проверяются `check-docs` ([T-522](tasks/T-522-check-docs-links.md)).
- **Одна страница-путеводитель:** таблица «пункт кейса → где посмотреть» из [80-05](05-submission-checklist.md) в сжатом виде.

## Что обязательно сказать про запуск

- Работает **без интернета** после первой сборки; ничего не качается при старте (RQ-53).
- **Никаких файлов настройки не нужно**: ключи по умолчанию уже подставлены, `.env` не требуется (RQ-11).
- **Make не нужен** — это инструмент разработчиков (D-064). Windows: хватает Docker Desktop (WSL2) и Git.
- Образы публикуются в GHCR только в момент сдачи (D-083): до этого `docker compose up` собирает локально; после — скачивает готовые; запасной способ `docker compose up --build` ([T-541](tasks/T-541-image-build-policy.md)).
- Облачный стенд (если будет): ссылка, код стенда для сброса и сбоев (D-086), оговорка «стенд общий».
- Профиль `ai` (свободный текст): по D-094 включён везде, добавляет около 1 ГБ; без него всё проходит на кнопках; ответы модели — подсказки с подтверждением.

## Что не пишем в README

- Подробности ядра и формулы (они в `docs/plan/30-*`), историю обсуждений, названия задач `T-NNN`.
- Полные таблицы, которые легко устареть, руками: только генерация ([T-531](tasks/T-531-readme-generated.md)).
- Обещания «будет»: развитие описывается как идея, не как факт.
- Секреты и реальные данные; ИНН только синтетические (регион `00`).

## Проверка качества README

1. `check-docs`: все относительные ссылки живы, нет битых якорей.
2. Генерируемые части совпадают с источниками (CI: после `make readme` diff пуст).
