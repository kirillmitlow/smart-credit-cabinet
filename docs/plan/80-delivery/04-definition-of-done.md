## Зачем

Прототип пишут ИИ-агенты, и код вживую читает мало кто. Единое определение готовности заменяет ревьюера: если все пункты ниже выполнены, задачу можно принимать, не открывая код. Карточки задач (`tasks/T-NNN-*.md`) ссылаются сюда последней строкой критериев приёмки.

## Три уровня готовности

| Уровень | Что значит | Кто решает |
|---|---|---|
| **Готово к PR** | Все пункты общего списка выполнены локально, `make check` зелёный | Агент, автор задачи |
| **Готово к слиянию** | PR открыт, `ci-ok` зелёный, описание заполнено, критерии карточки отмечены | CI и агент-проверяющий; слияние с согласия пользователя (D-00E) |
| **Готово совсем** | PR влит в `main`, статус документа плана стал `IMPLEMENTED`, статус карточки `DONE`, запись в журнале | Агент после слияния |

## Общий список для любой задачи

1. **Критерии приёмки карточки** выполнены и отмечены; если что-то не вошло, это записано в PR и в новую карточку, а не молча пропущено.
2. **Тесты.** На новое поведение есть тест с проверкой результата (`assert` на содержание, а не «не упало»). Тест без проверки считается дефектом. Тесты лежат в слое, указанном в [70-01](../70-quality/01-test-strategy.md), и помечены `TS-NNN`, если сценарий есть в каталоге [70-09](../70-quality/09-test-scenarios-catalog.md).
3. **Линтеры и типы.** `make check` зелёный: `ruff`, `mypy` (строго в ядре), `import-linter`, для фронта ESLint, Prettier, `tsc --noEmit`. Сгенерированные файлы руками не правятся.
4. **Покрытие** не опускается ниже порогов: ядро 90% строк и 85% ветвей, остальной `api` и моки 70%, фронт 70% (D-087).
5. **Контракты.**
   - Менялся API: `make openapi` выполнен, выгрузка в `docs/api/` и клиент закоммичены в том же PR; в коллекции запросов есть новая ручка.
   - Менялась модель данных: есть миграция Alembic и тест миграций; ER-диаграмма обновится генератором ([T-527](tasks/T-527-diagram-er.md)).
   - Менялись правила кредитной политики: изменён `policy/*.yaml`, у каждого порога тест «чуть ниже / чуть выше», версия правил записана.
   - Менялись статусы заявки: обновлены таблица переходов и тест «диаграмма = таблица» ([T-526](tasks/T-526-diagram-states.md)).
   - Менялись контракты моков: решение записано, поднят `builtinVersion` затронутых сценариев.
6. **Документы.** Документ плана, который реализует задача, переведён в `IMPLEMENTED` (после слияния); подводные камни дописаны в его раздел «Заметки для реализации»; если код разошёлся с документом, правится документ с отметкой «Ред. N» и записью в журнале, а не наоборот молча.
7. **Безопасность.** Нет секретов в коде, логах и описании PR (`gitleaks` зелёный); нет полных ИНН и ФИО в логах; зависимости добавлены в lock-файл, лицензия допустима ([T-524](tasks/T-524-third-party-notices.md)).
8. **Журнал и handoff.** Запись в `07-journal.md`: что сделано, что решили, подсказки следующему. В конце смены перезаписан `08-handoff.md`.
9. **PR.** Заголовок `[A] T-NNN …` или `[B] T-NNN …`, по шаблону: что сделано, как проверить, ссылка на карточку и решения. Одна карточка — один PR. Новых функций, не описанных в карточке, нет.
10. **Состояние стенда.** Если задача влияет на запуск, `docker compose up` на чистом томе доходит до `healthy`; память не вышла за лимиты ([50-01](../50-architecture/01-overview.md)).

## Дополнения по типам задач

| Тип | Дополнительные пункты |
|---|---|
| **Ядро и расчёты** (`decisioning`, `simulator`, `pipeline`, `applications`) | Property-тесты инвариантов ([70-02](../70-quality/02-unit-and-property-tests.md)); `Decimal`, округление по [30-16](../30-decisioning/16-loan-math.md); детерминизм; сверка с оракулом [30-17](../30-decisioning/17-persona-walkthrough.md) в допусках; решение хранит версию правил и все входные данные; типы `mypy --strict` |
| **API и бэкенд** | Идемпотентность изменяющих `POST`; `problem+json` с `code` и `requestId`; проверка прав «своя/чужая компания»; события аудита; миграции вверх-вниз-вверх; `X-Request-Id` в журнале |
| **Интеграции** | Таймауты, повторы только где безопасно, предохранитель; контрактный тест против живого мока; сбой источника превращается в понятный исход, а не в `500` |
| **Моки** | Данные только в БД; все ИНН и ОГРН синтетические (регион `00`); OpenAPI роли выгружен ([T-139](tasks/T-139-mocks-openapi-export.md)); соответствие разделу 11 спецификации моков; идемпотентные операции проверены параллельным повтором |
| **Фронт** | Три состояния экрана (загрузка, пусто, ошибка); тексты из словаря ([60-06](../60-frontend/06-ux-writing.md)), без «аннуитетный», «обеспечение» и подобного; `axe` без критических и серьёзных нарушений; весь ключевой путь проходится клавиатурой; роли строятся по `allowedActions`, а не по копии стейт-машины |
| **Инфраструктура и CI** | Проверено на чистом запуске; версии точные (действия Actions, образы, пакеты); ничего не публикуется наружу до сдачи (D-083); изменение объяснено в `AGENTS.md`, если меняет команды |
| **Документы и артефакты сдачи** | Ссылки живы (`check-docs`); простой язык; нет блоков кода в документах для людей, кроме коротких примеров; упрощения названы прямо; строка в [80-05](05-submission-checklist.md) обновлена |
| **Исследование и ИИ** | У каждой ИИ-функции есть запасной путь без ИИ; лицензия модели в `THIRD_PARTY_NOTICES`; метрики не приукрашены; ответы модели только подсказки с подтверждением (D-094) |

## Что не считается готовым

- «У меня работает», но CI красный, `make check` не запускался или тест помечен `skip` без причины.
- Тест, который проходит при любом результате; тест, зависящий от системного времени (допустим только `APP_TODAY`), от порядка запуска или от интернета.
- Расхождение схемы и кода: выгрузка OpenAPI не совпала с закоммиченной.
- Правка по ходу, которую не отражает карточка: «заодно починил» без записи.
- Закомментированный код, `TODO` без номера карточки, временные файлы, отладочные логи.
- Секрет или ключ в истории (даже удалённый последним коммитом): история переписывается только с согласия пользователя.

## Как выполняется слияние

1. Агент помечает карточку `REVIEW` и просит согласие пользователя. Чтобы очередь не стала узким местом, предлагается **стоячее согласие**: пользователь разрешает агенту вливать PR, у которого `ci-ok` зелёный, критерии выполнены и нет правок общих контрактов, а согласует по отдельности только PR с изменением контрактов, правил кредитной политики и заморозочные (`freeze-fix`). Пока стоячего согласия нет, действует D-00E: слияние только с явным согласием.
2. Перед слиянием: `git fetch`, `rebase` на актуальный `main`, повторный `make check`.
3. После слияния ветка удаляется, статус карточки `DONE`, в [handoff](../00-meta/08-handoff.md) попадает, что дальше.
4. Красный `main` чинится первым делом и записывается в handoff.

## Облегчённая готовность

Для карточек, которые меняют только документы плана или файлы журнала, пункты 2–5 и 10 не применяются; остаются 1, 6, 8, 9 и проверка ссылок. Для исправлений после заморозки ([80-02](02-schedule.md)) действует полный список без послаблений: именно они попадают в выпуск.

## Заметки для реализации

- Шаблон PR лежит в `.github/PULL_REQUEST_TEMPLATE.md` ([T-500](tasks/T-500-monorepo-skeleton.md)) и дублирует общий список короткими флажками.
- Если пункт списка невозможно выполнить в рамках карточки, это записывается в PR строкой «не сделано, потому что…» и становится новой карточкой; тихое пропускание запрещено.
