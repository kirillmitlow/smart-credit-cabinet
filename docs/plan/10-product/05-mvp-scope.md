Кейс просит реалистичный MVP с явным объяснением, что вошло и почему (RQ-31). Ориентир от организаторов: **связанный процесс, где клиент подаёт заявку и получает результат, а банковская логика обрабатывает и решает** (10-00, п. 15). Жюри проверяет само (D-064).

## Принцип порядка реализации

Сначала **тонкий сквозной сценарий**, потом наращивание: демо-компания → потребность → заявка → проверки в моках → решение с причинами → результат клиенту. Каждая следующая функция встраивается в уже работающий путь.

## Must — без этого не сдаём

| Что | Почему | Требования |
|---|---|---|
| Вход под демо-компанией (способ — Q-035) и список демо-компаний с ожидаемыми исходами | Жюри должно само пройти сценарий | RQ-15, RQ-41 |
| Мастер подбора на кнопках + каталог + калькулятор платежа | Выбор продукта клиентом без экспертизы | RQ-03, RQ-60 |
| Автозаполнение по ИНН с источником у каждого поля, ввод личного ИНН → «вы директор ООО X» | Сокращение повторного ввода | RQ-61, D-015 |
| Заявка с автосохранением черновика, согласия (БКИ, обороты, ПДн) | Данные сохраняются | RQ-05 |
| Конвейер: полнота/согласия → источники и БКИ → стоп-факторы → признаки → скоринг → ставка → лимиты → решение (D-090) | Модель принятия решения | RQ-04, RQ-62…RQ-66 |
| Все исходы: одобрение, встречное с вариантами, нужна информация, ручное рассмотрение, отказ с причиной и следующим шагом | Небинарное решение | RQ-68 |
| Объяснения: коды причин, понятные клиенту тексты | UX, прозрачность | RQ-42 |
| Цикл `NEEDS_INFO`: задача клиенту → ответ → повторная оценка | Уточнение данных | RQ-63 |
| Живой таймлайн статусов без перезагрузки | Динамическое состояние | RQ-05 |
| Принятие оферты → имитация подписи без SMS → выдача в АБС → «Мои кредиты» с графиком | Путь до результата, а не до одобрения | RQ-69, RQ-40 |
| 4 мока + сервис сценариев, хаос-режимы, адаптеры с таймаутами, повторами и circuit breaker | Автономность, enterprise | RQ-53, RQ-44 |
| Стейт-машина заявки, аудит переходов, снимок решения с версией правил | Согласованность, сопровождение | RQ-43 |
| `docker compose up` одной командой, ≤ 4 ГБ RAM, lock-файлы | Готовность к проверке | RQ-11, RQ-13 |
| Тесты: unit, property, синтетика, контракты, e2e по персонам. CI | Качество, enterprise | RQ-22 |
| Артефакты сдачи: README с самопроверкой, архитектура, OpenAPI, коллекция, диаграмма состояний, модель данных, тестовые сценарии, `THIRD_PARTY_NOTICES` | Чек-лист стр. 7 | RQ-10…RQ-22 |
| Сброс демо одной кнопкой/запросом | Повторяемость самопроверки | RQ-41 |
| **Банковская сторона** | Ручные исходы должны чем-то завершаться | ❓ Q-034: объём решает пользователь |

## Should — делаем сразу после первого сквозного прохода

| Что | Почему |
|---|---|
| Свободный текст в мастере (D-060) | Одна понятная «умная» функция |
| Парсер выписки 1С для `NEEDS_INFO` (Гарипов) | Закрывает третий источник выручки без ручного ввода |
| Предодобренное предложение на главной (D-018) | Клиент банка видит сумму до заявки |
| Бухгалтер готовит — директор подписывает (D-014) | Прямо из ЦА кейса |
| Демо-управление сбоями: «уронить БКИ» → заявка уходит на ручное, а не падает | Отказоустойчивость, видна жюри |
| Метрики качества скоркарты на синтетическом портфеле (Gini, KS, стабильность) | Кейс упоминает проверку моделей (RQ-67) |
| Облачный стенд (Q-008) | Желательно по кейсу |
| Базовая наблюдаемость: структурные логи, метрики, сквозной `X-Request-Id` | Enterprise |

## Could — если останется время

- Обученная ML-модель рядом со скоркартой (Q-036).
- Генеративная LLM: объяснения и записка андеррайтеру (Q-007).
- Распознавание PDF и сканов отчётности.
- Песочница правил «а что если»: поменял порог — увидел, как меняется доля одобрений.
- Дашборды Grafana, трассировка.

## Won't — осознанно не делаем

| Что | Почему |
|---|---|
| Новостная лента | Не относится к кейсу (10-00) |
| Адаптив под телефон | Необязателен (10-00), десктоп важнее |
| Презентация | Не требуется (10-00) |
| Регистрация | Необязательна (10-00) |
| Настоящая электронная подпись, реальные платежи | Допускается моделирование |
| Kafka, BPMN-движок, Keycloak | Риск по времени без ценности для проверки (D-057) |
| Мобильное приложение | Запрещено кейсом |
| ФССП, арбитраж, реестр залогов, МЧД | Описываем как «не моделируем» в README (R-001, V21) |
