# Тексты интерфейса: как говорим с клиентом

| | |
|---|---|
| Статус | REVIEW |
| Владелец | Агент A (черновик субагента) |
| Зависит от | [10-07](../10-product/07-need-wizard.md), [20-02](../20-process/02-application-states.md), [50-07](../50-architecture/07-api-design.md), [60-03](03-client-screens.md) |
| Решения | Реализует D-012, D-064, D-085 (плашка «Демо»), D-091 (отдельный словарь, показанный текст в снимке), D-093; кейс: «пользователь может не обладать банковской экспертизой» |
| Обновлено | 21.10.2026, ред. 2: сведение R-002 |

## Зачем

Клиент не из банковской сферы. Интерфейс должен объяснять себя сам (D-064), без слов, которые нужно гуглить. Здесь: тон, словарь, тексты статусов, ошибок и пустых состояний, шаблон отказа и подсказки к терминам. **Тексты причин по кодам (`DSCR_LOW`, `TAX_ARREARS_HIGH`…) пишет документ 30-12** ([папка](../30-decisioning/)); здесь только шаблон, в который они вставляются. В коде все тексты лежат в `web/src/texts/` по ключам; ключ ошибки = `code` из API.

## Тон

1. На «вы», спокойно, без восклицаний и «к сожалению». Не «Увы, отказ!», а «Сейчас одобрить не можем».
2. Короткие предложения. Одно действие в одной кнопке.
3. Всегда три вещи: **что случилось → почему → что делать дальше**. Тупиков нет.
4. Конкретика вместо общих слов: «до 28 октября», «46 000 ₽ в месяц», а не «в ближайшее время».
5. Просим — объясняем **зачем**: «Загрузите выписку из другого банка: так мы увидим ваши доходы».
6. Кнопки — глаголы: «Отправить заявку», «Выбрать этот вариант», а не «Далее» и «ОК».
7. Проценты, деньги, даты: `1 500 000 ₽`, `21,5%`, `28 октября`. Месяц — «12 месяцев». Неразрывные пробелы в суммах.

## Словарь «не говорим / говорим»

| Не говорим | Говорим |
|---|---|
| Цель кредитования | На что нужны деньги |
| Пополнение оборотных средств | Закупить товар или сырьё |
| Кассовый разрыв | Временная нехватка денег |
| Срок кредита | За сколько хотите вернуть |
| Аннуитетный платёж | Платёж в месяц (равный каждый месяц) |
| Обеспечение | Залог или поручительство: гарантия для банка |
| Скоринг, грейд, PD, LGD | Не показываем клиенту вообще |
| DSCR, покрытие долга | «Платёж по силам вашему бизнесу» |
| Кредитный лимит | Сколько можно взять |
| Андеррайтер | Специалист банка |
| Верификация, KYC | Проверка данных |
| БКИ | Кредитная история (в скобках: «бюро кредитных историй») |
| Оферта | Предложение банка |
| Акцепт | Принять предложение |
| Транш, выборка | Получить деньги |
| Овердрафт | Короткий заём на несколько дней (подсказка с определением) |
| Стоп-фактор, флаг риска | Причина отказа / «Нужна проверка специалистом» |
| Отклонено | Не одобрено / «Сейчас одобрить не можем» |
| NEEDS_INFO, MANUAL_REVIEW… | Не показываем коды. Есть «Нужна ваша помощь», «Заявку смотрит специалист» |
| Синтетические данные (в интерфейсе без пояснения) | «Демо: данные придуманы» плюс пояснение при наведении |

## Шесть шагов таймлайна

Тексты для состояний «ждёт» · «идёт» · «готово». Источник шагов — [20-02](../20-process/02-application-states.md). Шаг «Нужна ваша помощь» вставляется между шагами 2 и 3, когда он нужен.

| Шаг | Идёт сейчас | Готово |
|---|---|---|
| 1. Заявка отправлена | «Заявка у нас. Сейчас начнём проверку» | «Заявка принята 21 октября, 12:04» |
| 2. Проверяем данные | «Проверяем данные компании и кредитную историю. Обычно до 1 минуты» + подшаги: «Данные из реестра ✓», «Налоги и отчётность ✓», «Кредитная история…», «Обороты по счёту…» | «Данные проверены» |
| ⏸ Нужна ваша помощь | «Специалист просит: {что}. Зачем: {зачем}. Срок: до {дата}» + кнопка «Ответить» | «Вы ответили 22 октября. Продолжаем проверку» |
| 3. Оцениваем | «Заявку смотрит специалист. Обычно до 1 рабочего дня. Ничего делать не нужно» | «Оценка завершена» |
| 4. Решение готово | Своя карточка на каждый исход (экраны 9–13, [60-03](03-client-screens.md)) | «Одобрено» / «Есть другие варианты» / «Не одобрено» |
| 5. Подписание | «Проверьте документы и подпишите. Подписать может руководитель» | «Договор подписан 22 октября» |
| 6. Деньги на счёте | «Зачисляем…» | «500 000 ₽ на счёте 4070…1234» |

Дополнительные состояния: «Заявка отозвана вами» · «Срок ответа истёк: заявка закрыта. Можно подать новую» · «Предложение действовало до 31 октября и закрыто».

Если источник данных недоступен (клиент не должен видеть слов «сбой» и «ошибка системы»): «Часть проверок идёт дольше обычного. Мы передали заявку специалисту — он завершит её вручную. Ничего делать не нужно».

## Тексты ошибок

Фронт берёт текст по `code` из ответа API ([50-07](../50-architecture/07-api-design.md)), а не из `detail`. Всегда есть мелкая строка «Код для поддержки: {requestId}».

| `code` | Текст клиенту | Кнопка |
|---|---|---|
| `UNAUTHENTICATED` | Сессия закончилась. Войдите снова | Войти |
| `ROLE_CANNOT_SIGN` | Подписать может только руководитель. Передайте ему заявку | Передать руководителю |
| `INN_INVALID` | В ИНН должно быть 10 цифр для компании или 12 для ИП. Проверьте номер | — |
| `NOT_FOUND` | Не нашли такую страницу или заявку | На главную |
| `VERSION_CONFLICT` | Заявку изменили в другой вкладке. Обновите, чтобы не потерять данные | Обновить |
| `DUPLICATE_APPLICATION` | У вас уже есть заявка в работе. Новую можно подать после решения по ней | Открыть заявку |
| `INVALID_TRANSITION` | Это действие сейчас недоступно: статус заявки изменился | Обновить |
| `CONSENT_REQUIRED` | Без согласия на запрос в кредитную историю мы не сможем проверить заявку | Вернуться к согласиям |
| `ROUND_ALREADY_SENT` | Ответы уже отправлены банку. Обновите страницу, чтобы увидеть, что дальше | Обновить |
| `ROUND_INCOMPLETE` | Ответьте на все задачи, потом отправляйте | Обновить |
| `TASK_CLOSED` | Эта задача уже закрыта: банк её снял или срок вышел. Обновите страницу | Обновить |
| `VALIDATION_ERROR` | Проверьте поля, отмеченные красным (рядом с полем — что именно не так) | — |
| `IDEMPOTENCY_IN_PROGRESS` | Секунду, предыдущее действие ещё выполняется | Повторится само |
| `RATE_LIMITED` | Слишком много попыток. Подождите минуту | — |
| `SERVICE_UNAVAILABLE` | Сервис временно недоступен. Ваши данные сохранены | Повторить |
| Неверный код входа | Код не подошёл. Осталось {N} попытки | Получить новый |
| Нет связи | Нет связи с сервером. Как только появится, продолжим | — |
| Файл не подходит | Этот файл не получилось прочитать. Нужна выписка в формате 1С (текстовый файл) | Выбрать другой |
| Неизвестная ошибка | Что-то пошло не так. Попробуйте ещё раз | Повторить |

## Пустые состояния

| Где | Текст |
|---|---|
| Главная, нет заявок | «Пока заявок нет. Расскажите, на что нужны деньги, а мы подберём продукт» · «Подобрать кредит» |
| Задачи | «Сейчас от вас ничего не требуется» |
| Мои кредиты | «Кредитов пока нет. После одобрения и подписи он появится здесь» |
| Уведомления | «Новых уведомлений нет» |
| Предодобрение, нет данных | «Предварительное предложение появится, когда у нас накопится история ваших операций» |
| Очередь банка | «Очередь пуста. Все заявки обработаны» |
| Продукт недоступен | «Овердрафт станет доступен после 6 месяцев обслуживания у нас» |

## Тон отказа

Структура ровно из трёх блоков:

1. **Итог одной фразой.** «Сейчас одобрить заявку не можем».
2. **Почему.** 1–3 причины простыми словами, каждая с цифрой. Формулировки берутся из 30-12; шаблон: «{что обнаружили} → {чем это важно}».
3. **Что можно сделать.** Конкретные шаги и срок («Погасите долг по налогам и подайте заявку снова. Это можно сделать сразу, ограничений по срокам нет»), а ещё ссылка на другой вариант, если он есть.

Пример-иллюстрация (не источник, цифры взяты из мока `romashka`):

> **Сейчас одобрить заявку не можем.**
> **Почему:** у компании есть задолженность по налогам — 1 150 000 ₽. Это больше 10% месячной выручки. Пока долг не погашен, кредит мы не выдаём.
> **Что можно сделать:** погасите задолженность и подайте заявку снова. Кредитную историю мы не запрашивали, поэтому она не пострадала.

Чего не пишем: «по результатам скоринга», «не соответствует политике банка», «вы нам не подходите», «обратитесь позже» без объяснения когда и зачем.

## Подсказки к терминам

Формат: слово с пунктирным подчёркиванием, по наведению и по клавише Tab — карточка из 1–2 предложений и примера. Не отдельная страница глоссария: объяснение рядом с тем местом, где термин встретился.

| Термин | Подсказка |
|---|---|
| Залог | «То, что вы отдаёте банку в гарантию: например, купленное оборудование. Если не сможете платить, банк может его продать. Пока платите — оно ваше» |
| Поручительство | «Человек (обычно владелец) обещает вернуть долг, если компания не сможет. Он тоже даёт согласие на проверку кредитной истории» |
| Ставка | «Сколько вы платите за пользование деньгами за год. 21% — это примерно 21 ₽ в год на каждые 100 ₽ долга. Итоговая ставка зависит от вашей компании» |
| Платёж | «Сколько платить каждый месяц. Он одинаковый: часть возвращает долг, часть — проценты» |
| Переплата | «Разница между тем, что вернёте, и тем, что взяли» |
| Срок | «За сколько месяцев вернёте. Чем дольше, тем меньше платёж и тем больше переплата» |
| Кредитная линия | «Банк открывает вам лимит: сумму, в пределах которой можно брать деньги, когда нужно. В этом прототипе мы показываем только лимит» (D-093) |
| Овердрафт | «Короткий заём на несколько дней, если не хватает денег на счёте. Гасится поступлениями. В этом прототипе виден только лимит» (D-093) |
| Предодобрено | «Банк заранее посчитал, сколько может дать. Окончательное решение — после заявки» |
| Кредитная история | «Сведения о ваших прошлых кредитах и платежах в бюро кредитных историй. Запрашиваем только с вашего согласия» |

## Демо-пометки

- Плашка в шапке всех зон: «Демо-прототип. Все данные синтетические» (D-085, [60-01](01-app-structure.md)).
- Код входа и подписи: «Демо: в реальном продукте код придёт SMS руководителю».
- На документах: «ДЕМО. Синтетический документ, юридической силы не имеет».
- Размещать пометки так, чтобы не пугать клиента: спокойный серый, одна строка.

## Как проверяем

- Юзабилити-тест (3–5 человек вне банковской сферы, D-009): ни один не просит объяснить слово из интерфейса.
- Проверка словаря: поиск по всем текстам на слова из левого столбца «Не говорим» в CI (простой скрипт-линтер).
- Каждый `code` из [50-07](../50-architecture/07-api-design.md) имеет запись в словаре (тест на полноту).

## Заметки для реализации

- Тексты — плоский словарь `ключ → строка с подстановками {сумма}`; никаких вшитых строк в компонентах (кроме подписей, которые видит только разработчик).
- Склонение чисел («1 месяц, 2 месяца, 5 месяцев») — одна функция в `lib/`, не ручные формы.
- Тексты кодов причин (клиентская и андеррайтерская версии) не дублировать здесь: фронт берёт их из ответа решения, которое строится по справочнику 30-12.
