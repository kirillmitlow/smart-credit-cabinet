## Зачем

Полный перечень экранов клиента: что на каждом есть, какие у него состояния и какие ручки он зовёт. По этому списку режем задачи реализации и пишем e2e-тесты. Тексты — в [60-06](06-ux-writing.md), путь целиком — в [10-09](../10-product/09-client-journey.md).

## Общие правила экранов

- Любой экран объясняет себя сам (D-064): заголовок «что это», одна главная кнопка, подсказка «что будет дальше».
- Три обязательных состояния у каждого экрана с данными: **загрузка** (скелетон), **пусто** (что это значит и что сделать), **ошибка блока** (повторить). Для экранов с источниками добавляется четвёртое: **источник недоступен** (поле «не подтверждено», ввод вручную).
- У каждого значения из внешнего источника есть значок «Откуда?» (источник, дата получения). Показывать всегда или только по значку — Q-087.
- Деньги и сроки — в виде «500 000 ₽ на 12 месяцев, платёж 46 000 ₽». Термины — с подсказкой ([60-06](06-ux-writing.md)).
- Минимальная ширина 1280 px; телефон не поддерживаем (D-063).

## 1. Вход

**Цель:** войти в кабинет компании без регистрации. **Способ (Q-035, вариант Б):** ИНН + одноразовый код. Быстрого входа карточками персон нет; ИНН жюри берёт из README. Андеррайтер входит отдельной кнопкой «Войти как андеррайтер» (при `DEMO_MODE`).

| Шаг | Что видит клиент | Что происходит |
|---|---|---|
| 1. ИНН | Одно поле «ИНН компании или ИП, 10 или 12 цифр», пояснение «Личный ИНН директора тоже подойдёт» | Проверка длины на лету. 10 цифр → компания. 12 цифр → ИП или личный ИНН |
| 2a. Компания (10 цифр) | Карточка «ООО «СтанкоПром», действует» и список сотрудников с доступом: «Кузнецов И. П., руководитель», «Белова О. Н., сотрудник по доверенности». «Войти как…» | Выбор пользователя из членов компании (D-014) |
| 2b. Личный ИНН (12 цифр) | «Вы руководитель ООО «…». Оформлять от имени компании?» (если компаний несколько — список). Если это ИП, «ИП Соколова. Войти?» (D-015) | Определение роли по ИНН |
| 2c. Самозанятый | Объяснение: «Бизнес-кредит оформляют ИП и компании. Что делать: …» и кнопка «Как стать ИП» (текст на странице, не уход из продукта). Исход `NOT_ELIGIBLE` | До кода не доходим |
| 3. Код | Кнопка «Получить код» → плашка «Код: **123456**. В реальном продукте он придёт SMS руководителю» (только при демо); поле на 6 цифр; осталось попыток и время | Ввод кода, 3 попытки, 5 минут (как у подписи, 50-09) |
| 4. Кабинет | Если у пользователя больше одной компании — «Выбор компании», иначе главная | Сессия создана |

- **Состояния:** ИНН не найден («Не нашли такую компанию»), компания не действует (`COMPANY_NOT_ACTIVE`: можно войти и смотреть, но подать заявку нельзя; на первом шаге заявки объяснение), неверный код (остаток попыток), код истёк («Получить новый»), слишком много попыток (`RATE_LIMITED`, «Подождите минуту»), реестр недоступен («Не получилось проверить ИНН, повторить»).
- **Ручки:** `GET /companies/lookup/{inn}`; для личного ИНН — роли по ИНН (ручка добавляется, см. 60-01); запрос и подтверждение кода (ручки добавляются); `GET /me`; `GET /public-config`.
- **Персоны:** все с учёткой (девять основных); `orlov` — шаг 2c; `vektor` — вход есть, подача нет; `stankoprom` — два пользователя.
- **Что не зависит от способа входа:** всё после шага 4. Блок лежит в `features/auth`.

## 2. Выбор компании

**Цель:** выбрать, от чьего имени работаем (один человек может быть в нескольких компаниях). **Элементы:** карточки компаний (название, ИНН, роль), «Сменить компанию» потом всегда в шапке. **Состояния:** пусто невозможно (минимум одна); ошибка — повтор. **Ручки:** `GET /me`. **Персоны:** директор с несколькими компаниями (если будет такой в сценарии; по умолчанию экран пропускается).

## 3. Главная

**Цель:** за 5 секунд понять, что нужно сделать. **Элементы сверху вниз:**

1. **«Что нужно от вас»**: список задач (запросы банка, подпись, ответ на встречное предложение). Крупно, первым.
2. **Предодобренное предложение** (клиенты банка, D-018): «Вам доступно до 1 200 000 ₽ без заявки» и кнопка «Оформить». Для не клиента блока нет.
3. **Мои заявки**: карточки со статусом одним шагом таймлайна и кнопкой «Открыть».
4. **Мои кредиты**: сумма, ближайший платёж.
5. Большая кнопка «Нужны деньги» → мастер.

- **Состояния:** новая компания без заявок («Пока заявок нет. Начните с подбора» + кнопка), загрузка, источник недоступен (блок предодобрения «Сейчас не получилось посчитать», остальное работает).
- **Ручки:** `GET /applications`, `GET /applications/{id}/tasks`, `GET /companies/{id}/preapproved-offer` (Should), `GET /loans`, `GET /notifications`.
- **Персоны:** `sokolova` (предодобрение, после выдачи кредит), `stankoprom` и `garipov` (задачи), `snabkontrakt` (встречное ждёт выбора).

## 4. Мастер подбора

**Цель:** от «зачем деньги» к продукту без банковских слов ([10-07](../10-product/07-need-wizard.md)). **Элементы:** вверху поле «Опишите своими словами» (D-060; если модель не включена, поля нет), под ним один вопрос на экран крупными карточками, «Не знаю», «Назад», прогресс «Шаг 2 из 5». Заполненное по тексту показывается как выбранные карточки с пометкой «Заполнено по вашему описанию — проверьте». Сумма — поле числа.
**Состояния:** разбор текста идёт («Разбираем описание…», до 2 с, потом кнопки); модель не уверена — задаёт кнопками; текст не разобрался — не ошибка, а «Давайте ответим кнопками». **Ручки:** `POST /wizard/parse-text` (Should), `POST /wizard/recommendations`. **Персоны:** все, кроме технических; для `stankoprom` ветка «оборудование > 3 млн», для `snabkontrakt` — «заказ с оплатой позже».

## 5. Результат подбора

**Цель:** показать один основной продукт и одну альтернативу. **Элементы:** две карточки (название на языке клиента, «почему подходит вам» одной фразой, примерный платёж, срок решения «за минуты» / «1–2 дня», какие документы понадобятся), «Изменить ответы», «Посмотреть весь каталог». **Состояния:** подходящего нет → «Что станет доступно и когда» (не тупик); продукт недоступен по требованиям — карточка с причиной. **Ручки:** `POST /wizard/recommendations`, `POST /calculator/payment`. **Персоны:** `quick-start` (путь «На запуск»), `garipov` (экспресс).

## 6. Каталог и калькулятор

**Цель:** посмотреть все шесть продуктов и посчитать платёж. **Элементы:** сетка карточек, у карточки «для чего», сумма, срок, залог, «кому доступно». Калькулятор: два ползунка (сумма, срок) и результат «платёж / переплата / ставка от…». Над ставкой пометка «ориентировочно, итоговую ставку покажем после проверки». **Состояния:** продукт недоступен компании (серая карточка + «станет доступен после 6 месяцев обслуживания»), загрузка. **Ручки:** `GET /products`, `GET /products/{code}`, `POST /calculator/payment`. **Персоны:** все.

## 7. Заявка по шагам

**Цель:** подать заявку, ничего не вводя дважды. Пять шагов, шаг в адресе, «Сохранено в 12:04» (автосохранение).

| Шаг | Содержимое |
|---|---|
| 1. Условия | Продукт, сумма, срок: из мастера, можно править; платёж пересчитывается сразу |
| 2. Данные компании | Автозаполнение по ИНН: у каждого поля «Откуда?»; клиент проверяет и дополняет то, чего мы не знаем. Недоступный источник → «не подтверждено», ввод вручную |
| 3. Что нужно для продукта | По продукту: контракт из списка (`CONTRACT`), залог (`INVESTMENT`, «то, что покупаю»), для молодого бизнеса — поручитель. Лишнего не спрашиваем |
| 4. Согласия | Отдельно: запрос в БКИ, обороты по счёту, обработка данных. Кратко и понятно, что берём и зачем |
| 5. Проверьте и отправьте | Сводка, кнопка «Отправить». Бухгалтер может отправить, но подписывает позже руководитель |

- **Состояния:** конфликт версий (`VERSION_CONFLICT`), уже есть заявка в работе (`DUPLICATE_APPLICATION`: «У вас уже есть заявка, откройте её»), не подтверждены согласия (кнопка недоступна с пояснением), нет сети.
- **Ручки:** `POST /applications`, `PATCH /applications/{id}/draft`, `POST …/consents`, `POST …/collaterals`, `GET /companies/lookup/{inn}`, `GET /companies/{id}/gov-contracts`, `POST …/submit`.
- **Персоны:** `snabkontrakt` (потом выбор контракта), `stankoprom` (залог и два пользователя), `quick-start` (поручитель).

## 8. Страница заявки с таймлайном

**Цель:** всегда видно, на каком этапе заявка, что будет дальше и что нужно от клиента. Это главный экран продукта. **Элементы:** вверху номер и сводка («500 000 ₽, 12 месяцев»); слева вертикальный таймлайн из 6 шагов (тексты — [60-06](06-ux-writing.md)); внутри шага «Проверяем данные» видны подшаги (реестр, налоговая, кредитная история) с галочками по мере выполнения; справа блок **исхода** по статусу (экраны 9–13); внизу «Отозвать заявку» (до подписания). Подпись «обновляется автоматически» (SSE). Шаги идут сами, перезагрузка не нужна (RQ-05).
**Состояния:** конвейер идёт (подшаги движутся, «Обычно до 1 минуты»), источник недоступен (нейтральное «Часть проверок затянулась, передали специалисту», 20-01), заявка отозвана или истекла (конечное состояние с пояснением), связь потеряна (50-11). **Ручки:** `GET /applications/{id}`, `GET …/timeline`, `GET …/decision`, `GET …/tasks`, `POST …/withdraw`, события SSE. **Персоны:** все.

## 9–13. Экраны исходов

Блоки внутри страницы заявки ([60-01](01-app-structure.md)). Клиент видит причины простым языком; баллы и внутренности банка — никогда (50-07). Тексты кодов — [30-12](../30-decisioning/).

| Исход | Что на экране | Кнопки | Персоны |
|---|---|---|---|
| **9. Одобрено** (`APPROVED`) | «Одобрено на запрошенных условиях»; сумма, срок, платёж, ставка с разбивкой «из чего складывается»; срок действия предложения; что будет дальше | «Принять и перейти к подписанию», «Отказаться» | `sokolova`, после ручного — `stankoprom`, `zarya` |
| **10. Три карточки** (`COUNTER_OFFER`) | «Так, как вы просили, не получится. Вот что мы можем». До трёх карточек: «Ваша сумма, дольше срок», «Ваш срок, меньше сумма», «Другой продукт или с залогом». Метка «Рекомендуем»; у карточки сумма, срок, платёж, переплата, ставка, «что нужно от вас», «почему» одной фразой. Рядом блок «Как получить то, что просили» (D-072). Для молодого бизнеса — «С поручительством владельца» (D-077) | «Выбрать это», «Отказаться»; в блоке «как получить» — «Добавить залог / подтвердить выручку» (возврат в проверку) | `snabkontrakt` (три карточки, `DSCR_LOW`), `quick-start` (поручительство) |
| **11. Нужна информация** (`NEEDS_INFO`) | Крупно: «Специалист просит: … Зачем: … Срок: до 28 октября». Для выписки — зона «Перетащите файл 1С» и, **только в демо**, кнопка «Сгенерировать тестовую выписку». После загрузки — «Файл получен, читаем» и возвращение в таймлайн | «Отправить», «Сделать позже» | `garipov` (выписка), `stankoprom` (договор с поставщиком) |
| **12. Ручное рассмотрение** (`MANUAL_REVIEW`) | «Заявку смотрит специалист. Обычно до 1 рабочего дня». Что уже проверено, что ещё ждём, «Ничего делать не нужно» (или «Можете загрузить договор заранее») | «Отозвать» | `stankoprom`, `zarya`, после встречного — `quick-start` |
| **13. Отказ** (`REJECTED`) | Спокойный тон: «Сейчас одобрить не можем». Причины (1–3, простыми словами), «Что можно сделать» (шаги, а не «обратитесь позже»), «Когда можно подать снова» | «Подобрать другой вариант», «Понятно» | `romashka` (налоговый долг, до БКИ), `vektor` (`COMPANY_NOT_ACTIVE`), технические |

**Согласие поручителя (D-082).** Если выбрано поручительство, поручителем может быть только директор или учредитель, пользователь кабинета. Если это сам текущий пользователь, он подписывает согласие на БКИ и поручительство сразу. Если другой, у него в «Что нужно от вас» появляется задача, и после входа по своему ИНН он подписывает сам. До этого заявка в статусе «ждём согласие поручителя». **Состояния:** срок предложения истёк (`EXPIRED`), нет подходящего поручителя («Поручителем может быть директор или учредитель компании»).

## 14. Подписание

**Цель:** проверить документы и подписать. **Элементы:** договор (просмотр с водяным знаком «ДЕМО. Синтетический документ»), график платежей, «Что вы подписываете» тремя строками, кнопка «Подписать». Для бухгалтера вместо неё «Передать руководителю на подпись» (D-014): создаётся задача руководителю. Для руководителя после нажатия — плашка с кодом «Демо: в реальном продукте код пришёл бы по SMS», поле кода, подтверждение. После подписи: «Выдача» с шагами «Открываем счёт» (если нет) → «Зачисляем» → «500 000 ₽ на счёте 4070…». **Состояния:** неверный код, `ROLE_CANNOT_SIGN`, выдача в обработке (АБС временно недоступна, «Деньги будут зачислены, повтор безопасен»), предложение истекло. **Ручки:** `POST /offers/{id}/accept`, `GET /contracts/{id}`, `GET …/document`, `POST …/request-signature`, `POST …/sign`. **Персоны:** `sokolova`, `garipov` (открытие счёта), `stankoprom` (Белова готовит, Кузнецов подписывает).

## 15. Мои кредиты и график

**Цель:** видеть, что получено и сколько платить. **Элементы:** список кредитов (продукт, сумма, остаток, ближайший платёж); страница кредита: условия, график платежей (дата, платёж, долг, проценты, остаток), «Скачать договор». Платежи и просрочки не моделируются (20-01): надпись «Оплата в этом прототипе не моделируется». **Состояния:** пусто («Кредитов пока нет»), загрузка. **Ручки:** `GET /loans`, `GET /loans/{id}`, `GET /loans/{id}/schedule`. **Персоны:** `sokolova`, `garipov` после выдачи; клиенты банка с кредитами (`snabkontrakt`).

## 16. Уведомления

**Цель:** ничего не пропустить внутри продукта (D-020, без почты и SMS). **Элементы:** колокольчик со счётчиком в шапке, выпадающий список последних, страница всех. Уведомление: «Нужна ваша помощь по заявке № 2026-0007» и ведёт на заявку. Появляются сразу по SSE (`task_created`); о задаче и о решении дополнительно выскакивает тост (20-06). **Состояния:** пусто («Новых уведомлений нет»). **Ручки:** `GET /notifications`, `POST /notifications/{id}/read`. **Персоны:** все с ручным шагом.

## Развилки для пользователя

**Q-087. Как показывать источник и дату каждого автозаполненного поля?** Нужно из кейса («сокращение повторного ввода» и прозрачность), но шум в форме мешает.

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Всегда рядом с полем мелкой серой строкой: «ЕГРЮЛ, 20.10.2026» | Всё видно сразу, хорошо смотрится жюри | Форма пестрит |
| Б. **Значок «Откуда?» у поля, по нажатию подсказка с источником и датой; сверху шага сводка «Из реестра и налоговой: 14 полей. Проверьте»** | Чисто; источник доступен в один клик; сводка показывает пользу | Нужен лишний клик |
| В. Только в конце на странице проверки | Минимум шума | Источник не виден при вводе |

**Рекомендация: Б.**

## Заметки для реализации
