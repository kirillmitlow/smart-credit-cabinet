## Зачем

Признак — число или категория, которую ядро считает из снимка данных (шаг 6 в 30-01). Здесь для каждого: что значит, как считается, откуда берётся и что делать, если данных нет. Скоринг (30-07), лимиты и флаги берут признаки только отсюда.

## Общие правила

- Признаки считает только `decisioning`, из снимка. Дата «сегодня» — `APP_TODAY`. «Месяцы» — полные календарные месяцы.
- Каждый признак несёт **источник и качество**: `OWN_BANK` (наш банк), `OFFICIAL` (ФНС, реестр, БКИ), `CLIENT_UPLOAD` (выписка клиента), `ESTIMATE` (модель). Андеррайтер видит это рядом с числом.
- Нет данных ≠ ноль. Правило «нет данных» указано у каждого признака; общего «подставим среднее» нет.
- Пороги и коэффициенты лежат в конфиге (30-13), здесь указаны значения версии `v1` и источник.

## Выручка и поток (D-069, D-039)

**Приоритет источника выручки:** обороты нашего банка (если есть ≥ 6 месяцев или нет лучшего) → отчётность ГИР БО (свежая: год отчёта не старше 18 мес. на дату заявки) → выписка клиента → иначе `NEEDS_INFO` (`REVENUE_UNKNOWN`).

| Признак | Смысл и формула словами | Источник | Нет данных |
|---|---|---|---|
| `vat_rate(m)` | Ставка НДС месяца: до 31.12.2025 — 20%, с 01.01.2026 — 22% (30-18 №7). Применяется **только при режиме ОСНО**; УСН с НДС 5/7% в `v1` не моделируем | `tax-profile`, конфиг | Режим неизвестен → 0 |
| `turnover_net_series` | Помесячные чистые поступления **без НДС**: `incomingNetRub(m) / (1 + vat_rate(m))` | АБС `turnover` (до 24 мес.) → разобранная выписка | Ряда нет → пусто |
| `revenue_cautious_rub` | **Осторожная выручка в месяц.** Обычный бизнес: минимум из среднего за последние 12 и за последние 6 месяцев ряда. Сезонный: сумма за 12 мес. / 12. Если месяцев < 6: среднее по имеющимся × **0,7** (допущение 30-03: короткая история — осторожнее). Если источник — отчётность: строка 2110 последнего года / 12 | Приоритет выше | Ни одного источника → `REVENUE_UNKNOWN` |
| `revenue_annual_rub` | `revenue_cautious_rub × 12` | — | — |
| `is_seasonal` | Есть ≥ 24 мес.: корреляция первых и вторых 12 месяцев ≥ 0,7 **и** коэффициент вариации ≥ 0,35. Меньше 24 мес.: да для ОКВЭД 01–03 | Ряд, ОКВЭД | Нет → `false` |
| `flow_model_rub` | **Свободный поток в месяц.** Есть свежая отчётность: `(чистая прибыль 2400 + проценты 2330) / 12`, умноженное на `min(1, выручка_осторожная / (2110 / 12))`: не даём кредит под прошлогоднюю прибыль, если выручка упала. Иначе `revenue_cautious_rub × маржа отрасли`. Отрицательный поток = 0 | ГИР БО; конфиг | Нет выручки → `REVENUE_UNKNOWN` |
| `flow_observed_rub` | Поток «по счёту»: `(поступления − списания) + текущие платежи по кредитам`, среднее за 12 мес. Только для сверки | АБС, выписка | `null` |
| `flow_crosscheck_ratio` | `flow_observed / flow_model`. Значение < 0,5 — повод для `DATA_MISMATCH` (30-04) | — | `null`, проверка пропускается |
| `existing_payments_rub` | Ежемесячные платежи по долгам: `monthlyPaymentsRub` БКИ заёмщика + наши кредиты из АБС, которых ещё нет в БКИ. Один кредит не считается дважды: сравниваем `contractUid` (АБС) и `uid` (БКИ). Лимиты и карты уже включены (5% от использованного) | БКИ, АБС | БКИ нет (preview) → только АБС |
| `total_debt_rub` | `totalDebtRub` БКИ + наши кредиты вне БКИ + **50%** условных обязательств (`contingentLiabilitiesRub`: гарантии и поручительства; допущение, по Базелю коэффициент пересчёта 50–100%) | БКИ, АБС | как выше |
| `debt_to_revenue` | `total_debt / revenue_annual` | — | Нет БКИ (preview) → «неизвестно», в скоринге осторожное значение |
| `coverage_existing` | `flow_model / existing_payments`. Нет платежей → «без платежей» | — | — |
| `revenue_trend_pct` | Годовой тренд, %. Метод Тейла–Сена: медиана наклонов по всем парам точек ряда (до 24 мес.), `12 × наклон / медиана ряда`. Нет ряда, но есть два года отчётности: `2110 / предыдущий − 1` | Ряд, ГИР БО | < 6 точек и нет отчётности → `null` |
| `revenue_cv` | Коэффициент вариации: стандартное отклонение / среднее, последние 12 мес. ряда | Ряд | < 6 точек → `null` |
| `stress_shock` | Шок стресс-теста: `max(0,20; min(0,40; revenue_cv))`. Сезонным и при `null` — 0,20 | — | 0,20 |
| `bad_months` | Месяцев за последние 12 с выручкой < 50% медианы. Информация андеррайтеру и симулятору | Ряд | `null` |

**Маржа отрасли** (D-038, 30-18 №5). Группа определяется по первым двум цифрам главного ОКВЭД:

| Группа | ОКВЭД | Маржа |
|---|---|---|
| `TRADE` | 45–47 | 5% |
| `FOOD` | 55, 56 | 10% |
| `MANUFACTURING` | 10–33, 41–43 (строительства в статистике нет — допущение) | 12% |
| `IT` | 62, 63 | 15% |
| `AGRO` | 01–03 | 15% |
| `SERVICES` | всё остальное (96, 49–53, 68–82, 85–88…) | 13% |

## Кредитная история (БКИ)

Считается **по каждому субъекту отдельно**: `company` (или ИП как человек), `director` (только ООО), `guarantor` (если есть). Названия: `bki_company_*`, `bki_director_*`, `bki_guarantor_*`.

| Признак | Смысл | Нет данных |
|---|---|---|
| `has_history`, `history_months`, `obligations_count` | Есть ли история, её длина, число обязательств (активных и закрытых) | `NOT_FOUND` → `has_history = false` |
| `overdue_now_days`, `overdue_now_rub` | Текущая просрочка: дни и сумма. Учитывается при сумме ≥ 10 000 ₽ (допущение: ниже — техническая просрочка, по аналогии с порогами существенности Базеля CRE36.69) | `0` |
| `overdue_max_24m_days`, `restructurings_24m` | Худшая просрочка и число реструктуризаций за 24 мес. | `0` |
| `inquiries_30d`, `rejected_90d` | Только `...ExcludingOwn`: наши запросы и отказы не считаются (6.1 моков) | `0` |
| `bankruptcies` | Дела из отчёта БКИ (сверка с ЕФРСБ) | пусто |
| `credit_history_class` | **Итог по всем субъектам: худший класс**: `CLEAN` · `THIN_CLEAN` · `NO_HISTORY` · `MINOR` · `PAST_30` · `PAST_60` · `CURRENT_30_89` · `PAST_90`. Если у компании истории нет, класс не выше `THIN_CLEAN` (молодая компания живёт на истории владельца) | Все `NOT_FOUND` → `NO_HISTORY` |

`bureauScore` бюро показываем андеррайтеру, в решении не используем (моки, 6.1).

## Сверка и антифрод (D-076)

Правила только ставят флаг (D-034). Пороги — допущения, проверяются тестами на специально собранных рядах; источники методов указаны.

| Признак | Формула словами | Порог `v1` | Источник порога | Нужны данные |
|---|---|---|---|---|
| `mismatch_turnover_fin` | `\|A − B\| / B`, где A — сумма `turnover_net_series` за календарный год, целиком попавший в окно оборотов, B — строка 2110 за тот же год | > **30%** → `DATA_MISMATCH` | D-035 (знаменатель — отчётность, чтобы +40% и −40% ловились одинаково) | Обороты и отчётность |
| `mismatch_declared` | Заявленная клиентом выручка в месяц против `revenue_cautious_rub`, знаменатель — расчётная | > 30% → `DATA_MISMATCH` | D-035 | Заявленная выручка |
| `mismatch_statement` | Выписка клиента против отчётности за общий год, как в первой строке | > 30% | D-035 | Выписка и отчётность |
| `flow_crosscheck_ratio` | См. выше | < 0,5 → `DATA_MISMATCH` | Допущение: 2Б шумнее выручки (30-03), поэтому порог мягче | Обороты |
| `pump_ratio`, `pump_modz` | **Накачка:** `x` — среднее последних 3 мес. ряда; `b` — медиана 9 мес. до них. `ratio = x / b`; модифицированный z-балл `0,6745 × (x − b) / MAD` (если MAD = 0, берём 5% от `b`) | `ratio` ≥ **1,6** **и** z ≥ **3,5**; не срабатывает, если ряд ≥ 24 мес. и те же 3 мес. годом ранее дают `x / x_год_назад` ≥ 1,3 (сезонное повторение) | z ≥ 3,5: Iglewicz, Hoaglin (1993); 1,6 — допущение | ≥ 12 мес. оборотов |
| `transit_months` | Число месяцев из последних 12, где `outgoingRub / incomingNetRub` ≥ 0,985 | ≥ **9** → `TURNOVER_ANOMALY` | Допущение. У торговли с маржой 5% и НДС доля списаний ≈ 0,96, ложных срабатываний нет | ≥ 12 мес. |
| `payers_in_6m_max`, `payers_in_6m_avg_income` | Максимум `counterpartiesIn` за последние 6 мес. и средние `incomingNetRub` | максимум ≤ **2** и средние поступления ≥ **3 млн ₽/мес**. Не применяется для ОКВЭД 47, 55, 56, 96: там деньги идут через эквайринг и СБП (10.3 моков) | Допущение: «мало плательщиков при крупной выручке» | ≥ 6 мес. |

Правила накачки, транзита и одного плательщика применяются к оборотам нашего банка. Выписка клиента даёт помесячные суммы, но не число контрагентов: на ней работают первые два правила.

## Границы

- **Входит:** определения признаков, источник, нехватка данных.
- **Не входит:** баллы (30-07), пороги стоп-факторов (30-04), формулы платежа и лимитов (30-08, 30-16).

## Как проверяем

- Unit-тест на каждый признак: типичный случай, граница, «нет данных». Для выручки — таблица из 30-03 (Соколова, СнабКонтракт, Гарипов).
- Тесты антифрода на собранных рядах: накачка (срабатывает; не срабатывает на сезонной «Заре»), транзит, один плательщик (не срабатывает на кофейне Соколовой: ОКВЭД 56).
- Property-тест: `revenue_cautious_rub` ≤ среднего за 12 мес.; добавление НДС не меняет выручку.

## Открытые вопросы

Нет. Пороги антифрода уточняются на синтетическом портфеле (30-14), это правка конфига, не документа.

## Заметки для реализации

- НДС делим по **дате месяца**, не по дате заявки: ряд на 24 месяца пересекает 2025/2026.
- Нормализация ФИО — отдельная чистая функция с таблицей тестов (ё/е, «Иванов И. И.», лишние пробелы).
- Сумма по календарному году для сверки берётся только если все 12 месяцев года есть в окне оборотов.
- `contractUid = uid` — единственный способ не посчитать наш кредит дважды; тест: кредит в обеих системах считается один раз.
