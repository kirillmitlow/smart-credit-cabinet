Один документ — одна вещь: **какие проверки качества скоркарты входят в отчёт, по каким порогам они «зелёные / жёлтые / красные» и как отчёт строится в CI**. Требование кейса: банковские модели проверяются по различающей способности, точности и стабильности (стр. 14 кейса, RQ-67). Саму скоркарту описывает 30-05 / 30-07, данные даёт имитатор 30-19.

## 1. Честная оговорка (идёт в начало каждого отчёта и в README)

> Портфель синтетический: дефолты порождены нашей моделью денежного потока (30-19), а не реальными заёмщиками. Отчёт показывает **механику и процесс проверки**, а не реальную предсказательную силу. Высокий Gini на синтетике ничего не доказывает про реальные данные. Если Gini окажется выше 0,80, отчёт считает это подозрительным (утечка в данных), а не успехом.

| Тема | Что берём | Источник |

Формулы из статьи в этой сессии не сверялись, берём стандартные |

## 3. Метрики и пороги

Выборки: **разработка** (на ней подобраны баллы и PD грейдов) и **контроль** (другой seed имитатора, те же правила). Метрики считаются на контрольной. Целевой признак: дефолт в течение 12 месяцев после выдачи (30-19, определение дефолта — 90+ дней, D-075). Популяция: заявки, прошедшие стоп-факторы (то есть «входящий поток»), а также отдельно одобренные.

### 3.1. Различающая способность

| Метрика | Формула и смысл | Зелёный | Жёлтый | Красный |
|---|---|---|---|---|
| AUC | Вероятность, что случайный «хороший» получил балл выше случайного «плохого» (рангово, ничьи пополам) | ≥ 0,70 | 0,625–0,70 | < 0,625 |
| **Gini** | `2·AUC − 1` (в терминах ЦБ — коэффициент точности AR) | **≥ 0,40** | 0,25–0,40 | < 0,25 |
| **KS** | `max |F_плохих(s) − F_хороших(s)|` по баллам | ≥ 0,30 | 0,20–0,30 | < 0,20 |
| Доверительный интервал Gini | Бутстреп 200 перевыборок, 2,5–97,5% | ширина ≤ 0,05 | 0,05–0,10 | > 0,10 (мало данных) |
| Подозрительно высокий | Gini > 0,80 | — | жёлтый «проверить утечку» | — |

Обоснование порогов (📝): для скоркарт малого бизнеса Gini 0,3–0,6 считается нормой практики, ниже 0,2–0,25 — слабая. Прототип имитатора (21.10): экспертная карта на 7 факторах без DSCR даёт Gini около 0,30, KS 0,22 (жёлтая зона), логистический пересчёт на тех же данных — около 0,48 (зелёная). Это ориентир, реальные значения покажет отчёт. Дополнительно отчёт показывает Gini по каждому фактору в отдельности, чтобы было видно, что тянет карту.

### 3.2. Калибровка

| Метрика | Как считаем | Что значит |
|---|---|---|
| Таблица по грейдам A–E | Число заявок, число дефолтов, доля дефолтов `DR`, **заложенная PD грейда** (конфиг 30-07; до его утверждения — доля дефолтов на выборке разработки) | Факт против прогноза |
| **Биномиальный тест с поправкой на корреляцию** (по каждому грейду) | Верхняя граница `DR*` = `Φ( (Φ⁻¹(PD) + √ρ · Φ⁻¹(0,95)) / √(1−ρ) )`, `ρ = 0,12`. `DR > DR*` — красный; `DR` выше PD, но ниже `DR*` — жёлтый; `DR` ниже `Φ`-нижней границы (симметрично, 5%) — жёлтый «PD завышена» | Обычный биномиальный тест на синтетике слишком строг: дефолты в имитаторе коррелированы через общий макрофактор |
| Простой биномиальный p-value | Только для справки | Показываем рядом, в красный не идёт |
| **Brier** | `BS = среднее (PD_i − y_i)²` и `BSS = 1 − BS / (d̄(1−d̄))`, `d̄` — средняя доля дефолтов | `BSS > 0`: карта лучше, чем «всем одну PD». Красный при `BSS ≤ 0` |
| Хосмер–Лемешоу | χ² по группам (грейды) с `G − 2` степенями свободы | Информационный: на больших выборках отвергает почти всегда. В красный не идёт |
| Монотонность | `DR` не убывает от A к E (допуск 0,5 п.п.) | Нарушение — красный |

Пример (прототип 21.10, карта из 5 грейдов по квантилям, контроль 49 тыс. заявок): PD A–E 3,5 / 5,9 / 10,1 / 11,0 / 17,7%, факт 3,5 / 5,9 / 9,6 / 10,8 / 17,7%, `BS = 0,0631` против эталона 0,0644. Грейды различаются слабо: это жёлтый сигнал для экспертной карты.

### 3.3. Стабильность

| Метрика | Формула | Зелёный | Жёлтый | Красный |
|---|---|---|---|---|
| **PSI по баллу** | `Σ (a_i − e_i) · ln(a_i / e_i)`, `e_i` — доли по 10 равным по численности корзинам выборки разработки, `a_i` — доли в контроле; пустые корзины заменяем на 0,0001 | **< 0,10** | **0,10–0,25** | **> 0,25** |
| PSI по каждому фактору (CSI) | То же по интервалам фактора | < 0,10 | 0,10–0,25 | > 0,25 |
| Сдвиг по времени | PSI «первые 6 мес. против последних 6» внутри контрольного периода | то же | то же | то же |

Пороги 0,10 / 0,25 — общепринятые в практике. Прототип: два независимых прогона одной экономики дали PSI по баллу 0,002; по факторам «тренд выручки» 0,02, «волатильность» 0,0004. Чтобы красный PSI вообще проверялся, в CI есть **тест на тест**: искусственно сдвинутый портфель (выручка −15%, больше просрочек) обязан дать PSI > 0,25, иначе сломан сам отчёт.

### 3.4. Концентрация, одобрения, переопределения

| Метрика | Как считаем | Зелёный | Жёлтый | Красный |
|---|---|---|---|---|
| Доли грейдов | Доля каждого грейда среди одобрений и среди заявок | Любой грейд ≤ 50% | > 50% | > 70% |
| Индекс Херфиндаля `HHI = Σ s²` по грейдам | Концентрация | ≤ 0,35 | 0,35–0,50 | > 0,50 |
| Грейд A | Доля A в портфеле. Для PD 1 / 3 / 7% (30-18, п. 7 «Расхождения») A должен быть не больше трети | ≤ 33% | 33–50% | > 50% |
| **Доля одобрений** | `APPROVED / все решения`, по продуктам и грейдам | 50–80% | вне коридора | < 20% или > 95% |
| **Доля переопределений** | Решения андеррайтера против рекомендации ядра с причиной (D-010) / все решения | ≤ 10% | 10–20% | > 20% |
| Переопределения «вверх» | Одобрено там, где ядро советовало отказ или ручное | ≤ 5% | 5–10% | > 10% |

Пороги концентрации, одобрений и переопределений — 📝 допущения (в практике нет единых), коридор одобрений взят из прототипа (67% при DSCR ≥ 1,25 и грейде не ниже C). **Переопределений в синтетическом портфеле нет:** их производит живой процесс (андеррайтер в продукте), поэтому в CI-отчёте раздел отмечен «н/д, источник — таблица решений приложения», а на стенде с данными демо считается по реальным событиям.

### 3.5. Проверка правил (дополнительно, Should)

| Проверка | Смысл | Ожидание |
|---|---|---|
| Доля дефолтов по корзинам DSCR (<1,0; 1,0–1,25; 1,25–1,6; 1,6–2,5; >2,5) | Доказывает, что порог DSCR 1,25 разделяет заёмщиков | Монотонное убывание. В прототипе: 16,4 → 8,8 → 4,3 → 1,8% |
| Одобренные против входящего потока | Работает ли отбор | Доля дефолтов одобренных ниже, чем у входящего потока. Прототип: около 3,6% против 6–7% |
| Вероятностный стресс-тест (30-19): прогноз против факта | Проверка калибровки `P(дефолт 12 мес.)` по корзинам | Факт в каждой корзине рядом с прогнозом (прототип: 0,6→0,9%, 3,8→4,4%, 9,5→8,3%) |

## 4. Как отчёт строится в CI

1. Задача `make validation-report` (имя условное): имитатор (30-19) с зафиксированным seed строит два портфеля — разработка и контроль (по умолчанию 20 000 и 20 000 заявок) плюс сдвинутый портфель для теста на тест.
2. Скоркарта и PD грейдов берутся из текущего `policy/*.yaml` (30-13). Решение по каждой заявке принимает **то же ядро**, что в продукте, а не копия логики.
3. Считаются метрики разделов 3.1–3.5, светофоры, сравнение с предыдущим отчётом из репозитория (падение Gini более чем на 0,05 — жёлтый).
4. Артефакты в CI: `validation-<версия правил>.md` (читает человек), `validation-<версия правил>.json` (читает машина и страница), картинки `*.png` (ROC, кривая KS, PD по грейдам, PSI).
5. **Что ломает сборку:** красный в различающей способности, калибровке или монотонности; провал «теста на тест». Жёлтое — предупреждение в логе. Бюджет времени: до 60 секунд на 40 000 заявок (оценка по прототипу: генерация 40 тыс. заявок на чистом Python 5–10 с).
6. Запуск: на каждый PR, меняющий `policy/`, скоркарту или имитатор, и по ночам; полный отчёт приложен к сдаче.

## 5. Как отчёт выглядит

- **Основной формат: Markdown-отчёт** (в репозитории и как артефакт CI): читается без запуска продукта, подходит для README и для жюри.
- **Страница в продукте** («Качество модели», зона андеррайтера, D-010) — Could: рисует тот же JSON (светофоры, таблица грейдов, графики), без пересчёта. Данные там помечены «синтетический портфель».
- Порядок разделов отчёта: оговорка (1) → итоговая таблица светофоров (одна строка на метрику) → различающая способность → калибровка → стабильность → концентрация и одобрения → проверка правил → паспорт запуска (версия правил, версия имитатора, seed, числа заявок, дата, хеш конфига).

## Допущения и противоречия

- Пороги Gini, KS, концентрации и переопределений — допущения (в публичных источниках единых значений нет); PSI 0,10 / 0,25 — стандарт практики; методы — Базель WP14 и логика 483-П.
- Целевая доля дефолтов 6% (коридор 4–10%) — из 30-18 и D-079; для **одобренного** портфеля PD ниже (прототип 3,6%), поэтому PD грейдов 1 / 3 / 7% из 30-09 надо сверить с таблицей калибровки после выбора карты (30-07): в прототипе PD грейдов получились 3,5–17,7%, то есть **числа 1 / 3 / 7% — предположения, а не результат имитатора**. Решение: PD грейдов берутся из калибровки, 30-09 пересчитывается.
- Кейс упоминает «точность»: понимаем как калибровку (раздел 3.2).

## Заметки для реализации

- Метрики — чистые функции над двумя массивами (балл, дефолт) и таблицей грейдов; светофоры и пороги — в конфиге отчёта, не в коде; `Φ`, `Φ⁻¹` — из стандартной библиотеки (`statistics.NormalDist`).
- Тесты: AUC и KS против малого ручного примера; Gini = 1 для идеального и 0 для случайного баллов; PSI одинаковых выборок = 0; Brier и BSS на известном примере; «тест на тест»; воспроизводимость отчёта по seed (байт в байт, кроме даты).
- Бутстреп детерминированный (свой seed). Ничьи в AUC — средний ранг.
- Не обучать модель внутри отчёта. Пересчёт баллов логистической регрессией (D-074) — отдельная задача, её результат — новый `policy/*.yaml`, на который отчёт и указывает.
