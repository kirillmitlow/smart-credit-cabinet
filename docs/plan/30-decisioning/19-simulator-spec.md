Один документ — одна вещь: **как устроен помесячный имитатор денежного потока бизнеса**, из которого получаются (а) синтетический портфель с историей дефолтов для отчёта валидации ([30-14](14-model-validation-monitoring.md)) и массовых тестов, (б) вероятностный стресс-тест одной заявки. Дефолт здесь не задан формулой: он **возникает**, когда у бизнеса не хватает денег на платежи три месяца подряд.

Все числа этого документа получены на прототипе (Python + numpy, 21.10.2026, скрипт в рабочей папке сессии, в репозиторий не входит). Прототип проверял замысел и калибровку; при реализации калибровку (раздел 8) повторить на боевом коде.

## 1. Режимы

| Режим | Вход | Выход | Размер |
|---|---|---|---|
| **Портфель** | seed, число заявок, версия правил | Для каждой заявки: наблюдаемые признаки «как из моков» (раздел 6), запрос клиента, исход «дефолт в 12 мес. / за срок», траектория (по запросу) | 20 000 – 40 000 заявок |
| **Стресс одной заявки** | Наблюдаемые данные заявки + условия кредита | Вероятности: `P_def12`, `P_miss12`, то же за весь срок, квантили минимального остатка денег | 1000 траекторий |
| **Тесты** | seed | Те же функции на малых размерах (раздел 12) | десятки – сотни |

Движок один (одна функция «прожить месяц»), режимы различаются только тем, откуда берутся параметры: в портфеле они «истинные» и скрытые, в стрессе — оценённые по данным заявки с неопределённостью.

## 2. Сущности

| Сущность | Поля (смысл) |
|---|---|
| `Business` | Отрасль, возраст (мес.), среднемесячная выручка `R0`, маржа `m`, доля постоянных расходов `fs`, волатильность `σ`, тренд `μ`, вероятность шока `p`, целевая подушка `K`, налоговый режим и НДС, форма (ООО / ИП), флаг «клиент банка», «тонкое досье» |
| `Loan` | Вид (аннуитет / в конце срока / линия / овердрафт), сумма или лимит, ставка, срок, график платежей (из [30-16](16-loan-math.md)), для `CONTRACT` — контракт: цена, срок оплаты |
| `MonthState` | Месяц, выручка, поток, остаток денег, долг по просрочке, счётчик подряд непогашенных платежей `c` |
| `Observation` | Наблюдаемые признаки на день заявки (раздел 6) — то, что видят моки и ядро |
| `Trajectory` | Ряд `MonthState` до конца срока и исход: месяц первого пропуска, месяц дефолта |

## 3. Параметры по отраслям

Маржа `m` — по D-038 и [30-18](18-economic-assumptions.md) (Росстат и ФНС за 2025). Остальные колонки Росстат и ФНС не публикуют (месячной волатильности нет), поэтому они 📝 **допущения**, подобранные так, чтобы итоговая доля дефолтов и её разброс по отраслям попали в коридор ЦБ (30-18, п. 11).

| Отрасль | Доля заявок | Маржа `m` | Постоянные расходы `fs` (доля всех расходов) | Волатильность `σ` (месяц) | Шок `p` (в мес.) | Сезонность `A` | Фаза |
|---|---|---|---|---|---|---|---|
| Торговля | 0,30 | 5% | 0,15 | 0,07 | 0,0020 | 0,10 | 10 |
| Общепит | 0,15 | 10% | 0,35 | 0,07 | 0,0020 | 0,12 | 6 |
| Производство | 0,15 | 12% | 0,30 | 0,07 | 0,0016 | 0,05 | 9 |
| Услуги | 0,20 | 13% | 0,35 | 0,06 | 0,0016 | 0,08 | 9 |
| IT | 0,10 | 15% | 0,40 | 0,08 | 0,0020 | 0,03 | 0 |
| Агро | 0,10 | 15% | 0,30 | 0,08 | 0,0020 | 0,50 | 8 |

Доли заявок — 📝 допущение (ориентир: структура реестра МСП). Сезонный множитель: `S_t = 1 + A · sin(2π·(месяц − фаза)/12)`, среднее за год ровно 1. У агро амплитуда 0,5: зимой выручка вдвое ниже средней (D-069: сезонный бизнес оценивается годовой выручкой / 12).

**Разброс между компаниями** (чтобы не все были «средние по отрасли»; 📝 допущения):

| Параметр | Распределение |
|---|---|
| Маржа компании | `m_отрасли × LogN(0; 0,35)` |
| Доля постоянных расходов | `fs_отрасли + N(0; 0,10)`, в пределах 0,05–0,80 |
| Волатильность | `σ_отрасли × LogN(0; 0,30) × (1 + 0,5·y)`, `y = exp(−возраст/36 мес.)` (молодые нестабильнее) |
| Вероятность шока | `p_отрасли × LogN(0; 0,5) × (1 + 0,8·y) × λ`; `λ` — единственная ручка калибровки, по умолчанию ≈ 1 |
| Тренд `μ` (номинальный рост в год) | `N(0,08; 0,12)` |
| Возраст | 6 мес. + Gamma(2; 36), не более 480 мес. |
| Выручка `R0`, ₽/мес | `LogN(ln 3 млн; 1,0)` |
| Целевая подушка `K` | `LogN(0; 0,6)` (в долях месячных расходов × 0,3), для агро ×3 |
| Нагрузка по текущим кредитам | платежи = `Beta(1,2; 4) × поток`; 10% компаний — «тонкое досье», без кредитов |

## 4. Помесячная динамика

Шаг — месяц. Состояние: остаток денег `cash`, уровень шока `L`, шум `e`, макрофактор `M`, просрочка `arrears`, счётчик `c`.

| Блок | Правило (формулой) |
|---|---|
| Шум выручки | `e_t = 0,4·e_{t−1} + σ·√(1 − 0,16)·z`, `z ~ N(0;1)`. Стационарное отклонение равно `σ` |
| Макрофактор (общий для всех компаний прогона) | `M_t = 0,8·M_{t−1} + 0,012·z_M`: создаёт корреляцию дефолтов (поэтому в отчёте биномиальный тест с поправкой, 30-14) |
| Шок | С вероятностью `p` `L ← L·(1 − d)`, `d ~ U(0,15; 0,50)` (потеря ключевого клиента, кризис); иначе `L ← L + 0,08·(1 − L)` (восстановление 8% в месяц) |
| Выручка (без НДС) | `Rev_t = R0 · e^{μ·t/12} · S_t · L_t · e^{e_t + M_t}` |
| Расходы | Переменные: доля `V = (1 − fs)(1 − m)` от выручки. Постоянные: `F_t = fs·(1 − m)·R0 · e^{0,06·t/12}` (рост на 6% в год, 📝 допущение). Налоги отдельно не моделируем: `m` — рентабельность после налога |
| Поток до долгов | `CF_t = Rev_t·(1 − V) − F_t` (в точке `t = 0` и без шоков среднее равно `R0·m`). Операционное плечо: при падении выручки на 20% поток падает сильнее 20% |
| Платёж месяца | `due_t` = платежи по текущим кредитам + по новому кредиту (график 30-16) + накопленная просрочка |
| Оплата | Если `cash + CF_t ≥ due_t`: платёж внесён, просрочка 0, `c = 0`. Владелец забирает `0,7 ×` деньги выше цели `T_t = K·(0,3·(1 − m)·R0·e^{0,06·t/12} + платёж)`. Иначе платёж **не внесён целиком** (частичных платежей нет), `cash = max(cash + CF_t, 0)`, `arrears = due_t`, `c = c + 1` |
| Подушка | Начальный остаток `K·0,3·(1 − m)·R0`; без дополнительных источников денег (займов у владельца, нового кредита нет — 📝 допущение, осторожное) |

**Правило дефолта.** Дефолт наступает, когда `c ≥ 3`: платёж не вносился три месяца подряд (D-075). Параметр `DEFAULT_MISSED_PAYMENTS = 3`. Соответствие корзинам БКИ: `c = 1` → `D1_29`, 2 → `D30_59`, 3 → `D60_89`, 4 → `D90_119`. Формально «просрочка свыше 90 дней» (483-П, п. 13.3, Базель CRE36.68, 30-18 п. 4) наступает на четвёртой дате платежа, то есть на шаг позже. Мы признаём дефолт на третьем пропуске, как сказано в D-075; сдвиг стоит около 1 п.п. годовой доли (прототип: 6,0% при 3 против 5,1% при 4). Для строгого правила параметр ставится в 4 и калибровка повторяется. Просрочку можно «вылечить»: если деньги появились раньше третьего пропуска, платёж и накопленное гасятся, `c = 0`. Дефолт после наступления не снимается.

**Виды кредитов:**

| Вид | Что делает имитатор |
|---|---|
| Аннуитет | Платёж из графика 30-16 каждый месяц |
| Погашение в конце срока (`CONTRACT`) | Проценты каждый месяц; в месяце срока ещё и вся сумма. **Поступление по контракту** (цена контракта) приходит в месяц оплаты из ЕИС; с вероятностью 0,15 задержка 1–3 мес., с вероятностью 0,01 заказчик не платит (📝 допущения). Расходы на исполнение контракта идут за счёт кредита |
| Кредитная линия | Использование стартует с `U(0,3; 0,8)` лимита; нехватка денег покрывается выборкой в пределах лимита до того, как платёж считается пропущенным; излишки гасят линию; проценты на среднее использованное. Пропуск наступает, когда лимит исчерпан |
| Овердрафт | Как линия; задолженность обязана вернуться до нуля в течение 30 дней, иначе платёж по овердрафту считается пропущенным |

В прототипе реализованы только аннуитеты; контракт, линия и овердрафт описаны, но не калибровались.

## 5. Предыстория 24 месяцев

Перед заявкой имитатор «проживает» 24 месяца (от `t = −23` до `t = 0`) с текущими кредитами компании. Это даёт: остаток денег на день заявки, обороты, историю просрочек, налоговый долг, все согласованные друг с другом (раздел 6). Если к `t = 0` уже `c ≥ 3`, заявитель попадает в стоп-фактор (около 2% входящего потока) и в популяцию для метрик не включается. Отдельно отмечается: у 8% компаний был дефолт на текущих кредитах за 24 мес.

## 6. Наблюдаемые признаки (согласованы с моками)

| Что видит ядро | Как получаем из траектории | Правило моков |
|---|---|---|
| `incomingRub` (оборот, 24 мес.) | `Rev_t · (1 + НДС_t) · (1 + ε)`, `ε ~ N(0; 0,02)` в пределах ±5% | 10.3: шум ±5%, поступления с НДС |
| НДС | ОСНО: ставка по дате месяца (20% до 2025, 22% с 2026, `VAT_RATE_SCHEDULE`); у остальных 0. ОСНО у 60% торговли и производства, у прочих 0 (📝 допущение) | 10.3 |
| `incomingNetRub` | `incomingRub` минус 0,5–1% | 7.2 |
| `outgoingRub` | `incomingNetRub − (cash_t − cash_{t−1})`; включает платежи по кредитам и выводы владельца | 10.3 «списания = поступления − остаток». В моках остаток не меньше `minMonthlySurplusRub`, в имитаторе бывает отрицательным: это не нарушение, имитатор видит «плохие месяцы» |
| `counterpartiesIn/Out` | По ОКВЭД: розница, общепит, услуги — 1–3; агро — 3–12; остальные — 1 плательщик на 0,5 млн выручки, от 5 до 60. Исходящих 10–40, растёт с выручкой | 10.3 |
| Отчётность за последний полный календарный год (ООО, возраст ≥ 12 мес.) | 2110 = Σ `Rev` за год; 2400 = Σ `CF` − проценты по кредитам; 2330 = проценты по кредитам; 1400 = остаток долга на 31.12 | 10.3: сверка с оборотами ≤ 3%, 2330 = 2–25% среднего остатка |
| БКИ `summary` | Платежи и остаток существующих кредитов из траектории; `maxOverdueDays24m` и корзины `paymentHistory` — из счётчика `c` (раздел 4); `inquiries30d ~ Poisson(0,4 + 1,5·[была просрочка] + 1,5·[сейчас просрочка])`; «тонкое досье» — `hasHistory: false` | 6.1 |
| Налоговый долг | Появляется в месяце пропуска платежа с вероятностью 0,5 и остаётся | 5.1 |
| Возраст, клиент ли банка | Возраст из выборки; остаток денег на счёте — `cash_0`, если клиент | 7.1 |

Признаки для скоринга (возраст, история, запросы, долг / выручка, тренд, волатильность, налоговый долг) считает **ядро** по этим данным теми же функциями, что на живой заявке, имитатор их не знает. Скрытые `m`, `fs`, `p`, `K`, шоки ядру не передаются.

**Запрос клиента.** Платёж нового кредита задаётся долей оценки потока: `req ~ U(0,10; 1,00)` от `CF_est = R0·m_отрасли` за вычетом текущих платежей (банк не знает истинной маржи). Сумма получается обратной задачей (30-16, разд. 7), продукт и срок — из каталога (10-06), ставка — база продукта.

## 7. Что имитатор не умеет (честно)

Нет отраслевых кризисов по календарю, банковской реакции (реструктуризации, поручители), роста бизнеса на деньги кредита, мошенничества, эффекта отбора по «отказам других банков». Возможные утечки: ядро видит просрочки, которые порождены той же механикой, что дефолт, поэтому предсказательная сила на синтетике завышена. ## 8. Калибровка: доля дефолтов ~6% в год

- **Цель:** доля заявителей, прошедших стоп-факторы, с дефолтом в первые 12 мес. после выдачи = 6% (коридор 4–10%). Основание: ЦБ, малые предприятия 5,9% и микро 9,9% за 12 мес. (30-18, п. 11; D-079).
- **Ручки:** (1) `λ` — множитель вероятности шоков; (2) `s_m` — разброс маржи между компаниями (`0,35` в разделе 3); (3) `σ_g` — общий множитель волатильности. Бисекция по `λ` на одном seed (`N = 60 000`), 10 шагов, остановка при `|доля − 6%| < 0,1 п.п.`; если цель вне диапазона `λ` (0–3), дальше крутится `s_m`. Результат прототипа: `λ ≈ 0,97` (вероятности в таблице раздела 3 уже масштабированы под `λ = 1`). Главный двигатель дефолтов — не шоки, а **разрыв между оценкой банка (маржа отрасли) и настоящей маржой компании** плюс рост расходов быстрее выручки: диапазон доли дефолтов по ручкам — `λ` 0…1,5: 4,6…6,8%; `σ_g` 0,8…1,4: 5,7…6,7%; `s_m` 0,2…0,55: 4,6…8,3%. Коридор 4–10% достижим, выше 8,3% нужно менять и `μ`.
- **Итоги прототипа** (`λ = 1`, 60 000 заявителей, 12 мес.): всего **6,0%**; торговля 3,4%, общепит 9,0%, производство 5,8%, услуги 6,2%, IT 6,8%, агро 8,7%; с DSCR ≥ 1,25 — 3,7%. Все отрасли внутри коридора 3–10%. Накопленная доля дефолтов: за 24 мес. 14,8%, за 36 мес. 23,4% (по кредитам, прожитым до конца срока).
- **Динамика:** дефолтов в месяцы 1–3 — 0,2% заявителей, 4–6 — 1,5%, 7–9 — 2,7%, 10–12 — 1,6%, 13–24 — 8,8%. Ранних дефолтов мало, как в жизни (первое время поддерживает подушка).
- **Проверки после калибровки:** (1) монотонность: больше нагрузка → больше дефолтов (корзины DSCR: 16,4 → 8,8 → 4,3 → 1,8%); (2) отрасли упорядочены правдоподобно (общепит и агро рискованнее торговли); (3) ручки работают в сторону ожидаемого: больше шоков, больше разброс маржи и волатильность — больше дефолтов (числа выше).
- Калибровка к 6% на портфеле «входящего потока»; у одобренных она ниже (прототип: около 3,6%). 📝 Остальные параметры (раздел 3) подбирались вручную, проверены только на этом коридоре.

## 9. Детерминизм

- Один `seed` порождает всё. `seed` заявки в стрессе = `SHA-256(номер заявки + версия правил + версия имитатора)`, младшие 64 бита. Потоки случайных чисел раздельные: свой генератор на предысторию, на будущее, на параметры (чтобы добавление признака не меняло будущих траекторий).
- Случайные числа получаем **только** из базового `random()` встроенного генератора, а нормальные (Бокс–Мюллер), логнормальные, гамма, бета считаем сами: у разных версий библиотек результаты `gauss`/`gammavariate` не гарантированы одинаковыми.
- Порядок обхода — по возрастанию индекса компании и месяца; без обращения к времени, окружению и порядку словарей. Тест: два запуска дают побитово одинаковые таблицы.

## 10. Вероятностный стресс-тест одной заявки

**Вход (оценки по данным заявки, не истинные параметры):**

| Параметр движка | Откуда |
|---|---|
| `R0` | Осторожная выручка (30-03, вариант 1В; сезонным — годовая / 12) |
| `m` | Рентабельность из отчётности, иначе маржа отрасли (30-18) |
| `σ` | `σ̂ = стд(ln(Rev_t / Rev_{t−12}), последние 12 мес.) / 1,35`, в пределах 0,03–0,25. Коэффициент 1,35 — 📝 допущение прототипа: разность двух шумов с автокорреляцией 0,4 |
| `fs`, `A`, фаза, `p` | Таблица отрасли (раздел 3), для молодого бизнеса `y` по возрасту |
| Деньги на счёте | `cash_0` из АБС (для клиентов); иначе `K = 1`: 0,3 месячных расходов (📝 допущение) |
| Платежи | Текущие (БКИ + АБС) и график нового кредита (30-16) |

**Неопределённость параметров.** На каждой траектории `σ` и `m` умножаются на `LogN(0; 0,2)`, `fs` меняется на `N(0; 0,1)`, `μ ~ N(0,08; 0,12)`, `K ~ LogN(0; 0,6)`. Так результат не делает вид, что мы знаем параметры точно. Начальное состояние: `e = 0`, `L = 1`, `M = 0`, календарный месяц — месяц выдачи.

**Выход:** `P_def12` — доля траекторий с дефолтом в первые 12 мес.; `P_miss12` — с хотя бы одним пропуском платежа; то же за срок кредита (для андеррайтера); 5-й процентиль минимального остатка. Число траекторий `N_PATHS = 1000` (стандартная ошибка при вероятности 9% — 0,9 п.п.; для спорных заявок в 10% ± 2 п.п. можно перезапустить с 5000).

**Порог (принят D-084, решил агент по D-073).**

| `P_def12` | Что значит | Действие |
|---|---|---|
| ≤ 10% | Зелёная зона | Не мешает автоматическому решению |
| 10–20% | Жёлтая | Автоодобрения нет: встречное предложение (меньше сумма / дольше срок / с обеспечением) или ручное рассмотрение |
| > 20% | Красная | Вариант не проходит, ищем встречное |

**Исключение (R-003):** условное встречное «с обеспечением» для молодого бизнеса (`BUSINESS_TOO_YOUNG`, 30-04) жёлтой зоной **не блокируется**: решение по такой заявке после принятия встречного всё равно принимает человек, а у молодого бизнеса вероятность дефолта выше по определению; красная зона (> 20%) блокирует и здесь. Автоотказа по стресс-тесту нет (D-034): он только отсекает вариант и порождает встречное предложение, как DSCR. Метрика — дефолт, а не любой пропуск: пропуск, который «лечится», банку убытка не даёт, а в модели пропуск превращается в дефолт в ~75% случаев (Соколова: `P_miss12` 5,9%, `P_def12` 4,4%). Прежняя формулировка 30-08 («хотя бы один платёж не покроется ≤ 5%») заменена этим порогом (D-084, [30-08](08-affordability-options.md)). **Обоснование порога 10%:**

1. Калибровка (прототип, 2500 заявок с DSCR ≥ 1,25, прогноз против факта по корзинам `P_def12`): <1% → факт 0,9%; 1–3% → 2,2; 3–5% → 4,4; 5–8% → 6,2; 8–12% → 8,3; >20% → 23%. Прогноз не завышает и не занижает, поэтому порог читается как порог вероятности дефолта.
2. Таблица цен [30-09](09-pricing-options.md) покрывает PD до 7% (грейд C, ставка 22%); 10% — верхний край того, что можно прилично оценить с запасом на неточность параметров.
3. Эффект: порог 10% пропускает 94% потока, прошедшего DSCR, и снижает долю дефолтов прошедших с 3,6% до 2,9%; порог 5% пропускает 81% и даёт 2,2%. 10% не режет клиентов лишнего и всё же убирает «хвост».
4. Различающая способность самого `P_def12` как признака дефолта на этой выборке: Gini 0,48 (прототип).

**Персоны (R-003; числа прогона [30-17](17-persona-walkthrough.md)).** Входы — допущения таблицы выше; сезонность и поступление по контракту в расчёт не включены. Прототип 30-17 (чистый Python, 20 000 траекторий, σ = 0,08) даёт на 15–50% меньше, чем прежний прототип numpy (последняя колонка, старые входы), поэтому интервалы 30-17 взяты с поправкой ×1,2…×1,5. | Режим | Замер / оценка |
|---|---|
| Стресс одной заявки, 1000 траекторий × 12–36 мес. | Прототип numpy: 2–18 мс. Чистый Python (замер на эквивалентном цикле): ~0,1 с на 36 мес. Требование < 1 с на CPU выполняется с запасом ×10 |

| Портфель для отчёта, 40 000 × 60 мес. | Чистый Python ~7 с (оценка по замеру цикла). Бюджет CI из 30-14: < 60 с |
| Память | 40 000 заявок × 60 мес. × несколько рядов — до сотен МБ в numpy; в чистом Python потоком, без хранения траекторий (хранятся только признаки и исход) |

Рекомендация: **чистый Python** (без новой зависимости, один код для стресса и портфеля, свои преобразования случайных чисел из раздела 9); numpy ускорил бы портфель в 20 раз, но нужен второй путь кода и риск расхождений между путями. Выбор зависимостей — решение пользователя (D-073, технологии).

## 12. Тесты

1. Воспроизводимость: два запуска с одним seed дают одинаковый результат; разные seed — разные.
2. Доля дефолтов портфеля из 20 000 в коридоре 4–10% при `λ` из конфига; каждая отрасль в 2–15%.
3. Монотонность: рост платежа, рост доли постоянных расходов, рост `σ` не уменьшают долю дефолтов (статистически, на 20 000 заявок, допуск 0,5 п.п.).
4. Инварианты состояния: деньги не отрицательны; `c` не убывает, пока платёж не внесён; дефолт не отменяется.
5. Согласованность с моками: сумма `incomingNetRub` за год ≈ 2110 × (1 + НДС) в пределах 3%; 2330 в границах 2–25% среднего остатка; 1400 ≤ остатки на 31.12; категории МСП по выручке.
6. Платёж и остаток в траектории совпадают с графиком 30-16 (одна функция).
7. Стресс: для заявки с нулевой волатильностью и без шоков `P_def12 = 0`; для заявки с платежом выше потока и нулевой подушкой `P_def12 = 1`.
8. Калибровка стресса: на портфеле факт по корзинам `P_def12` отличается от прогноза не более чем на 2 п.п. (корзины с n ≥ 200).
9. Производительность: стресс одной заявки (1000 × 36) < 1 с в CI; регресс-тест времени.
10. Тест на тест для отчёта 30-14: сдвинутая версия портфеля (параметр «выручка −15%») обязана давать PSI > 0,25.

## Заметки для реализации
