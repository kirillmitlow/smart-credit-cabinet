## Зачем

Каждое решение должно быть понятно **клиенту** (что случилось и что делать) и **андеррайтеру** (почему, с числами). Ядро возвращает не тексты, а **коды с параметрами**; тексты собираются по справочнику ниже. Тот же справочник — контракт для интерфейса и для тестов.

## Правила текстов

- **Клиенту:** простыми словами, без слов «грейд», «балл», «скоринг», «PD», «DSCR», «стоп-фактор», «флаг». Всегда два куска: что случилось и что можно сделать. Баллы и грейд клиент не видит.
- **Андеррайтеру:** коротко, с числами и источником; можно термины. Параметры в фигурных скобках подставляются при сборке: суммы «1 150 000 ₽», доли «12,5%», даты «21.10.2026».
- Отказ по `AML_LIST` не раскрывает причину (запрет информировать о мерах ПОД/ФТ, 115-ФЗ).
- Флаги клиенту подаются как «заявку смотрит специалист», без обвинительных формулировок.

## Справочник кодов

Тип: `STOP` стоп-фактор · `FLAG` флаг · `CONSTRAINT` деньги · `PRODUCT` правила продукта · `ROUTE` ручной маршрут · `DATA` данные · `OUT` общий исход.

## Вклад факторов

Для каждого решения сохраняется таблица: фактор, значение признака, баллы, максимум, **недобор** (максимум минус баллы).

| Фактор | Клиенту, если вклад плохой (недобор > 50% максимума) | Что можно сделать |
|---|---|---|
| `SC_AGE` | Бизнесу пока немного лет | Со временем оценка вырастет |
| `SC_CREDIT_HISTORY` | В кредитной истории есть просрочки или она короткая | Платить вовремя, закрыть просрочки |
| `SC_INQUIRIES` | Недавно вы подавали много заявок в другие банки | Подождать месяц между заявками |
| `SC_DEBT_LOAD` | Действующие долги велики по сравнению с выручкой | Погасить часть долгов |
| `SC_TREND` | Выручка снижается | Загрузить выписку, если картина шире |
| `SC_VOLATILITY` | Выручка сильно скачет по месяцам | — |
| `SC_TAX` | Есть задолженность по налогам | Погасить долг |
| `SC_CLIENT` | Вы пока недавно или не обслуживаетесь у нас | Открыть счёт и вести по нему операции |
| `SC_COVERAGE` | Текущие платежи по кредитам занимают большую часть свободных денег | Погасить часть кредитов |

- **Андеррайтеру:** все девять строк, по убыванию недобора, с числами и источником значения.
- **Клиенту:** при `REJECTED`, `COUNTER_OFFER`, `NEEDS_INFO` — до 3 самых больших недоборов фразами из колонки 2. При `APPROVED` — до 2 лучших факторов («Что помогло: чистая кредитная история, стабильная выручка»).

## Блок «Что изменить, чтобы одобрили» (D-072)

Строится из того же перебора, что и встречные (30-10). Показывается при `COUNTER_OFFER`, `REJECTED` по деньгам и `NEEDS_INFO`; не более трёх строк, по близости к запросу.

| Рычаг | Когда показываем | Как считаем | Что видит клиент |
|---|---|---|---|
| Меньше сумма | Не проходит DSCR или потолок | Максимальная сумма при DSCR ≥ 1,30, стресс ≥ 1,0 | «Одобрим до {x} на {срок} мес., платёж {p}» |
| Дольше срок | То же | Минимальный срок из сетки, при котором запрошенная сумма проходит | «{сумма} пройдёт на {t} мес., платёж {p}» |
| Другой продукт | Лучший по расстоянию до запроса | Перебор каталога (30-10) | «Кредит под контракт: {сумма}, проценты {p}» |
| Залог | Грейд D, сумма выше авто-лимита или обязательный залог | Пересчёт с LGD 35% | «С залогом ставка {ставка}, вместо {ставка без залога}» |
| Поручитель | Молодой бизнес; тонкая история | Условие продукта | «Добавьте владельца как поручителя» |
| Подтвердить выручку | Выручка получена по марже или с коэффициентом 0,7; не хватает до порога | Нужный поток `max(1,30; 1/(1 − шок)) × (текущие платежи + новый)`; нужная выручка = поток / маржа. Показывается, только если нужное ≤ 1,5 × текущей: невозможное не обещаем | «Если выписка покажет не менее {R} в месяц, условия пройдут» |
| Погасить долг | Стоп-фактор `TAX_ARREARS_HIGH`, `CURRENT_OVERDUE_90` | Сумма до порога | «Погасите {сумма} и подайте заявку заново» |
| Подождать | `BUSINESS_TOO_YOUNG`, `PRODUCT_AGE_MIN`, `BANKRUPTCY` | Дата, когда условие снимется | «Подайте заявку после {дата}» |

Кнопки блока возвращают заявку в работу с новыми данными: `COUNTER_OFFER → CHECKING` (20-02).

## Границы

- **Входит:** коды, тексты, вклад факторов, блок «что изменить».
- **Не входит:** дизайн экранов, словарь клиентского языка (60-06), сами формулы (30-xx).

## Как проверяем

- Тест полноты: у каждого кода из политики есть все три текста; у каждого фактора скоркарты — строка.
- Тест подстановки: все `{параметры}` из справочника заполнены в ответе ядра, незаполненных скобок в выводе нет.
- Тест языка: в текстах для клиента нет слов «грейд», «балл», «скоринг», «PD», «DSCR», «стоп-фактор», «флаг».
- Персоны: ожидаемые коды из 10-02 есть в ответе (`REVENUE_UNKNOWN`, `TAX_ARREARS_HIGH`, `DSCR_LOW`…).
- Для `AML_LIST` клиентский текст не содержит причины.

## Открытые вопросы

Нет. Список кодов 10-02 (`AMOUNT_ABOVE_AUTO_LIMIT`, `COLLATERAL_REVIEW`) подтверждён этим документом как финальный.

## Заметки для реализации

- Тексты хранятся в каталоге `texts/ru` (30-13) и **собираются в момент решения**, итог сохраняется в снимке: клиент через месяц видит то же, что видел.
- Ядро возвращает код и словарь параметров; форматирование (пробелы в числах, ₽, даты) делает общий форматтер, не каждый текст.
- Для `NEEDS_INFO` клиентский текст превращается в задачу (`tasks`: «что», «зачем», срок).
- Не показываем в интерфейсе внутренние названия флагов и кодов; код видит только андеррайтер и тест.
