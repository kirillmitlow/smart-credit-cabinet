## Реализовано

- T-330: публичные чистые `parse_statement(content, expected_inn, as_of=...)` и
  `validate_statement_set(results)`, `ParsedStatement.as_dict()` для JSON.
- Синтаксис 1.03, Windows-1251/UTF-8, строгие даты/кодировка, контроль размера/строк;
  отрицательные остатки по овердрафту допустимы, отрицательные платежи — нет.
- Владелец из своей стороны платежа, проведённые даты отдельно от даты платёжки,
  сверка оборотов/остатков до копейки, дубли и противоречивые ключи, периоды счетов.
- Обе стороны собственных переводов сохранены; такой приход помечен OWN_TRANSFER.
  Все внешние поступления остаются неоднозначными до подтверждения: парсер не
  объявляет кредит, взнос, возврат или платёж по договору доказанной выручкой по назначению.
- Полные месяцы покрыты всеми загруженными счетами; неполные помечены и не повышают среднее.
  Суммирование в точных копейках, одно ROUND_HALF_UP на выходе. В JSON нет назначений платежей.
- T-331: независимый ручной корпус и unit/property, включая две стороны переводов,
  дубли разных видов документов, переход года, частичное покрытие, произвольные байты.
- Makefile: ошибки любого Python-подпроекта явно пробрасываются из check/test.
  На системном make старый цикл мог скрыть ошибку API за успешным следующим проектом.
