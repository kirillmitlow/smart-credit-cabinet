# Публичный интерфейс документов

Первый пакет T-332: хранение исходных байтов, метаданные и проверка загрузки.
Разбор 1С, подтверждение данных и использование в расчёте — следующие T-330…T-334.
В этом пакете выписка сохраняется в `PENDING`; её числа ещё не участвуют в решении.

## Для владельца банковской зоны

Импорт: `from app.modules import documents`. Транзакцию держит вызывающий.
`Access(user_id, company_ids=(), bank=False)` строится **на сервере из проверенной
сессии**, а не из входных данных. Для банковского чтения — `bank=True` после
обычной проверки актуальной банковской сессии. Клиентские `company_ids` должны
содержать только разрешённые компании без общей роли поручителя.

| Функция | Результат |
|---|---|
| `get_metadata(session, access, document_id)` | Метаданные одного документа, чужой → 404 |
| `list_metadata(session, access, application_id)` | Метаданные файлов заявки; байты не загружаются |
| `as_dict(document)` | Клиентская проекция с видом, происхождением, хешем и состоянием обработки |
| `verified_content(session, access, document_id)` | Метаданные и исходные байты после сверки размера и SHA-256 |

Прямые импорты `documents.models` и чтение/запись таблиц из backoffice не нужны.
Сохранённый исходник неизменяем; отмена при замене видна по `cancelled_at`.
Физически `document_blobs` хранит bytea отдельно от метаданных. `FileStore` имеет
`put/get/delete`; прикладное чтение идёт через `verified_content` с проверкой прав.
Перед будущей подписью PDF следует использовать именно эту функцию (T-336).

## HTTP

| Ручка | Доступ |
|---|---|
| `POST /documents` | Только клиент; multipart: `applicationId`, необязательные `taskId`/`replacesId`, `kind`, `file`. Обязателен `Idempotency-Key` |
| `GET /documents/{id}` | Своя компания; для банковской сессии явно `?zone=bank` |
| `GET /documents/{id}/download` | Те же права; attachment, nosniff, private/no-store |

Типы загрузки: `BANK_STATEMENT_1C`, `CONTRACT`, `FINANCIALS`, `OTHER`.
Выписка — до 5 МиБ, PDF — до 10 МиБ, до 30 страниц без шифрования; содержимое
проверяется независимо от имени и Content-Type. Суммарно 50 МиБ и 10 файлов на
заявку, включая заменённые исходники. Лимиты в настройках могут быть только ниже
предельных. Имена очищаются и никогда не становятся путями. Загрузка читается
потоково; при превышении лимита следующие порции не читаются.

При `NEEDS_INFO` нужна открытая задача DOCUMENT/CONFIRM_REVENUE именно этой заявки
и право на неё. В DRAFT задача необязательна. Банк через клиентскую ручку не пишет.
Одна транзакция: исходник, метаданные, отмена прежнего, аудит и ключ повтора.
Сбой откатывает всё; повтор того же ключа не создаёт второй файл. Изменение тела
при том же ключе — 409. Смена членства компании действует без повторного входа.

HTTP-сборка в `app.documents_http` / `app.document_actions` соединяет публичные
интерфейсы auth, applications и documents, как `app.wiring`. Нижний модуль
documents не импортирует владельцев заявок/пользователей или банковскую зону.
Операция держит ограждение компании во время чтения файла и записи. Сброс компании
сначала собирает её document/blob IDs, затем удаляет только их, до tasks/applications.
В сообщениях об ошибках и аудите нет исходного текста, назначения платежей или cookie.
