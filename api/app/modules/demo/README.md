# Демо-панель (T-370/T-374)

GET /demo/personas отдаёт шпаргалку из сервиса сценариев без учётных данных и полного spec.
GET /demo/chaos читает режим каждого источника; PUT /demo/chaos/{system} принимает
OK, SLOW, ERROR, DOWN, LOST_RESPONSE и latencyMs для задержки. Переключение ограждено
общим замком от сброса стенда. Частичная недоступность не скрывает остальные источники.

Вне DEMO_MODE все демо-методы закрыты. Локально управление открыто; в APP_ENV=cloud
сбросы и PUT chaos требуют X-Demo-Code, совпадающий с серверным DEMO_STAND_CODE.
Без настроенного кода управление закрыто. DEMO_CONTROLS_PER_MINUTE (по умолчанию 300)
ограничивает попытки по адресу в Redis, включая неверные коды; сброс квоту не очищает.
При отказе Redis управление закрыто. Квота — фиксированное минутное окно, не скользящее.
За общим reverse proxy без отдельных client IP посетители делят один лимит.

Публичная настройка сообщает demoCodeRequired и docsLinks из DOCS_LINKS. По умолчанию
есть только /docs API. Значение кода и ключи моков клиенту не передаются.
POST /demo/scenarios создаёт компанию; тестовый вход персоны пока не реализован. Банк входит через T-213,
клиент — по ИНН. Выписка и перепроверка после восстановления источника ждут модулей A.


## Создание компании

POST /demo/scenarios: тело ScenarioSpec, обязательный Idempotency-Key. Для тестового ИП
достаточны title, preset=IP_HEALTHY и при необходимости users с login/role/personRef=self.
Без preset или company.form сервис возвращает422 (Q-143). Доступны только клиентские роли
DIRECTOR/ACCOUNTANT/GUARANTOR; code + разделитель + login должны помещаться в100 символов.
Для code, не заданного явно, используется стабильный короткий хеш ключа запроса.

Успех201 подтверждает применение моков и синхронизацию каталога api. Повтор ключа возвращает
тот же ответ с Idempotent-Replayed=true. Потеря ответа после внешнего commit и откат локального
аудита восстанавливаются повтором того же ключа. Внешний FAILED может сохраниться без кэша201:
тогда повтор даёт409 SCENARIO_EXISTS; API не создаёт второй код и не выполняет автоматически
apply над существующим сценарием. Ответ не содержит учёток, expanded или полного spec.
Между внешним сервисом и api нет общей транзакции; до201 компания не считается подтверждённой.
