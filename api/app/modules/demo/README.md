# Демо-панель (T-370/T-374)

GET /demo/personas отдаёт шпаргалку из сервиса сценариев без учётных данных и полного spec.
GET /demo/chaos читает режим каждого источника; PUT /demo/chaos/{system} принимает
OK, SLOW, ERROR, DOWN, LOST_RESPONSE и latencyMs для задержки. Переключение ограждено
общим замком от сброса стенда. Частичная недоступность не скрывает остальные источники.

Вне DEMO_MODE все демо-методы закрыты. Локально управление открыто; в APP_ENV=cloud
сбросы и PUT chaos требуют X-Demo-Code, совпадающий с серверным DEMO_STAND_CODE.
Без настроенного кода управление закрыто. DEMO_CONTROLS_PER_MINUTE (по умолчанию 300)
ограничивает попытки по адресу в Redis, включая неверные коды; сброс квоту не очищает.
При отказе Redis управление закрыто. Квота — фиксированное минутное окно, не скользящее.
За общим reverse proxy без отдельных client IP посетители делят один лимит.

Публичная настройка сообщает demoCodeRequired и docsLinks из DOCS_LINKS. По умолчанию
есть только /docs API. Значение кода и ключи моков клиенту не передаются.
Создание сценариев и тестовый вход персоны пока не реализованы. Банк входит через T-213,
клиент — по ИНН. Выписка и перепроверка после восстановления источника ждут модулей A.
