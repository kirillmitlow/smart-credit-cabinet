# Умный кредитный кабинет (прототип)

Прототип цифрового кредитного конвейера для малого и микробизнеса: предприниматель входит по ИНН, подбирает продукт, подаёт заявку, подписывает согласия, получает решение, подписывает договор и видит кредит в разделе «Мои кредиты». Сотрудник банка видит очередь, запрашивает сведения, проверяет ручные условия и принимает решение. Проект сделан для хакатона «Альфа-Будущее 2026», кейс «Умный кредитный кабинет предпринимателя» ([текст кейса](docs/case.md), [оригинал в PDF](docs/Альфа_Хак_Умный_кредитный_кабинет.pdf)).

- **Все данные синтетические.** Компании, люди, ИНН (регион `00`), банковские системы и «банк» придуманы. Юридической силы у договоров и подписей нет.
- **Решение принимает не ИИ.** Одобрение, отказ, ставка и платёж считает детерминированное ядро по правилам из файла политики: один и тот же ввод всегда даёт один и тот же ответ. Генеративного ИИ в кредитном решении нет.
- Это прототип. Что в нём работает и чего нет, честно описано в разделе [«Ограничения и допущения»](#ограничения-и-допущения).

## Быстрый старт

Нужны только Docker и Git. Настраивать ничего не надо: ключи и пароли для разработки уже подставлены.

```bash
git clone https://github.com/kirillmitlow/smart-credit-cabinet.git
cd smart-credit-cabinet
docker compose up -d --build --wait
```

Когда команда вернёт управление, длительно работающие сервисы должны быть `healthy`; разовый `db-init` завершится с кодом 0. Откройте в браузере <http://localhost:8080>. Если порт 8080 на вашем компьютере занят, задайте другой:

```bash
WEB_PORT=8088 docker compose up -d --build --wait
```

Тогда адрес интерфейса — <http://localhost:8088>. Дальше в тексте везде написан порт 8080, подставьте свой. Уже работающий изолированный стенд команды — <http://127.0.0.1:8090>; он относится к отдельной установке, **8090 не порт по умолчанию**.

Для воспроизводимости четырёх сценариев ниже можно зафиксировать дату: `APP_TODAY=2026-10-21 docker compose up -d --build --wait`. В PowerShell задайте `$env:APP_TODAY="2026-10-21"` перед командой; для порта аналогично `$env:WEB_PORT="8088"`. Либо задайте обе переменные в локальном `.env`. Если Docker ещё не установлен, используйте Docker Desktop на macOS/Windows или Docker Engine с Compose на Linux; Node и Python на компьютере для запуска через Docker не нужны.

Интерфейс рассчитан на экран шириной от 1280 пикселей; на узком экране вверху будет предупреждение.

## Требования

| Что | Нужно |
|---|---|
| Docker | Docker Engine с Compose v2 или новее (команда `docker compose`, не `docker-compose`) |
| Память | стенд занимает около 1 ГБ оперативной памяти; на машине должно быть свободно не меньше 4 ГБ |
| Диск | образы приложения около 0,7 ГБ, плюс образы Postgres и Valkey; оставьте с запасом 5 ГБ |
| Порты | свободные `8080` (интерфейс, меняется через `WEB_PORT`), `8100` (API и Swagger), `8101`–`8105` (пять мок-сервисов). Порты открыты только на `127.0.0.1`, наружу в сеть они не торчат |
| Интернет | нужен для первой сборки (скачиваются образы и зависимости). Сам интерфейс после сборки работает без интернета. Исключение: страницы Swagger (`/docs`) подгружают оформление с публичного CDN, без интернета они не откроются |

**Что мы проверили.** Arch Linux, Docker 29.7.2, Docker Compose 5.5.1, 30 ГБ оперативной памяти. Дополнительно на macOS с Docker Desktop проверены сборка и браузерные пути Соколовой и Станкопрома. На Windows README не проверялся; нужны Docker Desktop (WSL2) и Git.

**Исторический замер команды, 23.10.** На указанной Linux-машине, когда базовые образы уже были скачаны: сборка с кэшем около 20 секунд, сборка с нуля (`build --no-cache`) около 45 секунд, подъём всех 11 контейнеров до `healthy` около 1 минуты. Самая первая сборка на чистой машине дольше: скачивание образов зависит от вашего интернета, мы его не измеряли.

## Как понять, что всё поднялось, остановить и сбросить

```bash
docker compose ps                  # сервисы Up или healthy; db-init в состоянии Exited (0), это нормально
curl http://127.0.0.1:8100/health/ready
```

Для полной проверки есть скрипт `scripts/smoke.sh` (подготовлен в PR #77, **появится в `main` после его влития**; до этого в этой ветке его нет). Он проверяет готовность всех сервисов и проводит через стенд кредит Соколовой от входа до выдачи. Запуск: `bash scripts/smoke.sh` (для другого порта: `bash scripts/smoke.sh http://127.0.0.1:8088`), быстрая проверка без изменения данных: `bash scripts/smoke.sh --quick`. Успех — строка `PASS` и код возврата 0. На нашем стенде полный прогон занял около 11 секунд.

Команды разработчиков (нужен `make`, жюри он не обязателен, каждая команда равна строке рядом):

| Команда | Что делает | Без `make` |
|---|---|---|
| `make up` | поднять стенд | `docker compose up -d --build --wait` |
| `make down` | остановить, данные сохраняются | `docker compose down` |
| `make reset` | сбросить демо-данные (заявки, кредиты, сессии, моки) | `curl -X POST http://127.0.0.1:8100/demo/reset` |

Полностью стереть всё, включая базу: `docker compose down -v` — эта команда удаляет данные выбранного стенда. Проект в Compose по умолчанию называется `smart-credit-cabinet`. При параллельной работе нужно **и своё имя проекта `-p mydemo`, и отдельные порты**: `WEB_PORT` меняет только web, прямые порты `8100`–`8105` остаются прежними. Их владелец стенда переопределяет отдельным локальным Compose override. Одно имя `-p` конфликты портов не устраняет. Не останавливайте чужие контейнеры ради запуска своей копии.

## Настройки

Для запуска `.env` не нужен. Если хотите что-то поменять, скопируйте шаблон: `cp .env.example .env`. Файл [.env.example](.env.example) содержит все переменные с пояснениями. Ключевые:

| Переменная | Значение по умолчанию | Что делает |
|---|---|---|
| `WEB_PORT` | `8080` | порт интерфейса на вашем компьютере |
| `APP_TODAY` | пусто (реальная дата) | «сегодня» для всего стенда, формат `ГГГГ-ММ-ДД`; после смены перезапустите стенд |
| `DEMO_MODE` | `true` | демо-режим: код входа и подписи показан на экране вместо SMS, работают `/demo` и вход андеррайтера кнопкой. В `.env.example` её нет, но compose её читает; для проверки жюри не меняйте |
| `POSTGRES_PASSWORD`, `MOCK_DB_PASSWORD`, `SESSION_SECRET` | значения для разработки | секреты. Это не боевые значения, на общедоступном стенде их надо заменить (для этого есть `docker-compose.cloud.yml`, где значений по умолчанию нет; облачный стенд мы не поднимали) |
| `REGISTRY_API_KEY`, `TAX_API_KEY`, `BKI_API_KEY`, `BANK_CORE_API_KEY` | `dev-…-key` | ключи, с которыми `api` ходит в мок-сервисы |
| `MOCK_ADMIN_KEY` | `dev-admin-key` | админ-ключ моков и сервиса сценариев (заголовок `X-Admin-Key`) |

## Самопроверка за 20–30 минут

Проходите по порядку, каждый сценарий можно повторять после сброса. Четыре основных сценария — Соколова, СнабКонтракт, Ромашка и Станкопром. Исторические браузерные проверки команды описаны в журнале 23.10; новая сверка и прогон API — в [отчёте комплекта](docs/plan/reviews/C-2026-10-24-jury-package-refresh.md). Это не репетиция человеком, впервые увидевшим проект. Сценарии 5 и 6 дополнительные, часть их шагов проверялась запросами. Время сценариев указано примерно.

### Перед началом и между прогонами

Перед каждым повтором откройте <http://localhost:8080/demo> и нажмите «Сбросить персону» в карточке **только нужной компании**, подтвердите. Это удаляет её демо-заявки и кредиты; соседние компании сохраняются. API-эквивалент — `POST /demo/personas/{code}/reset`: коды `sokolova`, `snabkontrakt`, `stankoprom`, `romashka`. При 409 повторите через секунду; 502 требует разбора шага сброса. Без сброса исход может отличаться из-за уже открытой заявки или кредита.

Общий «Сбросить демо» очищает весь стенд и сессии. Используйте его только если стенд ваш и остальные участники предупреждены. Коды входа, согласий и договора всегда новые, берите их с экрана; постоянного кода в инструкции нет.

### 4. Ручное встречное и сторона банка: ООО «СтанкоПром» (8 минут)

В этом проходе залог не предлагается: он проверяет оборотный запрос и ручные условия. Форма позволяет заявить имущество, но это не подтверждённая банком оценка залога. Точный инвестиционный сценарий оракула (15 млн / 60 мес. с залогом) проверяется браузерными тестами, которые подготавливают залог через публичный API. Загрузку договора этот проход не заменяет.

1. Войдите по ИНН `0017654322`, выберите «Кузнецов Игорь Петрович, руководитель». Бухгалтер не подпишет личные согласия руководителя: полный переход бухгалтер → руководитель ещё не завершён.
2. «Заполнить заявку сразу», **«Оборотный кредит», 15 000 000 ₽, 12 месяцев**. Пройдите шаги, подпишите согласия и отправьте. Клиент увидит ручное рассмотрение.
3. Во второй вкладке войдите как андеррайтер через `/login?zone=bank`, откройте заявку в очереди. Карточка показывает рекомендацию, ограничения, источники и расчёт. Не пытайтесь одобрить исходные условия вопреки ограничениям продукта.
4. «Запросить информацию»: тип «Пояснение», заголовок «Поясните сроки поставки», зачем «Нужно проверить план закупки». Подтвердите; у клиента появится задача.
5. Клиент заполняет ответ и нажимает «Отправить ответы». Банк увидит отправленный ответ и новый раунд; после повторного расчёта заявка вернётся на ручной разбор.
6. В банке откройте заявку → **«Ручной расчёт условий»**: сумма **10 000 000 ₽**, срок **12 месяцев**, ставку оставьте пустой. Выберите категорию **«Риск выше расчётного»** и напишите пояснение от 50 символов, например: «По результатам изучения источников предлагаем меньшую сумму финансирования с сохранением расчётной ставки». «Рассчитать»: видны платёж, DSCR, стресс, коридор ставки и требуемый уровень. Пока условия недопустимы, сохранить нельзя; после любой правки нужен новый расчёт.
7. Когда расчёт разрешает условия, нажмите «Сохранить встречное предложение». Клиент увидит вариант, выберет его и подпишет договор кодом; затем появится выдача. Внутреннего пояснения банка клиент не видит.

Отдельно доступны «Одобрить», «Отказать» и «Перезапросить источники». Отклонение от рекомендации требует причины; послабление — только L2 и пояснение от 50 символов. Жёсткие запреты не снимаются.

### 5. Сбой внешней системы (3 минуты)

1. Сбросьте персону Соколовой. На `/demo` в блоке «Сбои внешних систем» у «БКИ» выберите режим «Недоступен» и нажмите «Применить режим». Вверху всех страниц появится полоса «На стенде включены сбои. БКИ: Недоступен». (Мы проверили эту кнопку автотестом на налоговой; для БКИ в нашем прогоне отправили тот же запрос `PUT /api/demo/chaos/credit_bureau` с телом `{"mode":"DOWN"}`.)
2. Войдите как Соколова (`001234567887`) и подайте заявку на 500 000 ₽ на 12 месяцев, как в сценарии 1 (через «Заполнить заявку сразу»). Вместо ошибки клиент увидит «Заявку смотрит специалист».
3. В банке (вкладка андеррайтера) заявка в очереди с пометкой «Источник недоступен» (`SOURCE_UNAVAILABLE`, «Недоступно: bki:COMPANY»).
4. Верните у «БКИ» режим «Работает» и «Применить режим». В карточке банка нажмите «Перезапросить источники». Заявка перейдёт в повторную проверку; свежий отчёт БКИ используется повторно.

### 6. Своя компания (3 минуты)

Создайте компанию с просрочкой 40 дней и входом директора. Блок `users` обязателен, иначе по ИНН нельзя будет войти («У этой компании пока нет сотрудников с доступом в кабинет»):

```bash
curl -X POST http://127.0.0.1:8105/api/v1/scenarios \
  -H "X-Admin-Key: dev-admin-key" -H "Content-Type: application/json" \
  -d '{"title":"ООО, просрочка 40 дней","preset":"LLC_HEALTHY",
       "company":{"ageMonths":24,"okved":"47.19","regionCode":"77"},
       "finance":{"avgMonthlyRevenueRub":5000000},
       "bki":{"company":{"currentOverdueDays":40}},
       "users":[{"login":"director","role":"DIRECTOR","personRef":"director"}]}'
```

В ответе найдите поле `inn`, войдите по нему (название компании сгенерировано случайно), подайте «Экспресс-кредит» на 1 000 000 ₽ на 12 месяцев. Ждите «Заявку смотрит специалист»; в очереди банка причины: «Просрочка от 30 до 89 дней» (`OVERDUE_30_89`) и «Риск требует ручного рассмотрения». Кнопки «Создать тестовую компанию» на `/demo` пока нет. Те же запросы можно выполнять в Swagger сервиса сценариев <http://127.0.0.1:8105/docs>, кнопка Authorize, ключ `dev-admin-key`.

### Если что-то не так

| Симптом | Что делать |
|---|---|
| Страница не открывается | `docker compose ps`: все ли сервисы `healthy`; подождите минуту после `up`; проверьте порт (`WEB_PORT`) |
| Персон нет в `/demo` или «Сценарии ещё применяются» | Подождите минуту после запуска и обновите страницу |
| Заявка долго «Проверяем» | `docker compose logs worker`; проверьте красную полосу сбоев. Для повторной проверки сбросьте только нужную персону; её заявки будут удалены |
| Исход не совпал с ожидаемым | Проверьте продукт, сумму, срок, APP_TODAY и сбои; повторите после сброса этой персоны (удалит её демо-заявки) |
| Порт занят | Для web задайте WEB_PORT. Для API/моков нужен отдельный override портов; не останавливайте чужой стенд |
| Нехватка памяти, контейнеры перезапускаются | Увеличьте память Docker Desktop до 4–6 ГБ |

## Из чего состоит

[Архитектурная схема Mermaid](docs/architecture/architecture.md) · [Состояния заявки](docs/architecture/state_machine.md) · [Модель данных](docs/architecture/data_model.md).

Стенд содержит **12 сервисов: 11 работающих контейнеров и разовый db-init** ([docker-compose.yml](docker-compose.yml)):

| Сервис | Что делает | Порт на вашем ПК |
|---|---|---|
| `web` | интерфейс клиента и сотрудника банка (React, Mantine), nginx отдаёт страницы и проксирует `/api` | `8080` |
| `api` | бэкенд (FastAPI): вход, заявки, согласия, конвейер решения, договоры, выдача, демо-управление; Swagger на `/docs` | `8100` |
| `worker`, `beat` | фоновые задачи (Celery): проверки, обращения к внешним системам, повторы, расписание | нет |
| `postgres`, `redis` (Valkey) | база данных и очередь/кэш | нет |
| `db-init` | разовое создание баз и пользователей, завершается сам | нет |
| `mock-registry` | реестр компаний и ИП, ЕФРСБ (банкротства) | `8101` |
| `mock-tax` | налоговая и ЕИС (госконтракты) | `8102` |
| `mock-credit-bureau` | бюро кредитных историй | `8103` |
| `mock-bank-core` | банковская система: счета, обороты, выдача, комплаенс | `8104` |
| `mock-scenarios` | сервис тестовых компаний: создаёт и сбрасывает данные в остальных моках | `8105` |

Сквозная схема: клиент через `web` попадает в `api`; при отправке заявки `api` ставит задачу в очередь, `worker` ходит в моки (реестр, налоговая, БКИ, банк) через адаптеры с повторами и таймаутами, детерминированное ядро считает проверки, баллы, лимит, ставку и платёж; результат сохраняется со снимками источников. Подробнее: [обзор архитектуры](docs/plan/50-architecture/01-overview.md), [границы модулей](docs/plan/50-architecture/04-modules-and-boundaries.md), [правила решения](docs/plan/30-decisioning/01-pipeline-overview.md), [модель заявки и статусы](docs/plan/20-process/02-application-states.md).

## Ограничения и допущения

Это прототип, а не промышленная система. Новостная лента исключена решением **D-019**: [организаторы подтвердили, что она не относится к кейсу](docs/plan/10-product/00-organizer-clarifications.md). Чего нет или что упрощено:

- **Внешние системы — моки.** Реестр, налоговая и ЕИС, БКИ, банковская система и ЕФРСБ — наши имитации, а не настоящие сервисы. Формат упрощён (JSON, ключ в заголовке вместо СМЭВ и сертификатов). Список упрощений — раздел 12 [спецификации моков](docs/specs/mocks.md). Данные отдаются одним срезом на текущий месяц.
- **Не моделируются совсем:** ФССП, арбитражные дела, реестр уведомлений о залоге, машиночитаемые доверенности (МЧД; полномочия бухгалтера — просто флаг).
- **Подписи и SMS ненастоящие.** Согласия и договор подписываются кодом, показанным на экране (простая подпись в демо-режиме). Реальных SMS, ЭЦП и юридической силы нет.
- **PDF и подпись — демо.** Новые договоры и графики сохраняются как PDF с кириллицей; подпись проверяет сохранённые байты. Совместимость старых JSON сохранена. Юридической силы и настоящей ЭП нет.
- **Платежи и выдача условные.** Выдача проходит через мок банка; погашения не моделируются: «Остаток долга» всегда равен выданной сумме.
- **Файлы и выписка.** Работают загрузка PDF/1С, проверка и фоновый разбор, отдельное подтверждение поступлений, сохранение происхождения и снимка для расчёта. Генератор мока для кнопки ещё недоступен; путь Гарипова проверен с готовым файлом из docs/test-data. PARSED не означает подтверждённую выручку, текст не заменяет выписку.
- **Банк.** Решения, запрос сведений, перепроверка, ручные условия и просмотр документов подключены. Вход — демо-кнопка. В этой проверке использован директор; полный путь бухгалтер → руководитель заново не пройден и не обещается.
- **Залог и поручитель.** В форме можно заявить имущество и его стоимость, приложить PDF. Это сведения клиента, не подтверждённая оценка и не регистрация залога. Полный путь поручителя и банковская проверка обеспечения здесь не объявляются проверенными.
- **Каталог и уведомления.** Отдельных страниц каталога/калькулятора и уведомлений нет, их пункты убраны из меню. Подбор доступен в мастере; договор и подпись — внутри страницы заявки. Уведомлений (внутри продукта, почтой, SMS) нет.
- **Живые статусы.** SSE подключён с восстановлением и перепроверкой прав; при сбое остаётся запасной опрос. Проверены авторизованное соединение/повтор и отказ без сессии; длительная нагрузка и отказоустойчивость не измерялись.
- **Защита от сбоев неполная.** Повторы, идемпотентность и защита от двойной выдачи есть; автоматический «предохранитель» (circuit breaker) пока заглушка, а сброс зависших задач (reaper) не закончен.
- **ИИ-подсказки по свободному тексту** (профиль `ai`, сервис `nlu`) не реализованы; в стенде их нет.
- **Нагрузочных и хаос-тестов нет.** Производительность и масштабирование не измерялись. Проверенный размер — один экземпляр каждого сервиса на одном компьютере.
- **Облачного стенда нет.** Файл `docker-compose.cloud.yml` есть, но стенд не поднимался и не проверялся. Образы в публичный реестр не публикуются: `docker compose up` собирает их локально.
- **Пределы комплекта сдачи.** [Схемы реализации](docs/architecture/architecture.md), [реестр компонентов](THIRD_PARTY_NOTICES.md), [Postman](docs/api/README.md) и [каталог сценариев](docs/test-scenarios.md) подготовлены. Автоматическая сверка диаграмм/лицензий в CI, финальная версия сдачи, отдельная лицензия собственного кода, метрики синтетики и репетиция человеком ещё не завершены.
- **Только часть сценариев технических и ветвей.** Девять базовых персон есть, технических `t-*` нет; «Быстрый старт» и «Заря» проверены автотестами по API, а не в браузере.
- **Платформы.** Проверены Linux и macOS с Docker Desktop; Windows пока не проверена. Интерфейс рассчитан на ширину экрана от 1280 пикселей (мобильной версии нет).
- **Демо-панель общая:** сброс и сбои влияют на всех, кто работает на этом же стенде.

### Известные проблемы

- В историческом прогоне 23.10 `bankQueue.test.tsx` падал по таймауту на загруженной машине. Ошибка чрезмерной фильтрации Hypothesis в `test_counter_offers.py` исправлена в свежем main; история первоначальной проверки сохранена в журнале.
- На `/demo` нет кнопки «Создать тестовую компанию» (она есть в плане): компанию создают запросом, см. сценарий 6.
- Платёж мастера предварительный, считается сервером по ставке каталога. Итог после проверки может отличаться; банковские формулы в браузере не дублируются.
